# AppStorage应用全局的UI状态存储

This directory provides comprehensive documentation for AppStorage, a global UI state storage mechanism in Cangjie-based development. It covers the core concepts of application-level data sharing, contrasting it with page-level LocalStorage, and details the usage of decorators like @StorageProp and @StorageLink for data synchronization. The content includes API references, usage constraints, and practical scenarios for managing complex data types and cross-UIAbility state sharing. It is suitable for developers looking to decouple business logic from UI while maintaining efficient, reactive state management in HarmonyOS applications.

## Detailed Description

### AppStorage应用全局的UI状态存储_2more.md AppStorage应用全局的UI状态存储_2more.md
This technical guide introduces AppStorage, a global UI state storage mechanism designed for application-level data sharing in Cangjie-based development. It contrasts AppStorage with page-level LocalStorage and explains its role as a central hub for PersistentStorage and Environment variables. Key topics include the usage of @StorageProp and @StorageLink macros for UI synchronization, API interfaces for manual data manipulation, and support for cross-UIAbility state sharing. The document targets developers familiar with state management frameworks, emphasizing AppStorage's ability to decouple business logic from UI while maintaining two-way data synchronization.

### StorageLink.md StorageLink.md
This document serves as API reference documentation for the @StorageLink decorator, which enables two-way data synchronization between component variables and the central AppStorage. It details macro usage rules, including required string parameters, supported data types (such as Class, Map, Set, and primitives), and initialization requirements. The text explains variable transfer restrictions, noting that parent initialization is forbidden, and outlines observation behaviors for different data structures to trigger UI updates. Key takeaways include the mechanism for bidirectional data flow and the necessity of initial values to populate AppStorage. Intended for developers managing application state, this guide ensures proper implementation of reactive data binding and component re-rendering.

### StorageProp.md StorageProp.md
This API documentation defines the @StorageProp decorator used for one-way data synchronization between AppStorage and custom component variables in ArkTS. The document outlines macro usage rules, including supported data types like classes, arrays, and collections, and mandatory initialization parameters. It details variable passing restrictions, prohibiting parent initialization while supporting child node initialization. Key takeaways include that @StorageProp variables are immutable regarding local persistence, as AppStorage changes always overwrite local modifications and trigger component re-renders. This reference is intended for developers managing application state and UI updates.

### 限制条件.md 限制条件.md
This reference document outlines critical constraints and usage limitations for AppStorage, @StorageProp, and @StorageLink in the Cangjie framework. It covers parameter type requirements, incompatibility with function types, interaction rules with PersistentStorage and Environment, performance considerations for UI updates, and process isolation boundaries. Key takeaways include that decorator parameters must be strings, initialization order impacts data persistence, and AppStorage is not shared between UIAbility and UIExtensionAbility processes. Targeted at developers, it ensures correct state management and avoids runtime errors or unnecessary UI re-renders.
