# 运行配置

This directory contains essential reference documentation for configuring and executing the Cangjie (cjpm) unit testing framework. It focuses on command-line interface options that allow users to fine-tune test execution, manage output visibility, and optimize performance. Key areas covered include output capture strategies to prevent interleaved logs, parallel execution configurations for faster testing, and advanced filtering mechanisms using tags and wildcards. Additionally, it addresses benchmarking setup, custom report generation, and timeout management. This documentation is tailored for developers and QA engineers who need to automate testing processes, ensure test isolation, and generate detailed execution reports within the Cangjie development ecosystem.

## Detailed Description

### --capture-output_7more.md --capture-output_7more.md
This reference document details command-line options for configuring output capture, progress reporting, and testing strategies within the cjpm unit testing framework. It covers flags for managing test output visibility, including --capture-output, --no-capture-output, and --show-all-output, as well as progress display options like --progress-brief and --no-progress. Additionally, it introduces the --coverage-guided feature for randomized parameterized testing. Key takeaways include understanding that output capture is enabled by default for cjpm test to prevent interleaved output and that progress reporting can be customized or disabled. This guide is intended for developers and QA engineers seeking to optimize test execution workflows and reporting clarity.

### --parallel_5more.md --parallel_5more.md
This reference documentation outlines command-line options for configuring test execution, parallelism, and reporting within a testing framework. It details the `--parallel` flag for multi-process execution, custom `--option=value` parsing rules, and reporting settings including `--report-path`, `--report-format`, and `--baseline-path`. Key takeaways include that parallel execution requires independent test classes and conflicts with benchmarks, while custom options automatically convert to camelCase and infer types like Bool, Int, or String. Report formats vary by test type, with benchmarks supporting detailed HTML statistics and plots. This guide targets developers and QA engineers configuring test runs via the command line.

### 使用方法_8more.md 使用方法_8more.md
This reference guide details command-line options for executing Cangjie unit test executables. It explains how to control test execution using flags such as `--bench` for benchmarking, `--filter` for wildcard-based selection, and `--dry-run` for listing tests. Key sections cover tag-based filtering with `--include-tags` and `--exclude-tags`, including logic for combining tags and priority rules. Additionally, it describes `--show-tags` for reporting and `--timeout-each` for setting global timeouts. This guide is intended for developers needing to customize test runs and filter specific test cases or benchmarks.
