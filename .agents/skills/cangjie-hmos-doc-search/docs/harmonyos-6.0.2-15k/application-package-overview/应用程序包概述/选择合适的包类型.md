## 选择合适的包类型

HAP、HAR两者者的功能和使用场景总结对比如下：

| Module类型 | 包类型 | 说明 |
| -------- | -------- | -------- |
| Ability | [HAP](hap-package.md)| 应用的功能模块，可以独立安装和运行。|
| Static Library | [HAR](har-package.md) | 静态共享包，编译态复用。<br/> - 支持应用内共享，也可以作为二方库（SDK）、三方库（SDK）发布后供其他应用使用。<br/> &ensp; - 作为二方库（SDK），发布到[OHPM私仓](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/ide-ohpm-repo)，供公司内部其他应用使用。<br/> &ensp; - 作为三方库（SDK），发布到[OHPM中心仓](https://ohpm.openharmony.cn/)，供其他应用使用。<br/> - 多包（HAP）同时引用相同的HAR时，会造成多包间代码和资源的重复拷贝，从而导致应用包增大。<br/> - 注意：[编译HAR](har-package.md#编译)时，建议开启混淆能力，保护代码资产。 |

HAP、HAR支持的规格对比如下，其中“√”表示是，“×”表示否。

开发者可以根据具体的应用需求，选择相应类型的包进行开发。在后续的章节中还会针对如何使用[HAP](hap-package.md)、[HAR](har-package.md)分别展开详细介绍。

| 规格| HAP | HAR |
| -------- | ---------- |----------- |----------- |
| 支持在配置文件中声明[UIAbility](../../application-models/cj-uiability-overview.md)组件| √ | √ |
| 支持在配置文件中声明[ExtensionAbility](../../application-models/cj-extensionability-overview.md)组件 | √ | × |
| 支持包含资源文件与.so文件 | √ | √ |
| 支持依赖其他HAR文件 | √ | √ |
| 支持在设备上独立安装运行 | √ | × |

> **说明：**
>
> - HAR不支持循环依赖，也不支持依赖传递，详情说明可以参考[HAR](har-package.md#约束限制)中约束限制说明。
