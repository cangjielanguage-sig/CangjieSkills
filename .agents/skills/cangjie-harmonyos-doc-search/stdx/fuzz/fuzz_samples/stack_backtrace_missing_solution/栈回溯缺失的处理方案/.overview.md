# 栈回溯缺失的处理方案

本目录主要针对 cj-fuzz 框架在模糊测试过程中遇到的栈回溯缺失问题提供解决方案。内容涵盖了从链接配置、AddressSanitizer 集成到具体崩溃案例分析的全过程。核心关键词包括：栈回溯、模糊测试、AddressSanitizer、原生信号处理、Cangjie 运行时。该文档适合使用 cj-fuzz 进行安全测试的开发者、安全工程师以及负责 Cangjie 运行时维护的 QA 工程师阅读，旨在帮助诊断原生层面的故障并提升调试效率。

## 详细描述

### 栈回溯缺失的处理方案_1.md 栈回溯缺失的处理方案_1.md
本文档旨在解决 cj-fuzz 框架在模糊测试过程中因超时或 C 代码崩溃导致的栈回溯缺失问题。文档分析了相关警告产生的原因，区分了异常捕获与原生信号处理的差异，并提供了具体的链接配置方案。核心解决方案是在链接时引入 LLVM AddressSanitizer 静态库及 `-lgcc_s`、`--eh-frame-hdr` 选项，以实现 `__sanitizer_print_stack_trace` 功能，从而获取原生信号的栈回溯。该技术指南面向使用 cj-fuzz 进行模糊测试的开发者或安全工程师，帮助其诊断原生层面的故障。

### 栈回溯缺失的处理方案_2.md 栈回溯缺失的处理方案_2.md
本文档提供了一份技术日志，分析了 Cangjie 模糊测试环境中的崩溃场景，可能作为解决栈回溯缺失问题的证据或案例研究。它详细描述了从 Cangjie 应用层通过原生运行时封装层到 libFuzzer 引擎的执行流程，重点突出了具体的异常类型和输入数据。主要收获包括识别标准库数组操作中的“TRAP!”异常以及跨语言边界的调用栈可见性。该资源主要面向专注于调试、异常处理和模糊测试基础设施的 Cangjie 运行时开发者和 QA 工程师。
