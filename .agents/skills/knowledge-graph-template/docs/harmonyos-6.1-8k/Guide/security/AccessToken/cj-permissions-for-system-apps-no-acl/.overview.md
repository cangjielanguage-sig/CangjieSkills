# cj-permissions-for-system-apps-no-acl

This directory contains critical documentation regarding a specific subset of permissions within the OpenHarmony operating system that are restricted from standard ACL (Access Control List) applications but remain available for use by system applications. It serves as a technical reference for understanding the complex landscape of system-level privileges, specifically focusing on sensitive capabilities such as distributed hardware management, lock screen UI extensions, boot broadcasts, and network management. The content outlines the necessary prerequisites, including the requirement for applications to possess an APL (Ability Privilege Level) of `system_basic` or `system_core`. It is primarily tailored for system developers and application engineers who need to navigate these strict security constraints, verify their application's eligibility for high-privilege access, and ensure compliance with the `system_grant` authorization protocol.

## Detailed Description

### 不可ACL申请的系统应用可用权限系统授权/

This subdirectory hosts detailed documentation concerning OpenHarmony system permissions that are characterized by their high sensitivity and restricted availability. Unlike standard permissions that might be requested through ACLs, the permissions described here are exclusively reserved for system applications and require a specific authorization path.

The documentation provides an in-depth look at the definitions, functionalities, and protection levels associated with these permissions. It highlights critical domains such as distributed hardware, which involves cross-device resource management; lock screen UI extensions, which control secure screen interactions; boot broadcasts, which are vital for system startup sequences; and network management, which handles sensitive data transmission.

A key focus of the content is the authorization mechanism. It clarifies that these permissions utilize the `system_grant` mode, meaning they are automatically granted by the system if the application meets the stringent criteria, rather than requiring user consent. To qualify, applications must be signed and configured with an APL level of `system_basic` or `system_core`. This guide is indispensable for developers aiming to build system-level applications, providing the necessary knowledge to understand permission limitations, confirm application eligibility, and enhance overall development efficiency within the OpenHarmony ecosystem. By clearly delineating which permissions fall outside the scope of ACL application, the documentation helps prevent security vulnerabilities and ensures that only authorized system components can access critical device functions.
