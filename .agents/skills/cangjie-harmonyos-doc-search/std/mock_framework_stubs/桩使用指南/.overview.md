# 桩使用指南

This directory serves as a comprehensive guide for using stubs and mock objects within the Cangjie unit testing framework. It covers essential topics such as sharing mocks safely, capturing arguments for verification, configuring default behaviors via Stub Modes, and creating custom parameter matchers. The documentation addresses advanced techniques like using `ValueListener`, `SyntheticFields`, and the `@On` macro to optimize test code. It is designed for developers seeking to write maintainable, isolated unit tests while minimizing boilerplate and avoiding common pitfalls like test leakage.

## Detailed Description

### 共享_mock_对象和桩.md
This guide explains best practices for sharing mock objects and stubs across multiple test cases within a unit testing framework. It covers the risks of test leakage, appropriate locations for declaring stubs (test body vs. BeforeAll), and restrictions on shared stubs. Key takeaways include that mocks can be shared as instance variables, while shared stubs in BeforeAll must be stateless operations like returns or throws, excluding expectations or cardinality specifiers. The document explicitly warns against declaring stubs in the test class constructor. This technical reference targets developers writing unit tests who need to optimize mock setup without causing test instability. Keywords: Mock objects, Stubs, Unit testing, Test isolation, BeforeAll, Stateless operations, Test leakage.

### 捕获参数.md
This technical guide explains how to use the mock framework's `captor` and `ValueListener` to intercept and verify arguments passed to stubbed methods. It covers immediate validation via `ValueListener.onEach`, post-execution inspection using `allValues()` and `lastValue()`, and conditional capturing with the `argThat` matcher. Key takeaways include practical code examples for binding listeners to arguments and the constraint that these matchers cannot be used within the `@Called` macro. Intended for developers using the Cangjie language, this document serves as a reference for implementing detailed argument verification in unit tests.

### 桩使用指南_4more.md
This guide explains how to effectively use mock/spy objects and stubs within a specific mock framework to write maintainable test cases. It covers the working principles of stubs, redefining stub behavior, and defining multiple stubs for a single declaration. Key information includes the use of the `@On` macro for declaration, bottom-to-top priority for argument matching, and the requirement that all defined stubs must be called unless the `anyTimes()` modifier is applied. The document details fallback behaviors for mocks versus spies and provides examples of handling different arguments. This technical guide is intended for developers writing unit tests who need to manage test expectations and mock configurations.

### 桩的模式.md
This technical guide explains how to configure default behaviors for mock objects using Stub Modes to reduce boilerplate code in testing. It details two specific modes: ReturnsDefaults, which provides standard empty or zero values for common types like numbers and strings, and SyntheticFields, which simplifies property handling by allowing direct assignment and retrieval. Key information includes that modes are enabled via the mock function's modes parameter, explicit stubs always override defaults, and assigned values take precedence over default returns. The document also notes limitations regarding static members and the lack of enforced expectations. This reference is intended for developers using the Cangjie mock framework to write unit tests.

### 自定义和使用参数匹配器_2more.md
This guide introduces how to customize parameter matchers and set property and field stubs in the Cangjie Mock framework. It primarily covers creating reusable matchers by extending the Matchers class and using SyntheticField to configure property and field behaviors. Key information includes that users can extend Matchers to define TypedMatcher types for logic reuse. For properties, the document demonstrates using SyntheticField.create to create synthetic fields and simulating field behavior via getsField and setsField operations, with the framework automatically managing state reset between tests. This technical tutorial is intended for Cangjie language developers who need to write advanced unit tests. Keywords: Mock framework, parameter matchers, synthetic fields, unit testing.
