# 隐式Want匹配原理

This directory provides a comprehensive technical overview of the implicit Want matching mechanism used in system application component routing. It covers the core logic for resolving intents based on parameters such as action, entities, URI, type, and linkFeature. The documents detail specific matching rules, priority handling, and configuration requirements within `module.json5`. Key topics include URI expression types, wildcard handling, and the interaction between caller parameters and target skills. This resource is suitable for system developers and application engineers looking to implement or debug cross-component invocation and intent filtering.

## Detailed Description

### uri匹配规则_3more.md uri匹配规则_3more.md
This technical reference document outlines the matching logic for URI, type, and linkFeature parameters within the system's "want" mechanism. It details specific rules for comparing source and want parameters across three main sections: URI matching (covering scheme, host, port, and path variations like regex), type matching (handling wildcards), and linkFeature matching. Key takeaways include the definition of four URI expression types and the restriction that third-party apps must not use the "ohos" scheme reserved for system applications. The document serves as a guide for developers configuring application component skills to ensure correct routing and invocation.

### want参数的action匹配规则_2more.md want参数的action匹配规则_2more.md
This technical reference document defines the matching logic for `want` parameters against application component `skills` configurations. It covers two primary topics: `action` matching rules and `entities` matching rules. The document outlines specific scenarios determining match success or failure based on whether the input parameters are empty or contained within the target component's skills. Key takeaways include that an empty `action` matches non-empty skills, while an empty `entities` always matches regardless of the skills configuration. Conversely, non-empty inputs require the target skills to explicitly contain them to succeed. Intended for developers configuring component capabilities, this guide ensures correct routing and invocation of application abilities.

### want参数的uri和type匹配规则.md want参数的uri和type匹配规则.md
This technical reference document defines the matching logic between a caller's want parameters (uri and type) and the skills configuration of installed application components. It details four specific matching scenarios based on whether the input uri and type are empty or populated, explains the "leftmost uri matching" rule for partial configurations, and provides variable definitions for clarity. A match succeeds if any element in the component's uris array aligns with the input parameters, including fallback logic for file path MIME types when type is missing. This guide targets system developers or application engineers needing to understand component resolution and intent filtering mechanisms.

### 隐式Want匹配原理.md 隐式Want匹配原理.md
This technical reference document explains the principles and logic behind implicit Want matching for application components. It details matching parameters via a table, defines the relationship between caller want parameters and target skills configuration in module.json5, and outlines specific matching rules including priority handling for the linkFeature parameter. Key information includes that matching compares attributes like action, entities, uri, and type. The linkFeature parameter triggers a priority match path, while standard matching requires all four attributes to align for the component to appear in the application selector. This guide targets application developers configuring module.json5 files and implementing cross-component invocation logic.
