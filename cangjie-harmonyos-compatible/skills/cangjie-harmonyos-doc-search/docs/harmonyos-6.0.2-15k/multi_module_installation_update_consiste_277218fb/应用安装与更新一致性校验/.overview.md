# 应用安装与更新一致性校验

This directory focuses on the technical specifications and verification rules required to maintain consistency during the installation and update processes of applications. It primarily addresses the HarmonyOS and OpenHarmony ecosystems, detailing how to handle signature certificates, configuration files, and version control. The content covers critical fields such as `appId`, `bundleName`, `versionCode`, and `apl` levels, explaining how they are validated across different scenarios like multi-module installations. These documents are essential resources for software developers, system architects, and engineers who need to ensure application security, legality, and stability while managing package integrity and compatibility.

## Detailed Description

### 应用安装与更新一致性校验_2more.md 应用安装与更新一致性校验_2more.md
This document outlines the consistency verification rules for signature certificates and configuration files during the installation and update of multi-module applications to ensure security and legality. It covers the definition of version consistency via app.json5 and details specific verification rules for fields such as appId, appIdentifier, appDistributionType, appProvisionType, and apl. Key takeaways include that versionCode determines version identity, and update checks vary by version: appId and appIdentifier allow flexibility, while other fields like apl and certificate types are strictly checked only for same-version updates. Intended for developers and system architects working on modular HarmonyOS applications, this reference guide requires knowledge of app packaging and security concepts like APL levels.

### 配置文件一致性校验.md 配置文件一致性校验.md
This reference document outlines consistency verification rules for application configuration fields during installation and updates. It details specific attributes like bundleName, versionCode, and apiReleaseType, indicating whether each field must be verified during installation, updates, or both. Key information includes strict requirements for unique identifiers and version numbers, alongside distinct rules for debug flags and module types. The document references app.json5 and module.json5 sources to guide developers in maintaining package integrity. It is intended for software developers and system engineers working within the HarmonyOS or OpenHarmony development environment to ensure application compatibility and stability.
