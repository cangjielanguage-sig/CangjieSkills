# 鸿蒙应用经验沉淀 Skill

## 目的

维护一份持续积累的经验文档 Evolution.md，记录每次构建中遇到的难点与已验证解决方案，使后续相同或相似问题能快速定位和修复。

## 文件位置

Evolution.md 位于目标应用项目的根目录下（与 build.ps1 同级）。如果不存在则在首次写入时创建。

## 核心原则

- **只记录已验证方案。** 只有 BUILD SUCCESSFUL 之后才允许写入，构建失败的尝试不得记录。
- **每条记录必须完整。** 缺少任何必填字段的记录不允许写入。
- **查阅优先于新增。** 遇到构建失败时，先在 Evolution.md 中搜索匹配，命中则直接复用，避免重复踩坑。

## 记录格式（严格遵守）

每条经验按以下格式追加到 Evolution.md 末尾：

```markdown
## [简短问题标题]

- **日期**：YYYY-MM-DD
- **错误类型**：[编译错误 / 链接错误 / 运行时错误 / 打包错误 / 签名错误 / 配置错误]
- **错误信息**：
  ```
  [从 build-full.log 中摘录的关键报错，保留原始格式]
  ```
- **原因分析**：[为什么会出现这个错误，根因是什么]
- **解决方案**：[具体做了什么修改来修复]
- **正确代码示例**：
  ```cangjie
  // 修复后的关键代码片段
  ```
- **关键词**：[用于后续检索匹配的关键词，逗号分隔]
```

## 使用场景

### 场景一：构建失败时查阅（读取）

这是 harmonyos-build Skill 失败处理的第一优先级步骤。

**步骤：**

1. 读取项目根目录下的 Evolution.md（如果不存在则跳过，进入下一步排查）。
2. 从 build-full.log 中提取关键报错信息（错误类型、API 名称、报错关键词）。
3. 在 Evolution.md 中搜索匹配：
   - 优先匹配**错误信息**字段中的相同报错
   - 其次匹配**关键词**字段
   - 最后匹配**错误类型**字段
4. 命中已有记录后，直接应用其解决方案并重新构建。
5. 未命中则退出本 Skill，由 harmonyos-build Skill 继续后续排查步骤。

### 场景二：构建成功后沉淀（写入）

当本次构建过程中经历了失败→排查→修复→成功的完整周期时，将经验写入。

**步骤：**

1. 确认当前构建结果为 BUILD SUCCESSFUL。
2. 回顾本次遇到的问题：错误信息、排查过程、最终修复方案。
3. 按上述记录格式组织内容。
4. 追加到 Evolution.md 末尾（不修改已有记录）。
5. 向用户简要确认已沉淀的经验条目标题。

### 场景三：首次构建即成功

如果构建一次通过没有遇到问题，则无需写入 Evolution.md。

## 注意事项

- 不要记录过于琐碎的问题（如单纯的拼写错误）。重点记录有普遍参考价值的难点。
- 代码示例应精简到关键修改部分，不要贴大段无关代码。
- 关键词字段要覆盖可能的检索词，包括类名、函数名、错误码、框架概念等。
- 如果某条旧记录的方案已过时或有更好方案，在其下方追加更新说明，不要删除原记录。
