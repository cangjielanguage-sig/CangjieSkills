# 开发步骤

This directory serves as a comprehensive technical resource for developers focusing on application stability and performance monitoring within the Cangjie ecosystem. It provides a detailed, step-by-step tutorial on implementing crash event subscriptions using the PerformanceAnalysisKit, covering essential tasks such as importing dependencies, configuring AppEventFilter and Watcher components, and manually triggering crashes for testing. Furthermore, it offers a deep dive into the log output format generated by the HiAppEvent framework, illustrating exactly how crash data is structured for effective analysis. The content addresses specific technical behaviors, such as stack unwinding differences between CjError and NativeCrash, and the precise timing of crash reports. It is specifically designed for Cangjie developers and system engineers utilizing DevEco Studio who need to debug application failures, interpret complex crash logs, and optimize error handling mechanisms in HarmonyOS or OpenHarmony environments.

## Detailed Description

### 开发步骤_1.md
This tutorial guides developers through implementing crash event subscription in a Cangjie application using the PerformanceAnalysisKit. It covers importing dependencies, configuring an AppEventFilter and Watcher in the onCreate function, and manually triggering a crash in onClick. Key information includes the implementation of the onReceive callback for logging event data and an explanation of stack unwinding behaviors for CjError versus NativeCrash, noting that NativeCrash is slower. It also clarifies reporting timing: uncaught crashes report on the next launch, while caught exceptions report before exit. Targeted at Cangjie developers using DevEco Studio for performance analysis and debugging.

### 开发步骤_2.md
This document presents a raw log output example of an application crash event captured by the HiAppEvent framework. It covers the detailed parameters associated with an APP_CRASH event, including application metadata like bundle name and version, system identifiers such as PID and UID, and specific crash details like the CjError type and exception stack trace. The log illustrates how crash data is structured, showing the inclusion of external log file paths and foreground status, which serves as a reference for analyzing system failures. This content is intended for software developers or system engineers debugging application stability issues, likely within a HarmonyOS or OpenHarmony development environment.
