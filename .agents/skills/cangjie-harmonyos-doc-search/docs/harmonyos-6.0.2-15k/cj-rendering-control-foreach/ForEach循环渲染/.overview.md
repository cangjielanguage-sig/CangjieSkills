This directory focuses on the ForEach loop rendering mechanism within the ArkUI framework using the Cangjie language. It covers the core principles of rendering array data, key generation rules, component lifecycle (initial vs. non-initial rendering), and handling dynamic data source changes. Key topics include unique identifiers, performance optimization, and avoiding common pitfalls. It is suitable for HarmonyOS developers and UI engineers looking to implement dynamic lists efficiently and understand state management in ArkUI.

### 使用建议.md 使用建议.md
This document provides usage recommendations and best practices for optimizing the ForEach component in UI development to ensure rendering performance and stability. It covers key generation strategies, handling basic versus object data types, the role of index parameters, and compatibility with container components like List and Grid. Key takeaways include using unique IDs for object keys instead of indices to prevent performance degradation, converting basic types to objects with IDs for dynamic sources, and avoiding mixing ForEach with LazyForEach in specific containers. Targeted at UI developers, this guide helps prevent unexpected rendering results and performance bottlenecks when iterating over data arrays.

### 非首次渲染_3more.md 非首次渲染_3more.md

It details the key-based component reuse logic, provides a code example demonstrating data modification and re-rendering, and outlines usage scenarios such as static data sources like skeleton screens. Key takeaways include that ForEach checks generated keys; existing keys trigger component reuse, while new keys create new components. It demonstrates how @State monitors array changes to trigger this process. This guide targets HarmonyOS developers using the Cangjie language who need to optimize list rendering performance and understand state management.

### 首次渲染.md 首次渲染.md
This technical guide explains the initial rendering mechanism of the ForEach component in ArkUI, specifically focusing on key generation rules. It covers how unique keys are generated for data source items and illustrates the rendering process through Cangjie code examples. Key information includes that ForEach creates components based on the keyGeneratorFunc return value, and if duplicate keys are generated, the framework's behavior is undefined, leading to missing components for duplicate items. This document is intended for developers using the Cangjie language and ArkUI framework who need to understand list rendering logic and avoid common pitfalls with duplicate data.

### 不推荐案例/
This directory serves as an essential educational resource for ArkUI/Cangjie developers, focusing on anti-patterns and common pitfalls in list rendering. It specifically addresses the incorrect usage of the `ForEach` component, providing detailed analyses of why certain implementations are discouraged. The core content covers the critical importance of key generation, explaining how using data source indices as keys can lead to unexpected rendering results, such as duplicate UI elements, and how omitting custom key generators can cause significant performance degradation due to unnecessary component recreation. By understanding these "not recommended" cases, developers can master the framework's key matching mechanism and lifecycle management. This directory is highly suitable for developers seeking to debug rendering issues, optimize application performance, and ensure robust state management in their Cangjie projects.
