# 应用程序包常见问题

This directory provides comprehensive technical documentation addressing common queries and issues related to HarmonyOS application packages. It primarily focuses on application identification mechanisms, detailing how to retrieve critical identifiers such as `appIdentifier` and `appId`. The content covers various methods for obtaining certificate fingerprints, including programmatic access via APIs and command-line tools. Additionally, it explains the structural definitions within Profile signature files and the implications of auto-signing versus manual signing on identifier stability. This resource is specifically designed for HarmonyOS and OpenHarmony developers who are managing application security, deployment configurations, and ensuring consistent identification across devices.

## Detailed Description

### 如何获取应用信息中appIdentifier_3more.md 如何获取应用信息中appIdentifier_3more.md
This technical guide explains how to retrieve application identifiers, specifically `appIdentifier` and `appId`, within a HarmonyOS development context. It details two primary retrieval methods: programmatic access using the `BundleManager.getBundleInfoForSelf` API in Cangjie and command-line usage via the `bm` tool. The document defines `appId` as a combination of the package name and certificate public key, noting that `appIdentifier` is preferred for stable unique identification as it remains constant despite certificate changes. Targeted at developers, this guide provides code snippets and shell commands for practical implementation.

### 应用程序包常见问题_3more.md 应用程序包常见问题_3more.md
This document serves as a technical guide for developers addressing common queries regarding application package signatures and identifiers. The main topics cover methods to retrieve fingerprint information and the definition of the `appIdentifier`. Key takeaways include four ways to obtain fingerprints: via the `bundleManager` API, the `bm` shell tool, certificate files, or `keytool`. Furthermore, the document explains that the `appIdentifier` is a unique field in the Profile signature file; it clarifies that while auto-signing generates random values, manual signing is recommended for scenarios requiring a consistent identifier, such as cross-device debugging. This reference targets HarmonyOS or OpenHarmony developers managing application security and deployment configurations.
