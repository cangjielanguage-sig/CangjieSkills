# 场景详细说明

This directory contains technical documentation for enabling interoperability between Cangjie and ArkTS using declarative macros. It covers specific usage scenarios for functions, classes, enums, and interfaces, detailing constraints and syntax for cross-language data and function exchange. Key concepts include the `@Interop[ArkTS]` annotation, visibility control, and automatic interface generation. This resource is designed for HarmonyOS developers who need to integrate Cangjie backend modules with ArkTS frontends, ensuring seamless application functionality across languages.

## Detailed Description

### 场景详细说明_4more.md
This technical reference guide explains how to use declarative interoperability macros to enable data and function exchange between Cangjie and ArkTS. It categorizes usage scenarios for functions, async functions, interfaces, classes, and enums, detailing specific constraints such as mandatory public modifiers and restrictions on type parameters. The document provides code examples demonstrating the syntax for Cangjie definitions, the resulting auto-generated ArkTS interfaces, and implementation usage. Key concepts include the @Interop[ArkTS] annotation and handling asynchronous operations. This guide is intended for developers building cross-language applications within the HarmonyOS ecosystem who need to integrate Cangjie modules with ArkTS frontends.

### 枚举.md
This technical guide explains how to implement Cangjie enums for interoperability with ArkTS using declarative macros. It covers declaration constraints, code implementation, and the automatic generation of TypeScript interfaces. Key takeaways include the requirements that enums must be public and cannot have parameterized constructors. The document illustrates how the @Interop[ArkTS] macro converts Cangjie enums into ArkTS const enum types, enabling seamless function calls and data exchange. Targeted at HarmonyOS developers, this guide assumes knowledge of both Cangjie and ArkTS syntax and focuses on cross-language integration patterns.

### 类.md
This document outlines the constraints and implementation guidelines for using Cangjie classes within ArkTS through declarative interoperability macros. It details strict declaration rules, such as mandatory public modifiers, constructor limitations, and restrictions on type parameters and operator overloading. The text explains visibility control using `@Interop[ArkTS, Invisible]` to hide internal members. A comprehensive example illustrates the mapping from Cangjie code to the generated ArkTS interface, demonstrating how constructors, properties, and methods are exposed and consumed. This technical reference is intended for developers integrating Cangjie modules with ArkTS applications.
