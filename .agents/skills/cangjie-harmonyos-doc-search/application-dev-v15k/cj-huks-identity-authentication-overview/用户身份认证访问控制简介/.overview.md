# 用户身份认证访问控制简介

This directory provides comprehensive documentation on User Identity Authentication and Access Control within the HUKS system. It covers essential concepts such as key binding to device credentials, biometric integration, and specific authorization types like INVALID_CLEAR_PASSWORD and ALWAYS_VALID. The content details security mechanisms including challenge values, AuthToken control, and multi-factor authentication combinations. Designed for developers and security engineers, these guides facilitate the implementation of high-security features like passwordless login and secure payments in HarmonyOS applications, ensuring strict key usage restrictions and secure storage.

## Detailed Description

### 使用场景及开发流程.md 使用场景及开发流程.md
This technical guide outlines usage scenarios and development processes for user identity authentication and access control within the HUKS system. Main sections cover user identity authentication requirements, three specific authorization access types defining invalidation conditions, challenge value verification, and secondary authentication methods including AuthToken control and timestamp-based access. Key information details how keys bind to device credentials like passwords and biometrics, with specific triggers for permanent invalidation, alongside security mechanisms like challenge values for anti-replay protection and batch authorization for efficiency. Targeted at developers implementing high-security features like passwordless login and payment, this document assumes familiarity with key management and TEE environments.

### 用户身份认证和授权访问类型详细规格.md 用户身份认证和授权访问类型详细规格.md
This technical reference document specifies the detailed behaviors of user identity authentication and authorization access types, likely for a hardware-backed keystore system. It defines abbreviations for authentication methods (PIN, FACE, FINGERPRINT) and access control types (INVALID_CLEAR_PASSWORD, INVALID_NEW_BIO_ENROLL, ALWAYS_VALID), followed by a comprehensive mapping table. The table details how keys become invalid based on specific events, such as clearing screen passwords or enrolling new biometric features, across various single and multi-factor authentication combinations. This guide targets developers and security engineers configuring key access policies.

### 用户身份认证访问控制简介.md 用户身份认证访问控制简介.md
This document introduces the key access control capabilities provided by HUKS to ensure secure key storage and usage. It covers service-specific key isolation, user identity authentication for high-security keys, and strict usage restrictions based on key algorithms. Key information includes that services can only access their own generated or imported keys, while sensitive keys require immediate user verification via lock screen password or biometrics. Additionally, key usage is restricted to specific operations like encryption or signing. The document notes that lightweight devices do not support user authentication access control. This conceptual guide targets developers implementing security features in HarmonyOS applications who need to manage key access and permissions.
