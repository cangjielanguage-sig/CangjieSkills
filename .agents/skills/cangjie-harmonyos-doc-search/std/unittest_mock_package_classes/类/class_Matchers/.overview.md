# class_Matchers

This directory provides comprehensive API reference documentation for the `Matchers` class within the Cangjie mock framework. It serves as a technical guide for developers working on unit testing, specifically focusing on the static functions required to generate argument matchers. These matchers are fundamental tools for defining stub behaviors, filtering arguments, and capturing values for verification. The content covers the integration of matchers within `@On` macro expressions, the distinction between structural and reference equality, and type-based filtering. It is designed for developers and quality assurance engineers who need to configure specific test scenarios, manage mock and spy objects, and enforce precise argument constraints using Cangjie generics and type systems.

## Detailed Description

### class_Matchers_6more.md

This API reference document details the Matchers class, which provides static functions to generate argument matchers for defining stub behaviors in unit tests. It covers the class overview with usage examples for mock and spy objects, followed by detailed specifications for static methods including any, argThat, argThatNot, and capture. Key information explains how matchers are used within @On macro expressions to filter arguments, specify different behaviors based on input, or capture values for verification using ValueListener. This guide targets developers using the Cangjie mock framework who need to configure specific test scenarios and argument constraints.

### static_func_defaultTT_5more.md

This document provides API reference documentation for static matcher functions used in a Cangjie unit testing and mocking framework. It covers methods for creating argument matchers, specifically default, eq, ofType, same, and an extension for none. Key information includes the functional differences between these matchers: default uses structural or reference equality but may throw exceptions, eq enforces structural equality via the Equatable interface, same checks for reference equality on objects, ofType filters by type, and none handles None values. The content is intended for developers writing test cases who need to validate method arguments precisely, requiring an understanding of Cangjie generics and type constraints.
