# 权限列表

This directory functions as a specialized reference library for system permissions within the OpenHarmony and HarmonyOS ecosystems, specifically targeting API version 12. It provides detailed lists of permissions necessary for accessing a diverse range of device capabilities, including hardware interfaces (Bluetooth, NFC, sensors), system utilities (background running, biometric auth), and advanced features (cloud sync, input control). The documentation clarifies that these are generally normal level permissions using system_grant authorization. This resource is primarily designed for application developers who need to accurately declare permissions in their configuration files to unlock specific functionalities and adhere to system security policies.

## Detailed Description

### ohospermissionUSE_BLUETOO_25more.md ohospermissionUSE_BLUETOO_25more.md
This document serves as a reference list for OpenHarmony system permissions available starting from API version 12. It details specific permissions categorized by functionality, including Bluetooth access, sensor data reading, network usage, NFC operations, and system settings modification. Key takeaways include that all listed permissions are classified as normal level, use system_grant authorization, and allow capabilities like background running, biometric authentication, and privacy window management. The target audience is application developers who need to declare these permissions in their configuration files to access specific device hardware or system features.

### ohospermissionhsdrHSDR_AC_14more.md ohospermissionhsdrHSDR_AC_14more.md
This document serves as a reference list for specific HarmonyOS permissions introduced or defined in API version 12. It details 14 distinct permissions covering areas such as security detection, cloud synchronization, persistent data storage, external device drivers, account states, navigation, window management, and input control. All listed permissions are classified as normal level with system_grant authorization. Key takeaways include specific usage constraints for certain permissions; for example, RUN_DYN_CODE is system-only, INPUT_KEYBOARD_CONTROLLER is restricted to input methods, and NDK_START_SELF_UI_ABILITY is limited to 2-in-1 devices. This reference guide targets HarmonyOS application developers who need to declare these permissions to access specific system capabilities.
