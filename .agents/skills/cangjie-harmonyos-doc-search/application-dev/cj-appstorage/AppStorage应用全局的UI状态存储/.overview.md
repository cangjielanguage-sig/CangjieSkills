# AppStorage应用全局的UI状态存储

This directory serves as a comprehensive resource for understanding and implementing AppStorage, a global, process-bound UI state storage mechanism in the Cangjie and ArkUI frameworks. It covers core concepts like singleton lifecycle, unique key access, and data synchronization between components and global storage. Key topics include the @StorageProp and @StorageLink decorators, two-way data binding, and integration with PersistentStorage. Designed for developers using state management in pure Cangjie or ArkTS scenarios, these documents provide the necessary guidelines to manage cross-ability data sharing, optimize performance, and ensure correct data flow in applications.

## Detailed Description

### AppStorage应用全局的UI状态存储_2more.md AppStorage应用全局的UI状态存储_2more.md
This document serves as a technical guide explaining AppStorage, a global, process-bound UI state storage mechanism for applications. It details how AppStorage functions as a central hub for application-level data sharing, distinguishing it from page-level LocalStorage and explaining its integration with PersistentStorage and Environment variables. The text focuses on the core concepts of the singleton lifecycle, unique key access, and the specific macros @StorageProp and @StorageLink used for UI synchronization. It highlights that AppStorage supports two-way data binding and offers APIs for external state manipulation. Intended for developers using the state management framework in pure Cangjie scenarios, this guide requires prior knowledge of state management principles to effectively implement cross-ability data sharing.

### StorageLink.md StorageLink.md
This API documentation defines the @StorageLink decorator, which establishes two-way data synchronization between a component's state and the global AppStorage. The document details macro usage rules, specifying supported types like classes, arrays, and collections, alongside initialization requirements. It explains variable passing restrictions and observation behaviors, noting how changes trigger UI updates and data propagation across the application. Key takeaways include the requirement for a string key and initial value, and the mechanism for syncing data bidirectionally. Intended for HarmonyOS developers using ArkTS, this guide helps manage global state and reactivity efficiently.

### StorageProp.md StorageProp.md
This API documentation defines the @StorageProp macro, which establishes one-way data synchronization between AppStorage and custom component variables. Key sections cover macro usage rules, variable transfer restrictions, and change observation behaviors for various data types including classes, arrays, and collections. The document explains that @StorageProp variables must be initialized locally and are read-only regarding AppStorage updates, meaning AppStorage changes overwrite local modifications. It targets developers managing application state in UI frameworks, detailing how specific data type changes trigger component re-rendering.

### 限制条件.md 限制条件.md
This reference document outlines critical constraints and usage rules for state management decorators and storage mechanisms in the Cangjie framework. It covers parameter requirements for StorageProp and StorageLink, type restrictions, and interaction protocols between AppStorage, PersistentStorage, and Environment. Key takeaways include that decorator parameters must be strings, Func types are unsupported, and initialization order affects data persistence. It also recommends using emitter for non-UI message passing to avoid unnecessary rendering. This guide targets developers implementing state management in ArkUI applications who need to avoid runtime errors and ensure correct data flow.
