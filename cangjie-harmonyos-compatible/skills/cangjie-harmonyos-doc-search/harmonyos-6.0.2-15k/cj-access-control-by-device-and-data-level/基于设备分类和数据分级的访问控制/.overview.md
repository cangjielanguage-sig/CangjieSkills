# 基于设备分类和数据分级的访问控制

This directory focuses on implementing access control mechanisms based on device classification and data grading within the ArkData framework using the Cangjie language. It comprehensively covers the fundamental concepts of security levels—ranging from S1 to S4 for data and SL1 to SL5 for devices—and provides practical tutorials for applying these classifications to both relational and key-value databases. Key topics include security level configuration, cross-device synchronization rules, and data protection policies. This resource is suitable for Cangjie developers and system architects aiming to secure distributed applications by ensuring data only syncs to compliant devices.

## Detailed Description

### 使用关系型数据库实现数据分级.md 使用关系型数据库实现数据分级.md
This tutorial demonstrates how to implement data classification by setting a specific security level when creating a relational database in the Cangjie language. The document covers two main steps: obtaining the application context and configuring the database store with the security level parameter. Key information includes code examples using StoreConfig and RelationalStoreSecurityLevel.S1 to create a secure database instance via the getRdbStore function. It targets Cangjie developers using the ArkData framework who need to manage data security levels in their applications.

### 使用键值型数据库实现数据分级.md 使用键值型数据库实现数据分级.md
This tutorial guides developers on implementing data classification in key-value databases by configuring the securityLevel parameter using the ArkData framework in Cangjie. The document covers retrieving the UIAbility context and creating a KV store with a specific security level, such as S1. Key information includes constraints on security level upgrades: they are irreversible, require closing the database, and are not supported for databases requiring cross-device synchronization. The content provides practical code examples for initializing a KVManager and configuring KVOptions. This guide is intended for developers seeking to secure application data through hierarchical database management.

### 基本概念_3more.md 基本概念_3more.md
This technical reference document outlines the security mechanisms for distributed data management, focusing on classification, grading, and access control. It covers data security labels (S1-S4), device security levels (SL1-SL5), and the cross-device synchronization access control matrix. Key information includes the rule that data can only sync to a device if its security label is not higher than the device's security level. For instance, S4 data requires at least an SL4 device. The document emphasizes setting database labels consistent with content sensitivity. This guide targets developers or system architects implementing secure distributed databases who need to understand data protection policies and hardware security capabilities.
