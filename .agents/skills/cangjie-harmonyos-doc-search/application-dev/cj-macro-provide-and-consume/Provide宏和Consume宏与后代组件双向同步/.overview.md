This directory focuses on the @Provide and @Consume macros within the Cangjie and ArkUI frameworks, designed to facilitate two-way data synchronization between ancestor and descendant components. It covers the core mechanisms of cross-level state management, eliminating the need for manual parameter passing through intermediate layers. The content includes technical specifications, variable access rules, usage constraints, and practical scenarios for handling complex data structures. It is suitable for developers, software engineers, and technical architects working with HarmonyOS or Cangjie who need to implement efficient, reactive state management in complex component hierarchies.

## Detailed Description

### Provide宏和Consume宏与后代组件双向同步_3more.md Provide宏和Consume宏与后代组件双向同步_3more.md
This technical reference guide explains the @Provide and @Consume macros for implementing two-way data synchronization between ancestor and descendant components in the Cangjie framework. The document covers an overview of cross-level state management, binding mechanisms via variable names or aliases, and detailed macro specifications including parameters, synchronization types, and allowed variable types. Key takeaways include that @Provide decorates variables in ancestors while @Consume binds to them in descendants, eliminating the need for manual parameter passing across intermediate layers. Binding requires matching types and names or aliases, with @Consume resolving to the nearest ancestor. Intended for developers familiar with declarative UI syntax and custom components, this guide facilitates efficient state management in complex component hierarchies.

### 变量的传递访问规则说明.md 变量的传递访问规则说明.md
This reference document outlines the data passing and access rules for the @Provide and @Consume decorators used in state management. It details initialization sources, child component initialization capabilities, synchronization behaviors, and access visibility for both decorators. Key takeaways include that @Provide allows initialization from various parent state variables and establishes a two-way sync with @Consume in descendant components. Conversely, @Consume cannot be initialized by a parent directly but retrieves data from a matching @Provide ancestor. Both decorators are private to their components. This guide targets developers managing cross-component state synchronization in this UI framework.

### 限制条件.md 限制条件.md
This reference document outlines the specific constraints and usage rules for the @Provide and @Consume decorators in the Cangjie language. It details key parameter requirements, initialization restrictions, duplicate key resolution, and error handling for missing providers. Key takeaways include that keys must be string literals, @Consume variables cannot be locally initialized and rely solely on matching @Provide keys, and duplicate keys bind to the nearest ancestor. Additionally, type mismatches or missing providers trigger runtime errors. This guide targets developers using state management in component-based UI development to ensure correct data binding and avoid exceptions.
