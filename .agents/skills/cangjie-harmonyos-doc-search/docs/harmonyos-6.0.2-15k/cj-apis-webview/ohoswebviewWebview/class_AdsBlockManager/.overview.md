# class_AdsBlockManager

This directory provides comprehensive API reference documentation for the `AdsBlockManager` class, implemented in the Cangjie language specifically for the ArkWeb framework. It focuses on the technical implementation and configuration of ad-blocking mechanisms within Web and Webview components. The documentation covers essential functionalities such as configuring domain lists (AllowedList and DisallowedList), applying suffix matching logic, and managing custom EasyList syntax rules. Developers will find detailed explanations regarding the persistence of settings, clearly distinguishing between temporary list modifications and persistent custom rules. This resource is specifically designed for application developers who require granular control over web content filtering, enabling them to create cleaner browsing experiences by effectively managing ad-blocking behaviors, parameter requirements, and exception handling within their applications.

## Detailed Description

Below are the detailed summaries for each file contained within this directory.

### class_AdsBlockManager_5more.md class_AdsBlockManager_5more.md
This API reference document details the AdsBlockManager class for configuring ad blocking rules within Web components using the Cangjie language. It covers static methods for managing domain lists, specifically adding to and clearing the AllowedList (re-enabling blocking) and DisallowedList (disabling blocking). Key information includes that the manager uses suffix matching for domains and shares a single instance across all Web components in an application. Notably, DisallowedList settings are not persistent after app restarts. This guide targets application developers working with the ArkWeb framework who need granular control over web content filtering.

### static_func_removeAdsBlock_3more.md static_func_removeAdsBlock_3more.md
This API reference documentation outlines three static Cangjie functions for managing ad-blocking configurations within the Webview component. The primary topics include removing domains from the AllowedList and DisallowedList, and setting custom EasyList syntax rules. Key takeaways are that list removals are non-persistent and require re-application after restart, whereas custom rules are persistent. The setAdsBlockRules function allows either replacing or appending to built-in rules. Intended for developers building web applications, this guide details parameter requirements, system capabilities, and exception handling, specifically error code 401 for parameter errors.
