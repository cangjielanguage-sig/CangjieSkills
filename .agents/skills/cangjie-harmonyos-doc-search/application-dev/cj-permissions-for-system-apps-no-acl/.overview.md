# cj-permissions-for-system-apps-no-acl

This directory serves as a specialized repository for documentation concerning HarmonyOS system permissions that are explicitly excluded from standard Access Control List (ACL) application procedures. It covers high-privilege capabilities essential for system-level operations, including distributed hardware management, system light control, and user authentication processes. The content details specific permission levels, such as `system_basic`, and authorization methods like `system_grant`, alongside API version constraints. This resource is indispensable for system developers and application engineers aiming to implement sensitive features, understand ACL boundaries, and ensure strict compliance with HarmonyOS security standards for core system functionalities. It clarifies the distinction between permissions that can be freely applied for and those that require elevated system status, providing a clear roadmap for secure system app development.

## Detailed Description

### 不可ACL申请的系统应用可用权限系统授权/
This directory provides comprehensive documentation for HarmonyOS system permissions that are explicitly restricted from Access Control List (ACL) applications. It focuses on high-privilege capabilities required for system-level operations, such as managing distributed hardware, controlling system lights, and handling user authentication. The documents outline specific permission levels (system_basic), authorization methods (system_grant), and API version constraints. These resources are critical for system developers and application engineers who need to implement sensitive features, understand the boundaries of ACL usage, and ensure their applications meet the necessary privilege requirements for accessing core system functionalities without standard ACL authorization. By referencing these files, developers can navigate the complex landscape of system authorization and ensure compliance with HarmonyOS security standards. The documentation serves as a vital guide for distinguishing between standard user permissions and those reserved for system-level integration, ensuring that applications do not attempt to request restricted permissions via invalid ACL methods. It provides the necessary context for API versioning and the specific `system_grant` mechanism, which is fundamentally different from user-grant permissions. This ensures that developers can correctly configure their application manifests and understand the security implications of accessing sensitive hardware and software interfaces. Furthermore, the directory helps in identifying which specific APIs are gated behind these non-ACL permissions, allowing for precise architectural planning when building system applications that require deep integration with the operating system.
