# class_Matchers

This directory provides comprehensive API documentation for the `Matchers` class, a fundamental component of the Cangjie unit testing framework dedicated to advanced mocking and stubbing capabilities. It serves as a guide for developers to generate argument matchers that control mock object behavior with high precision. The content covers essential functionalities such as accepting arbitrary values, filtering arguments through custom predicates, and capturing argument values for later verification. Key concepts include the distinction between mock and spy behaviors, the use of the `@On` macro for conditional stubbing, and the nuances of structural versus reference equality. This documentation is specifically tailored for developers implementing unit tests who require granular control over argument matching to ensure their test logic is both robust and reliable.

### class_Matchers_6more.md class_Matchers_6more.md
This API documentation defines the Matchers class, which provides static functions to generate argument matchers for controlling mock object behavior in unit tests. The document details specific static methods including any() for accepting any value, argThat and argThatNot for filtering arguments via predicates, and capture for listening to argument values. Key takeaways include the usage of matchers within @On macro stub chains to define conditional return values or exceptions, and the distinction between mock and spy object behaviors. This reference is intended for developers using the Cangjie unit testing framework to implement precise argument matching and verification in their test cases.

### static_func_defaultTT_5more.md static_func_defaultTT_5more.md
This API reference document details static functions used to create argument matchers within a Cangjie unit testing mock framework. It covers the default, eq, ofType, and same functions, alongside the Matchers extension containing the none function. Key information includes how these functions generate TypedMatcher objects to filter inputs based on structural equality, reference equality, or type. The default function prioritizes structural equality but falls back to reference equality, throwing exceptions for unsupported types, while eq and same enforce specific constraints like Equatable or Object inheritance. This guide targets developers implementing unit tests who need precise control over mock method argument verification.
