# 在仓颉代码里导入ArkTS模块

This directory serves as a technical guide for developers working on HarmonyOS applications, focusing on the interoperability between the Cangjie and ArkTS programming languages. It specifically addresses the mechanisms required to import and load ArkTS modules within Cangjie code. Key topics include the `JSContext.requireArkModule` interface, dynamic loading strategies for various module types (HAR, HSP, Native, System, HAP), and specific configuration files like `oh-package.json5`. The documentation also highlights critical usage restrictions, such as thread limitations and initialization constraints. This resource is essential for developers aiming to achieve seamless cross-language communication and manage complex dependencies in their applications.

## Detailed Description

### 场景介绍_3more.md
This API documentation details the `JSContext.requireArkModule` interface for loading ArkTS modules within the ArkTS interoperability library. The document outlines the module loading scenario, provides the Cangjie function signature, and lists critical usage restrictions. Key takeaways include the requirement to use the interface only on the ArkTS binding thread and prohibitions against calling it during global variable initialization or module exports. It also notes that system modules like `ohos.router` are unavailable in worker threads and that direct calls in `spawn(UIThread)` or `postJSTask` callbacks currently fail. This reference is intended for developers implementing cross-language interoperability between Cangjie and ArkTS.

Key topics cover dynamic loading strategies, configuration specifications in `oh-package.json5` and `build-profile.json5`, and the practical application of the `requireArkModule` function. This resource is essential for HarmonyOS developers aiming to achieve seamless cross-language communication between Cangjie and ArkTS, manage complex dependencies, and optimize module interactions in their applications. The directory includes specific guides on general loading scenarios and detailed technical instructions for handling HAR, HSP, and Native modules.
