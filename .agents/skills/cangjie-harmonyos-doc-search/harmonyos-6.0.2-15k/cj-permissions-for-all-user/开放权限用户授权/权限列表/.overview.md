# 权限列表

This directory serves as a comprehensive resource for HarmonyOS developers regarding system permissions and access controls, specifically targeting API version 12 and later. It encompasses a wide array of permissions necessary for hardware interaction—such as Bluetooth, Camera, and Microphone access—as well as data retrieval for sensitive categories like Calendar, Health, and Media files. Additionally, it addresses specific file system permissions tailored for 2-in-1 devices. The documentation outlines critical implementation details, including permission levels, grant modes (specifically user_grant), and complex workflows like background location access. This collection is essential for developers aiming to ensure compliance and proper functionality when configuring system capabilities in their HarmonyOS applications.

## Detailed Description

### ohospermissionACCESS_BLUE_15more.md ohospermissionACCESS_BLUE_15more.md
This reference document details specific HarmonyOS permissions available starting from API version 12. It covers permissions for hardware access like Bluetooth, Camera, and Microphone, as well as data access for Calendar, Health, and Media files. Most entries are classified as "normal" level requiring "user_grant" authorization. A key highlight is the detailed application workflow for background location access, which mandates obtaining foreground permissions first and guiding users to manually enable background access in settings. This guide is intended for HarmonyOS developers configuring system capabilities in their applications.

### ohospermissionREAD_WRIT_e087722f.md ohospermissionREAD_WRIT_e087722f.md
This API reference document defines the HarmonyOS permission ohos.permission.READ_WRITE_DOCUMENTS_DIRECTORY, which enables applications to read and write data within the public Documents directory. It covers the permission's scope, device-specific constraints, and technical attributes such as permission level and grant mode. Key information includes that this permission is restricted to 2-in-1 device applications, requires user authorization (user_grant), is classified as a normal level permission, and is available starting from API version 12. The target audience is HarmonyOS developers building file management or document-centric applications for 2-in-1 hardware. Keywords: HarmonyOS, permission, file access, API 12, user_grant, 2-in-1 devices.
