# fake_coverage_usage

This directory serves as a vital technical resource for developers utilizing the Cangjie fuzzing framework, specifically addressing a critical libfuzzer termination error found in versions 14 and lower. It focuses on the DataProvider mode, where the fuzzer exits prematurely due to a lack of coverage during initial input probes caused by data consumption failures on short inputs. The guide provides a detailed solution using the `enableFakeCoverage` method, which allows developers to inject false signals to maintain the fuzzer's operation until valid data is consumed. Furthermore, it notes that libfuzzer version 15 resolves this issue natively. This documentation is essential for software engineers seeking to troubleshoot coverage instrumentation errors and ensure the stability of their fuzzing workflows without upgrading the underlying fuzzer engine immediately.

This technical guide addresses a specific libfuzzer termination error encountered when using DataProvider mode with versions 14 or lower. It covers the problem description, the root cause involving initial input probes, and the solution using the enableFakeCoverage method. The document explains that libfuzzer exits if no coverage is detected during initial probes because data consumption fails on short inputs. By enabling Fake Coverage, developers provide false signals to keep the fuzzer running until valid data is consumed. It also notes that libfuzzer 15 fixes this natively. This guide is intended for developers using the Cangjie fuzzing framework who encounter coverage instrumentation errors.
