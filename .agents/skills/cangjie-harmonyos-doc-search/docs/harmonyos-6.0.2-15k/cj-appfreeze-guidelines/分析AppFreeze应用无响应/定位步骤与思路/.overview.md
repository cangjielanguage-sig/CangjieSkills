# 定位步骤与思路

This directory provides a comprehensive technical guide for diagnosing and resolving application unresponsiveness and freeze issues (AppFreeze) within HarmonyOS and Android environments. It covers the complete debugging lifecycle, from initial log acquisition and basic information confirmation to advanced analysis using Binder, Hilog, and Trace tools. Key topics include fault detection logic, IPC bottlenecks, event handler diagnostics, and stack trace interpretation. This resource is suitable for system developers, support engineers, and performance analysts seeking to identify root causes of application instability and optimize system responsiveness.

## Detailed Description

### 定位步骤与思路_2more.md 定位步骤与思路_2more.md
This technical guide outlines the methodology and steps for diagnosing application unresponsiveness issues. It covers the general workflow of log acquisition and analysis, specifically detailing how to retrieve fault logs via DevEco Studio or the hiAppEvent interface. Key information includes the fact that unresponsiveness logs are managed by the FaultLog module, and developers must combine basic log data with hilog and trace tools to pinpoint the exact location of the problem. This document is intended for developers debugging application performance issues, requiring familiarity with development tools and system logging mechanisms.

### 查看_binder_信息.md 查看_binder_信息.md
This technical guide explains how to analyze Binder information to diagnose Android application freeze (AppFreeze) issues. It covers interpreting Binder call chains, identifying IPC_FULL states (thread ID 0), analyzing waitTime discrepancies, and handling transient stacks. Key takeaways include understanding that binder info is captured after warning or block events, and that a thread ID of 0 indicates no available threads, often due to lock contention or full async buffers. The document also notes that small waitTimes suggest the IPC isn't the root cause and that data collection has inherent delays. This guide is intended for Android system engineers or developers debugging IPC-related performance bottlenecks.

### 确认基本信息.md 确认基本信息.md
This technical guide explains how to extract and interpret basic information from HarmonyOS appfreeze logs generated by HiviewDFX. It covers identifying process details like PID and foreground status, determining fault timestamps, and referencing a comprehensive table of detection durations for various fault types such as THREAD_BLOCK and LIFECYCLE_TIMEOUT. The document clarifies the logic for calculating fault occurrence times and details specific reporting rules, such as the accumulation requirement for background applications where five 3s blocks trigger a 6s report. Intended for HarmonyOS developers or support engineers debugging application stability issues, this reference requires basic knowledge of log analysis.

### 结合_hilog_2more.md 结合_hilog_2more.md
This technical guide outlines methods for analyzing application freezes (appfreeze) by integrating Hilog logs and Trace data. It covers DFX-related logs, including fault reporting, stack traces, and kill reasons, and details general analysis steps to pinpoint freeze times based on log output patterns. Key takeaways include identifying freezes through missing or excessive log entries and using Trace to detect dense main thread usage or specific function timeouts. The document provides specific examples, such as FormManagerService timeouts and animation loops, to illustrate debugging workflows. Intended for system developers or debuggers, this guide facilitates the diagnosis of application stability and performance bottlenecks.

### 查看_eventHandler_信息/
This directory provides technical guides for analyzing `eventHandler` dump logs to diagnose system performance issues, specifically application freezes (appfreeze) and scheduling anomalies. It covers the interpretation of task execution times, VIP and High priority queues, and watchdog timer logs. Developers will learn how to calculate task duration, identify bottlenecks in event queues, and distinguish between application freezes and thread starvation. This resource is suitable for system developers and engineers debugging event handling, thread management, and performance optimization in ArkUI applications.

### 查看_stack_信息/
This directory contains technical guides and raw stack trace logs designed to help system developers diagnose and debug application performance issues within the OpenHarmony and HarmonyOS environments. It covers a range of scenarios, including application freezes caused by lock contention or IPC deadlocks, SQLite database I/O timeouts, HAP resource loading failures, and thread busy states in ArkTS runtimes. By analyzing Process IDs (Pid) and Thread IDs (Tid), developers can pinpoint root causes in native C++ libraries or application layers. These resources are essential for engineers troubleshooting system stability, responsiveness, and crash analysis.
