Key topics include usage scenarios for large data lists, dynamic layouts, and specific constraints to avoid common pitfalls. This resource is suitable for Cangjie and HarmonyOS developers looking to enhance rendering efficiency, minimize memory usage, and improve frame rates in complex, data-driven applications.

## Detailed Description

### Reusable宏组件复用_2more.md Reusable宏组件复用_2more.md
This document provides a technical reference for the @Reusable macro, designed to optimize performance by enabling the reuse of custom components. It details how the macro functions alongside the @Component decorator to manage component lifecycles. Key sections explain the caching mechanism: when a marked component is removed from the component tree, it is stored in a reuse cache rather than destroyed. Subsequent component creation retrieves these cached nodes, significantly reducing the time required for instantiation. Currently in Beta, this feature targets developers seeking to enhance application efficiency through intelligent resource management and component recycling.

### 使用场景.md 使用场景.md
This document outlines specific scenarios where applying a component reuse mechanism is necessary to optimize application performance and reduce resource overhead. It covers three primary usage scenarios: handling large data lists during scrolling, managing frequent dynamic layout updates, and optimizing environments with repetitive creation and destruction of data item views. The key takeaway is that reusing existing views instead of constantly creating and destroying them minimizes layout calculations and memory usage. This approach significantly improves frame rates and scrolling smoothness by only updating data content within the reused components. This guide targets developers and UI engineers looking to optimize rendering performance in applications dealing with complex or dynamic interfaces. Keywords: Component reuse, performance optimization, list scrolling, dynamic layout, view recycling, UI rendering.

### 限制条件.md 限制条件.md
This reference document outlines specific constraints and limitations regarding the usage of the @Reusable macro in Cangjie ArkUI development. It covers three primary restrictions: lack of support for mixed projects, incompatibility with @Builder decorators, and the prohibition of nested @Reusable usage. The document explains that nested usage creates separate cache pools, increasing memory and causing lifecycle management issues such as unpaired aboutToRecycle and aboutToReuse calls. It explicitly advises against nesting to ensure efficient resource management. This guide targets Cangjie developers implementing component reuse strategies who need to avoid common pitfalls and compilation errors.
