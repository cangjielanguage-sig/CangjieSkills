# cj-app-permission-mgmt-overview

This directory provides a comprehensive overview of application permission management mechanisms, focusing on the core principles and concepts necessary for secure development. It covers the essential framework for compliantly applying for and utilizing system capabilities, including detailed explanations of permission protection objects and the distinction between authorization modes such as `system_grant` and `user_grant`. The documentation further explores permission group strategies and critical technical components like TokenID, Application Privilege Level (APL), and ACL cross-level applications. Special emphasis is placed on the principle of least privilege, the implementation of dynamic authorization for sensitive permissions, and the system authentication workflow. This resource is tailored for application developers who need to declare permissions, configure security settings, and gain a robust understanding of the system permission model to ensure user privacy and application security.

## Detailed Description

### 应用权限管控概述/

This subdirectory provides a foundational introduction to the core mechanisms and basic concepts governing application permission management. It is designed to guide developers through the complexities of compliantly applying for and using system capabilities. The content covers the definition of permission protection objects and distinguishes between different authorization methods, specifically `system_grant` (granted upon installation) and `user_grant` (granted dynamically during runtime).

Additionally, the text explores permission group policies and delves into critical technical components such as TokenID, which serves as the application's identity for permission verification. It explains Application Privilege Level (APL) classifications and how to use ACL (Access Control List) for cross-level permission applications, allowing apps to access permissions beyond their default level. A significant portion of the documentation is dedicated to the principle of least privilege, ensuring apps minimize access to sensitive data. It also outlines the workflow for dynamically requesting sensitive permissions and the system's authentication process. This section is indispensable for developers who need to declare permissions in configuration files, implement runtime permission requests, and fully grasp the system's security architecture.
