# SysCap开发指导

This directory serves as a comprehensive technical resource for understanding and managing System Capabilities (SysCap) within the HarmonyOS/OpenHarmony development ecosystem. It addresses the critical challenges posed by hardware fragmentation, providing developers with the knowledge to ensure application compatibility across diverse devices. The documentation covers the theoretical origins of SysCap variations, including the mapping of OS components and the generation of PCID and RPCID. Furthermore, it offers practical, step-by-step guidance on configuring capability sets in `syscap.json`, utilizing DevEco Studio for development, and implementing runtime checks using the `canIUse` function. This guide is essential for application developers and product solution vendors seeking to optimize their software for single and cross-device deployment scenarios.

## Detailed Description

### SysCap开发指导_7more.md SysCap开发指导_7more.md
This guide provides instructions for developers on managing System Capabilities (SysCap) during application development. It covers PCID acquisition, configuring association and required capability sets in syscap.json, and strategies for single versus cross-device development. Key information includes the distinction between association (union) and required (intersection) capability sets, and the use of the Cangjie canIUse function or exception handling to verify API availability. The document targets developers using DevEco Studio to ensure application compatibility across various hardware devices.

### 设备间的SysCap差异如何产生的.md 设备间的SysCap差异如何产生的.md
This document explains the origin of System Capability (SysCap) variations across different devices and the lifecycle of managing these differences. It covers the mapping between OS components and SysCaps, the assembly process by manufacturers, and the generation of PCID and RPCID. Key information includes the relationship between components and SysCaps, encoding SysCaps into PCID for development, and using RPCID for installation verification.
