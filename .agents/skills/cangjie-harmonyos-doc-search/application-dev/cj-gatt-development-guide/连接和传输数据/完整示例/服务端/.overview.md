# 服务端

This directory contains technical documentation and code examples for implementing Bluetooth Low Energy (BLE) GATT Server functionality. It covers the complete lifecycle of a BLE server, including initialization, service and characteristic configuration, event handling (read/write requests), connection state management, and resource cleanup. The examples are provided in multiple languages relevant to the OpenHarmony ecosystem, such as Cangjie and ArkTS, with potential references to Kotlin or Swift. This content is suitable for software developers and system engineers building robust Bluetooth server-side applications for HarmonyOS or similar platforms.

## Detailed Description

### 服务端_1.md
This document provides a Cangjie code example for implementing a Bluetooth Low Energy (BLE) GATT Server manager. It details the GattServerManager class structure, covering the initialization of services, characteristics, and standard or custom descriptors. Key sections include defining UUIDs, constructing BLE components, and setting up callbacks for connection state changes and read/write requests. The code illustrates how to handle client configuration descriptors for notifications and indications and how to respond to read requests. This technical reference is intended for developers building BLE server-side applications within the OpenHarmony ecosystem using the Cangjie programming language.

### 服务端_2.md
This document provides a code implementation guide for handling BLE GATT server events and initialization in ArkTS. It covers defining callback functions for characteristic and descriptor read and write operations, including request validation, response generation, and error logging. The content details the process of creating a GATT server instance, adding services, and subscribing to specific event types like connection state changes and data requests. Key takeaways include the logic for sending server responses and simulating characteristic change notifications. This technical guide targets developers building Bluetooth functionality for HarmonyOS applications, requiring prior knowledge of BLE protocols and ArkTS syntax.

### 服务端_3.md
This document provides API code examples for managing Bluetooth Low Energy (BLE) GATT server operations, specifically focusing on notifying clients and server cleanup. Key sections include the `sendCharacterChange` function, which checks descriptors to send either notifications or indications when characteristic values change, and `unRegisterServer`, which handles service removal, event unsubscription, and closing the server connection. The content also defines callback wrapper classes for connection states and read/write requests. Important takeaways involve the conditional logic for notification types and the comprehensive cleanup steps to prevent resource leaks. This technical reference is designed for developers implementing BLE server-side logic, requiring knowledge of GATT protocols and asynchronous event handling.

### 服务端_4.md
This document serves as a technical code reference for implementing server-side Bluetooth Low Energy (BLE) logic, specifically focusing on handling descriptor write requests. The content presents a class definition for DescriptorWriteRequestCb, which acts as a callback wrapper that processes potential business exceptions and request objects. Additionally, it demonstrates the instantiation of a GattServerManager to manage server operations. Key takeaways include the structure of the callback interface, the use of optional error handling, and the initialization of the core server component. This material is intended for software developers with knowledge of BLE protocols and the specific programming language used, likely Kotlin or Swift, who are building or maintaining GATT server functionalities.
