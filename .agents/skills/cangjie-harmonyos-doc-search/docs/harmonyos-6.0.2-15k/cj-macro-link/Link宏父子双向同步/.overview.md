# Link宏父子双向同步

This directory provides comprehensive documentation and tutorials on the `@Link` macro for implementing two-way data binding between parent and child components in Cangjie UI and ArkUI development. It covers core concepts like state synchronization, variable transfer protocols, and observation mechanisms for primitives, classes, and arrays. The content includes technical specifications, usage constraints, troubleshooting guides for type mismatches, and practical scenarios involving `ObservedArrayList` and `@Watch`. It is suitable for developers familiar with `@State` who need to manage reactive state and ensure bidirectional data flow in component hierarchies.

This reference documentation explains the @Link macro, which establishes two-way data binding between parent and child components. Key sections include an overview of shared values, macro usage rules detailing synchronization types and supported variable types, and variable transfer protocols. Important takeaways are that @Link variables must be initialized by the parent, support basic types and complex objects like classes and arrays with specific decorators for deep observation, and ensure changes propagate bidirectionally. The document targets developers already familiar with @State, providing technical specifications for implementing reactive state management in component hierarchies.

### 常见问题.md 常见问题.md
This troubleshooting guide addresses a common type mismatch error when using the @Link decorator in Cangjie UI development. The document focuses on the strict type consistency required between child @Link variables and parent data sources like @State. Key takeaways include the rule that @Link variables must match the exact type of their source (e.g., @Link: T and @State: T). It illustrates a correction where a child component must link to the entire object instance rather than a specific property of that object to ensure proper state synchronization. Targeted at Cangjie developers, this guide provides code examples comparing incorrect and correct implementations to resolve state management issues.

### 观察变化和行为表现.md 观察变化和行为表现.md
This technical guide explains the observation mechanisms and framework behavior of the @Link decorator in ArkUI state management. It covers observing changes in primitives, classes, and arrays, and details the lifecycle and synchronization processes between parent and child components. Key takeaways include that primitives sync automatically, while classes require @Observed and @Publish decorators. Arrays need ObservedArray for internal change detection. The document outlines the two-way data flow where parent @State initializes child @Link, and updates propagate bidirectionally via registered pointers. This reference material targets developers building ArkUI applications who need to understand component state synchronization and rendering updates.

### 限制条件.md 限制条件.md
This reference document outlines the specific usage constraints and limitations for the @Link decorator in Cangjie UI development. It covers component scope, variable declaration syntax, initialization rules, type consistency with data sources, and prohibited data types. Key takeaways include that @Link is restricted to child components (not @Entry), requires parent initialization via @State variables, forbids local initialization, and demands strict type matching between parent and child. Additionally, it clarifies that @Link cannot decorate Function types. This guide targets Cangjie developers implementing state management in custom components to ensure compilation success and correct data flow.
