This document provides guidelines and implementation details for using the Toast component in HarmonyOS applications to display temporary, non-intrusive user feedback. It covers the definition of Toast, the API implementation chain involving UIContext and PromptAction, security constraints, and specific usage recommendations regarding text density, display duration, positioning, and interaction limitations. Key takeaways include that Toasts should be brief (under 3 seconds), avoid interactive elements, adhere to system default positioning to prevent overlap, and are restricted to the current UI instance for security. This guide targets application developers designing user interfaces who need to implement lightweight status notifications without disrupting the user workflow.

### 即时反馈模式对比_2more.md 即时反馈模式对比_2more.md
This technical guide compares two display modes for Toast notifications in ArkUI using the Cangjie language. It details the differences between Default and TopMost modes, specifically regarding sub-window creation, display hierarchy, and keyboard avoidance logic. Key takeaways include that TopMost creates a full-screen sub-window for higher layering and specific keyboard spacing (80.vp), whereas Default mode stays within the main window. The document provides Cangjie code examples for implementing both modes and creating basic toasts. Intended for HarmonyOS developers using Cangjie and ArkUI, this guide helps in selecting the appropriate feedback mechanism for short-lived user prompts.
