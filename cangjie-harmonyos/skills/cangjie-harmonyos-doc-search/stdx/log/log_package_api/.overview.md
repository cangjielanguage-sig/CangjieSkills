# log_package_api

The `log_package_api` directory serves as the comprehensive API reference for the Cangjie language logging library. It encompasses the fundamental building blocks required to implement, manage, and customize logging functionality within applications. This module covers core class definitions, abstract interfaces, data structures, type aliases, global logger management functions, and exception handling mechanisms. It is designed for developers who need to integrate logging into their Cangjie projects, as well as those looking to extend the framework's capabilities through custom implementations. By providing a structured approach to log data and error handling, this API ensures consistency and robustness in system operations.

## Detailed Description

### [1] log_package_classes/
This directory serves as the central repository for the core class definitions within the Cangjie language logging library. It encompasses the essential data structures, abstract interfaces for log writers, the primary logger implementation, and a no-op implementation. It is the primary location for understanding the object-oriented architecture of the logging system.

### [2] log_package_exceptions/
This directory is specifically dedicated to storing core API reference documentation for exception handling within the Cangjie language log package. It primarily defines the `LogException` class, the foundational component for handling errors and anomalies during the logging process. The documentation covers the class's inheritance hierarchy, construction methods, and key implementation details, aiming to provide developers with a standardized exception handling workflow. By mastering these concepts, developers can more effectively capture and manage errors within the logging system, thereby enhancing program robustness. This documentation is primarily intended for Cangjie library developers or application developers requiring deep customization of logging features.

### [3] log_package_funcs/
This directory provides detailed API reference documentation regarding global Logger management within the log package. It focuses on the core control mechanisms of the logging system, specifically the usage specifications for the `getGlobalLogger` and `setGlobalLogger` functions. The content covers how to retrieve a Logger copy based on an input attribute array, as well as the initialization flow and lifecycle management of the global Logger object. Furthermore, it emphasizes that `setGlobalLogger` should be invoked only once during the program's lifecycle and clarifies the strategy for handling log events prior to this call. This document is suitable for developers currently using or integrating the logging framework.

### [4] log_package_interfaces/
The `log_package_interfaces` directory is a foundational element of the Cangjie language's software development kit, specifically tasked with defining the abstract contracts that underpin the logging framework. This directory is essential for establishing the protocols and behaviors that various logging components must adhere to, ensuring modularity and interoperability within the system.
