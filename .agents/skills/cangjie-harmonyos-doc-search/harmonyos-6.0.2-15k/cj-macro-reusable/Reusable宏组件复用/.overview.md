## Detailed Description

### Reusable宏组件复用_2more.md Reusable宏组件复用_2more.md
This document serves as a technical reference explaining the @Reusable macro, designed to enhance performance by enabling the reuse of custom components. The content covers the macro's definition and provides an overview of its caching mechanism. Key information indicates that @Reusable must be used alongside @Component; when a decorated component is removed from the tree, it is cached instead of destroyed. Future component creation requests then reuse these cached nodes to save initialization time. This guide is intended for developers looking to optimize application performance by reducing the overhead of frequent component creation and destruction.

### 使用场景.md 使用场景.md
This document outlines specific scenarios where applying component reuse mechanisms is necessary to optimize application performance and reduce resource overhead. It covers three primary use cases: handling large data lists during scrolling, managing frequent dynamic layout updates, and optimizing environments with rapid view creation and destruction cycles. The key takeaway is that reusing existing views and only updating data content prevents performance bottlenecks like stuttering and excessive layout calculations, thereby ensuring smoother user interactions and higher frame rates. Targeted at developers and UI engineers looking to optimize rendering performance in applications dealing with dynamic or data-heavy interfaces.

### 限制条件.md 限制条件.md
This reference document outlines specific constraints and usage limitations for the @Reusable macro in Cangjie HarmonyOS development. The main topics cover mixed project support, the scope of @Reusable application, and the risks of nested usage. Key takeaways include that mixed projects are currently unsupported and @Reusable is strictly for custom components, causing compilation errors when used with @Builder. Furthermore, nested @Reusable usage is strongly discouraged because it creates independent cache pools, leading to increased memory usage, lower reuse efficiency, and lifecycle management issues where methods like aboutToRecycle and aboutToReuse fail to pair correctly.
