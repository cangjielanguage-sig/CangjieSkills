# 开发步骤

This directory provides comprehensive resources for developing and debugging application performance monitoring features within the HarmonyOS ecosystem. It focuses specifically on detecting and handling application freeze events using the Cangjie language and ArkTS. The content covers the full lifecycle of event handling, from initial code implementation and module configuration to the final analysis of generated log data. Key technical elements include the PerformanceAnalysisKit, HiAppEvent framework, and cross-language interaction patterns. This material is primarily suitable for HarmonyOS developers, performance engineers, and QA professionals seeking to enhance application stability and diagnose complex runtime issues using DevEco Studio. By following these steps, users can effectively implement monitoring systems and interpret system-level data to maintain optimal app performance.

## Detailed Description

### 开发步骤_1.md
This tutorial provides a comprehensive, step-by-step guide designed for developers to subscribe to and handle system appfreeze events within a Cangjie application. The document details the necessary procedures for importing essential modules such as PerformanceAnalysisKit and configuring core components like AppEventFilter and Watcher within the onCreate function. It further instructs on implementing a callback mechanism to log event details effectively. Additionally, the guide explains how to manually trigger the event using an ArkTS button to simulate a freeze condition. Key takeaways include utilizing HiAppEvent for subscription and parsing event parameters. Intended for HarmonyOS developers using DevEco Studio, this guide demonstrates practical cross-language interaction between Cangjie and ArkTS for performance analysis.

### 开发步骤_2.md
This document serves as a vital technical reference, displaying the raw log output for an application freeze event as captured by the HiAppEvent framework. The content provides a detailed breakdown of the APP_FREEZE event structure, listing critical parameters such as bundle information, process IDs, timestamps, and specific exception details like "THREAD_BLOCK_6S". Key takeaways from this reference include the inclusion of memory statistics, thread counts, and references to external log files for deeper, low-level analysis. Intended for software developers and QA engineers, this log aids significantly in diagnosing application stability issues and understanding system behavior during crashes or freezes.
