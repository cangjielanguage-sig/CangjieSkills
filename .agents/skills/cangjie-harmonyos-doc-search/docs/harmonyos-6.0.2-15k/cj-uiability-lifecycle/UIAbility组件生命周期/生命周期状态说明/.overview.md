# 生命周期状态说明

This directory provides comprehensive technical documentation on the lifecycle states of UIAbility and WindowStage components within the HarmonyOS development environment. It covers the entire application lifecycle, including initialization, foreground and background transitions, window management, and destruction. Key topics include the onCreate, onDestroy, onForeground, onBackground, and various WindowStage callbacks. These guides are essential for application developers using the Cangjie language, AbilityKit, and ArkUI frameworks who need to manage system resources efficiently, handle state transitions, and implement robust startup and cleanup logic.

## Detailed Description

### Create状态.md
This technical reference document explains the Create state within the application lifecycle, specifically detailing the initialization phase of UIAbility instances. The content covers the system-triggered onCreate() callback, page initialization tasks such as variable definition and resource loading, and the function of the Want object as an information carrier. Key takeaways include a Cangjie code example demonstrating how to override the onCreate method to handle startup parameters and prepare the UI for display. Intended for application developers using the Cangjie language and the AbilityKit framework, this guide assists in managing app startup logic and component communication.

### Destroy状态.md
This document defines the Destroy state within the UIAbility lifecycle, explaining its trigger conditions and usage. Main sections cover the `onDestroy()` callback, resource management, and specific scenarios like calling `terminateSelf()` or user closure. Key information includes the necessity of overriding `onDestroy()` to release system resources and save data, demonstrated via a Cangjie code example. This technical reference guide targets application developers using the HarmonyOS AbilityKit and Cangjie language who need to manage application lifecycle events effectively.

### Foreground和Background状态.md
This technical guide explains the lifecycle management of UIAbility instances when switching between foreground and background states. It details the onForeground and onBackground callbacks, their specific trigger timings, and best practices for resource management. Key takeaways include using onForeground to acquire necessary resources before UI visibility and onBackground to release resources or perform heavy tasks like state saving after the UI becomes invisible. The document also addresses the onNewWant callback behavior in singleton launch modes. Targeted at developers using the AbilityKit framework, it provides Cangjie code examples to demonstrate efficient application state handling and resource optimization.

### WindowStageCreate和WindowStageDestroy状态.md
This document details the lifecycle management of WindowStage within the UIAbility context for HarmonyOS development. It covers the onWindowStageCreate() callback for UI initialization and event subscription, and the onWindowStageDestroy() callback for resource cleanup. Key information includes using loadContent() to set pages and on('windowStageEvent') to monitor states like foreground, background, and focus. The document provides Cangjie code examples demonstrating event handling for types such as SHOWN, ACTIVE, and HIDDEN. This guide targets HarmonyOS application developers using the Cangjie language and ArkUI framework.

### WindowStageWillDestroy状态.md
This document serves as a technical reference for the onWindowStageWillDestroy() lifecycle state in Cangjie application development. It explains that this callback executes immediately before the WindowStage is destroyed while the object remains usable. The primary content includes a code example demonstrating how to implement this method within a UIAbility class. Key takeaways involve the proper cleanup of resources, specifically unsubscribing from WindowStage events like focus and visibility changes using the off() method. This guide is intended for HarmonyOS developers using the ArkUI framework to ensure proper resource management during the application lifecycle.
