本目录深入解析了应用开发中状态管理的核心机制，重点阐述状态变量如何驱动UI更新及框架的响应式行为。内容涵盖框架底层的渲染逻辑、按需更新原则，以及针对不同数据类型（如基础类型、struct、class、数组）的观察规则。通过理解@State、@Observed等装饰器的使用场景，开发者可以掌握如何高效地触发界面刷新。本文档适合ArkUI及Cangjie语言开发者，旨在帮助其理解底层原理并优化应用性能。

## 详细描述

### 框架行为_4e0b5ff3.md
本文档阐述了框架的核心响应式机制，即状态变量变化如何驱动组件更新并优化渲染性能。主要涵盖了状态变量变更时的依赖查询、组件更新方法的执行以及按需渲染原则。关键信息指出，当状态变量改变时，系统仅查询并执行依赖该变量的组件更新，而与该状态变量不相关的组件或UI描述不会发生重新渲染，从而实现页面渲染的按需更新。该参考文档面向使用该框架的开发者，旨在帮助其理解底层渲染逻辑并优化应用性能。关键词：状态变量、组件更新、按需渲染、框架行为。

### 观察变化.md
这份文档详细说明了在Cangjie语言中使用@State装饰器观察不同数据类型变化的机制。主要涵盖了基础数据类型、struct结构体、class类以及数组集合类型的观察规则。关键信息包括：基础类型可直接观察数值变化；struct仅支持整体赋值观察，无法修改内部属性；class需配合@Observed和@Publish宏才能监听内部及嵌套属性变化；普通数组仅支持整体替换，而ObservedArrayList支持项赋值、属性修改及增删操作的深度观察。这是一份面向ArkUI开发者的状态管理指南，旨在帮助开发者正确实现UI响应式更新。

### 观察变化和行为表现_665603f3.md
本文档旨在阐述状态变量修改与UI刷新之间的关系，解释框架如何感知变化并触发界面更新。主要涵盖可被框架感知的修改类型，以及框架在观察到变化后的具体行为表现机制。核心要点在于明确并非所有状态变量的更改都会引起UI刷新，只有符合框架观察机制的修改才能生效。适用于使用该UI框架的开发者，帮助他们理解状态管理的底层原理以优化界面渲染。
