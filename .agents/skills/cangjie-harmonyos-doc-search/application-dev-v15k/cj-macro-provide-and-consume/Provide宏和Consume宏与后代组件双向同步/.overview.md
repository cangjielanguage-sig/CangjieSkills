# Provide宏和Consume宏与后代组件双向同步

This directory focuses on the `@Provide` and `@Consume` macros in the Cangjie declarative UI framework, enabling efficient two-way data synchronization between ancestor and descendant components. It covers core mechanisms, variable access rules, usage constraints, and practical scenarios ranging from simple counters to complex collections. Designed for developers building responsive HarmonyOS applications, this documentation explains how to bypass intermediate component layers for direct state management, ensuring automatic UI updates and optimized performance through dependency injection and minimal rendering techniques.

## Detailed Description

### Provide宏和Consume宏与后代组件双向同步_3more.md Provide宏和Consume宏与后代组件双向同步_3more.md
This technical reference document explains the usage of the `@Provide` and `@Consume` macros for implementing two-way data synchronization between ancestor and descendant components in the Cangjie declarative UI framework. The content covers an overview of cross-level data binding mechanisms, binding rules via variable names or aliases, and detailed macro specifications including parameters, synchronization types, and allowed variable types. Key takeaways include that `@Provide` makes state variables automatically available to all descendants, while `@Consume` binds to them, creating a bidirectional link that bypasses intermediate component layers. Binding requires matching types and supports nearest-match logic for duplicate names. This guide targets developers familiar with Cangjie's basic syntax and custom components who need to manage state across multiple component hierarchies.

### 变量的传递访问规则说明.md 变量的传递访问规则说明.md
This reference document outlines the variable passing and access rules for the @Provide and @Consume decorators within a UI framework. It is divided into two main sections detailing the specific behaviors of @Provide and @Consume, covering initialization, synchronization, and visibility. Key takeaways include that @Provide allows initialization from various parent state types and enables two-way synchronization with @Consume in descendant components, while @Consume cannot be initialized by a parent but retrieves data from an ancestor @Provide variable. Both decorators enforce private visibility. This guide targets developers managing cross-component state and data flow in component-based applications.

### 限制条件.md 限制条件.md
This document outlines the specific constraints and usage rules for the @Provide and @Consume decorators in the Cangjie language. It covers key literal requirements, initialization restrictions, duplicate key binding behavior, and error handling for missing providers. Key takeaways include that keys must be string literals, @Consume variables cannot be locally initialized and rely solely on matching @Provide keys, and duplicate keys bind to the nearest ancestor. Type mismatches or missing providers result in runtime errors. This reference guide targets developers implementing cross-component state management, helping them prevent compilation and runtime failures.
