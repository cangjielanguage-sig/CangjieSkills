## 示例 3: 数据处理需求 - "解析 JSON 数据"

### 用户原始需求
> "从 API 获取 JSON 数据并解析"

### 技术需求分析

| 分析维度 | 内容 |
|---------|------|
| **功能分析** | 需要发送 HTTP 请求、接收 JSON 响应、解析为可用数据 |
| **数据分析** | JSON 字符串 → 结构化数据（对象或数组） |
| **交互分析** | 异步请求、错误处理、数据转换 |
| **问题类型** | 数据处理/API调用 📡 |

### 技术关键词细化

| 模块/功能 | 关键词 |
|----------|--------|
| **HTTP请求** | HTTP、请求方法、异步处理 |
| **JSON解析** | JSON parse、JsonValue、字符串转对象 |
| **错误处理** | 异常捕获、网络异常、解析异常 |

## 示例 4: 复杂业务需求 - "电商购物页面"

> "创建一个电商购物页面"

### 技术需求分析

| 分析维度 | 内容 |
|---------|------|
| **界面分析** | 商品列表、商品图片、价格显示、加入购物车按钮、购物车状态栏 |

## ✅ 正确的 L0 分析要点

1. **不做业务联想** - 不搜索"篮球"、"电商"、"游戏"等业务词汇
2. **专注技术组件** - 识别 UI 组件、数据结构、交互方式
3. **清晰分类** - 确定问题类型（UI开发/数据处理/语法查询/构建错误）

## ❌ 错误示例

### ❌ 错误分析 1
```
用户需求: "电商购物页面"
错误分析: 需要 PayPal 集成、库存管理系统、物流跟踪
问题: 直接联想业务场景，未分析技术实现点
```

### ❌ 错误分析 2
```
用户需求: "篮球排行榜"
技术关键词: ["排行榜", "排名", "得分"]
问题: 使用业务词汇，"排行榜"不是技术组件
正确做法: ["List", "Text", "数据排序"]
```
