# cj-apply-custom-authentication

This directory provides a specialized development guide for the Unified User Authentication Framework, specifically addressing the implementation of a mechanism to switch from system biometric authentication to custom business authentication. It comprehensively covers the necessary switching logic, a detailed compatibility table for supported authentication types, and a practical Cangjie code example. The guide details the configuration of `WidgetParam` with `navigationButtonText` to display a navigation button. It explains how to handle the result code `12500011` to launch custom interfaces. This resource is suitable for application developers using the Cangjie language who need to implement fallback authentication flows, such as switching to a payment password after biometric failure. It ensures developers can create seamless user experiences when primary authentication methods are unavailable.

## Detailed Description

### cj-apply-custom-authentication.md cj-apply-custom-authentication.md

This development guide provides a comprehensive explanation of how to implement a mechanism for switching from system biometric authentication to custom business authentication within the Unified User Authentication Framework. The document is designed to assist developers in understanding the complete flow, covering the switching logic, a compatibility table for supported authentication types, and a Cangjie code example.

Key technical information provided in the guide includes the specific steps for configuring the `WidgetParam`. Developers are instructed to use the `navigationButtonText` attribute to display a navigation button to the user. The guide details the system behavior: when users click this button, the system returns the result code `12500011`. This return value serves as the prompt for the application to launch its custom authentication interface. This guide is specifically targeted at application developers using the Cangjie language who need to implement fallback authentication flows, such as switching to a payment password after biometric failure.
