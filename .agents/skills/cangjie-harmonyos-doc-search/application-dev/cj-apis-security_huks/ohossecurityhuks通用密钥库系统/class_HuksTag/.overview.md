# class_HuksTag

This directory contains API reference documentation for the `HuksTag` class and related static constant definitions within the HarmonyOS Universal Keystore (HUKS) framework. It covers a comprehensive set of tags used to specify key attributes, cryptographic algorithms, operational parameters, and security access controls in the Cangjie programming language. Key topics include AEAD data, key agreement, block modes, authentication mechanisms, and RSA configurations. This documentation is suitable for security developers, system engineers, and application developers implementing secure hardware-backed key management and cryptographic functions in OpenHarmony or HarmonyOS environments.

## Detailed Description

### static_const_HUKS_TAG_AE__12more.md static_const_HUKS_TAG_AE__12more.md
This document serves as an API reference defining specific static constant tags for the HUKS (Hardware Universal Key Store) system in the Cangjie programming language. It covers constants related to AEAD data, key agreement parameters (algorithms, keys, aliases), general cryptographic algorithms, block modes, associated data, and authentication mechanisms like attestation challenges and auth tokens. Each constant is defined as a UInt32 combining a tag type and a specific ID, with details on system capabilities and version requirements (starting from version 22). This reference is intended for security developers implementing cryptographic operations and key management in HarmonyOS or OpenHarmony applications, requiring knowledge of the HUKS framework and Cangjie syntax.

### static_const_HUKS_TAG_CHA_13more.md static_const_HUKS_TAG_CHA_13more.md
This document serves as a reference for static constant definitions of HUKS tags used in the Cangjie programming language for HarmonyOS security operations. It lists specific tags such as HUKS_TAG_CHALLENGE_TYPE, HUKS_TAG_DERIVE_KEY_SIZE, HUKS_TAG_DIGEST, and HUKS_TAG_KEY_AUTH_ACCESS_TYPE, detailing their values, functions, and system capabilities. These constants define parameters for cryptographic processes including key derivation, import, storage, and access control. Most tags are of type UInt32 and belong to the SystemCapability.Security.Huks namespace. The target audience is HarmonyOS developers implementing secure key management and cryptographic functions using the Cangjie language.

### static_const_HUKS_TAG_KEY_13more.md static_const_HUKS_TAG_KEY_13more.md
This API reference document defines Cangjie constant values for various HUKS (Harmony Universal KeyStore) tags used in cryptographic key management. It enumerates tags related to key attributes such as size, type, purpose, generation type, storage flags, padding, and nonce, alongside several reserved identifiers. Each constant is a UInt32 combining a tag type and a specific ID, supporting system capabilities like Core and Extension starting from version 22. This reference is intended for security developers implementing cryptographic operations in OpenHarmony applications using the Cangjie language.

### static_const_HUKS_TAG_RSA__6more.md static_const_HUKS_TAG_RSA__6more.md
This API reference document defines six specific constant tags used within the HarmonyOS Universal Keystore (HUKS) system for configuring cryptographic parameters and security attributes. The content covers tags for RSA PSS salt length types, key derivation salt values, unwrap algorithm suites, user authentication types, user IDs, and authentication storage levels. Each constant is defined as a UInt32 combining a tag type and a specific ID, with system capabilities and version 22 specified. Notably, the user authentication tag supports combinations like face and fingerprint for secure access control. This reference is intended for system developers and security engineers implementing key management and access control in HarmonyOS applications.
