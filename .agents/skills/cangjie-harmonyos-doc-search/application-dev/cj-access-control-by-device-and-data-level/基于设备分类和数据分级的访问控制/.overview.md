# 基于设备分类和数据分级的访问控制

This directory focuses on implementing robust access control mechanisms based on device classification and data classification within the Cangjie language environment. It comprehensively covers how to configure security levels for both relational and key-value databases to ensure data protection. Key topics include setting specific security grades (S1-S4), understanding device security levels (SL1-SL5), and managing synchronization rules between distributed devices. This resource is suitable for developers using the ArkData framework who need to design secure database environments and strictly control data flow across different device security tiers.

## Detailed Description

### 使用关系型数据库实现数据分级.md 使用关系型数据库实现数据分级.md
This tutorial demonstrates how to implement data classification by configuring security levels for relational databases in the Cangjie language. The document outlines the process of obtaining the application context and creating a database instance with a specific security grade. Key information includes using the StoreConfig class to set the RelationalStoreSecurityLevel.S1 parameter and invoking the getRdbStore function. Intended for Cangjie developers using the ArkData kit, this guide provides the necessary code snippets to establish a secure database environment with defined access controls.

### 使用键值型数据库实现数据分级.md 使用键值型数据库实现数据分级.md
This tutorial explains how to implement data classification in key-value databases by configuring the security level parameter. It details the process of obtaining the UIAbility context and creating a KV store with a specific security level (S1) using Cangjie code. Key takeaways include the usage of KVOptions and KVSecurityLevel.S1, along with important constraints for upgrading security levels: upgrades are irreversible, require closing the database, and do not support cross-device synchronization. This guide targets developers using the ArkData framework to manage data security in single-device scenarios.

### 基于设备分类和数据分级的访问控制_4more.md 基于设备分类和数据分级的访问控制_4more.md
This document outlines the access control mechanism for distributed data management, utilizing data security labels and device security levels to ensure data protection. It details the classification of data into four risk levels (S1-S4) and devices into five security levels (SL1-SL5) based on hardware capabilities. The core rule dictates that data can only sync to a remote device if the local data's security label does not exceed the remote device's security level. The document provides a synchronization matrix and practical examples, such as SL1 devices only accepting S1 data. This technical guide is intended for developers designing secure distributed databases, emphasizing the importance of aligning database content with appropriate security labels.
