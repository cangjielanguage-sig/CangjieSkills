# cj-actions-entities

This directory provides essential documentation for HarmonyOS developers regarding the use of Actions and Entities within implicit Want parameters. It serves as a technical reference for defining generic operations (such as viewing data) and categorizing system components (such as browsers). The content covers specific constants like `ACTION_VIEW_DATA` and `ENTITY_HOME`, illustrating how they function to match caller requests with receiver skills. However, a primary focus of this documentation is the security implications of these features; it explicitly warns against their continued use due to risks like malicious traffic hijacking. Consequently, it outlines the system's roadmap for deprecating these features and guides developers toward adopting safer, specific type-based launching methods. This resource is suitable for application developers currently maintaining legacy code or configuring module skills who need to understand the shift away from implicit intents. Understanding these definitions is critical for ensuring application compatibility while adhering to new security protocols.

## Detailed Description

### cj-actions-entities.md cj-actions-entities.md

This reference document serves as a comprehensive guide to the common actions and entities utilized within implicit Want parameters specifically for HarmonyOS application development. It provides a detailed breakdown of the definitions and implementation strategies for "actions," which represent generic operations such as viewing or choosing data, and "entities," which are used to categorize components like browsers. The document lists specific constants, including `ACTION_VIEW_DATA` and `ENTITY_HOME`, and explains their specific roles in the system's ability to match caller requests with the appropriate receiver skills.

Crucially, the text goes beyond mere implementation details to address significant security concerns associated with these legacy features. It explicitly advises developers against the continued use of these implicit parameters. The document highlights the system's plan to deprecate these features as a necessary measure to prevent malicious traffic hijacking and other security vulnerabilities. As a key takeaway, it strongly recommends that developers transition to using specific type-based launching methods instead of relying on these implicit mechanisms. This guide is primarily intended for developers who are configuring module skills or handling implicit intents and need to update their practices to align with current security standards and future system requirements.
