# cj-page-routing

This directory serves as a specialized technical resource for understanding page routing mechanics within the Cangjie (cj) and HarmonyOS development ecosystem. It focuses primarily on the `ohos.router` module, providing detailed insights into its implementation for various navigation tasks. Key topics covered include page jumping, returning to specific pages, data transfer between views, and page stack lifecycle management. The documentation explicitly identifies this module as deprecated for new projects, strongly recommending the Navigation component as the modern alternative. This collection is particularly suitable for HarmonyOS and Cangjie developers who are responsible for maintaining legacy codebases, troubleshooting existing routing logic, or seeking a historical understanding of the framework's evolution before undertaking a migration to the current best practices. It acts as a bridge for developers transitioning from older patterns to modern standards.

## Detailed Description

### 页面路由ohosrouter不推荐/

This directory provides comprehensive documentation on the `ohos.router` module, which serves as the traditional mechanism for page navigation within HarmonyOS and Cangjie applications. The content is designed to assist developers in mastering the essential routing operations required for robust application development. It covers the technical implementation of page jumping, allowing for smooth transitions between different user interfaces. Furthermore, it details the procedures for returning to previous pages or navigating to specific pages within the application's history stack, which is crucial for complex user flows.

Beyond basic navigation, the guide delves into advanced data handling. It explains how to effectively pass data between pages, ensuring that state and user inputs are preserved during transitions. The documentation also provides insights into managing the page stack lifecycle, a key aspect of memory management and application stability in the HarmonyOS environment.

User experience is another focal point. The directory outlines methods for adding confirmation dialogs before navigation events. This feature is particularly important for preventing data loss, as it warns users before they leave a page with unsaved changes. Crucially, the content marks the `ohos.router` module as not recommended for new development. It explicitly advises developers to adopt the Navigation component, which offers enhanced functionality and better alignment with current architectural standards. This resource is therefore highly suitable for HarmonyOS and Cangjie developers who are maintaining legacy code, troubleshooting existing routing issues, or seeking to understand the historical context of routing before migrating to the recommended framework. By understanding the limitations of the old module, developers can better appreciate the improvements offered by the new system.
