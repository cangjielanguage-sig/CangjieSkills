# 受限开放权限

This directory serves as a comprehensive guide for managing restricted open permissions within the HarmonyOS and OpenHarmony development environments. It addresses the critical procedures and compliance standards required for applications that need access to sensitive system capabilities. The content covers the end-to-end application process, including eligibility criteria, the necessity for prior approval, and the rigorous audit processes conducted by App Gallery Connect (AGC) during the release phase. Furthermore, it provides detailed reference documentation for API version 12 permissions, outlining specific authorization types, usage scopes, and hardware constraints. This resource is specifically designed for HarmonyOS developers and enterprise engineers who are building advanced applications requiring elevated privileges, such as USB debugging or system-level file management, and must adhere to strict security protocols to ensure successful publication and operation.

## Detailed Description

### 申请方式.md 申请方式.md
This document outlines the application process for developers seeking to use restricted permissions in HarmonyOS applications. It covers the eligibility criteria for these permissions and the subsequent review process during app publishing. Key information includes that only applications fitting specific special scenarios are eligible for restricted permissions, requiring prior approval. Furthermore, the App Gallery Connect (AGC) will strictly audit the usage scenario during the release phase, rejecting apps that do not justify the need for these permissions. This guide targets HarmonyOS developers whose applications require sensitive system capabilities and need to navigate the compliance and publishing requirements.

### 权限列表/
This directory contains reference documentation for sensitive system permissions introduced in API version 12 for OpenHarmony and HarmonyOS. It covers specific authorization requirements, usage scopes, and restrictions for hardware access, file management, input monitoring, and system-level operations. Key topics include `system_grant` vs `user_grant` types, allowlist requirements, and device-specific constraints (e.g., 2in1 devices). This resource is suitable for application developers and enterprise engineers implementing advanced features like USB debugging, disk access, or floating windows while adhering to strict security protocols.
