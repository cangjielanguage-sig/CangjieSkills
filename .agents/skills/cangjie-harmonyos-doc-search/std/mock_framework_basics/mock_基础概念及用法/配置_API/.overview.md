# 配置_API

This directory contains comprehensive documentation for the Configuration API of a Cangjie mocking framework. It covers essential aspects of defining mock and spy behaviors, including parameter matching, operation definitions, and stub chaining. Developers will find guides on using the `@On` macro, setting return values, enforcing call cardinality, and handling complex sequential logic. This resource is suitable for software engineers and QA professionals looking to isolate dependencies and simulate component behavior during unit testing in the Cangjie language.

## Detailed Description

### 参数匹配器.md 参数匹配器.md
This reference guide explains how to define and use parameter matchers within a Cangjie mocking framework to specify conditions for stub function arguments. It details predefined matchers like any(), eq(), and argThat(), alongside syntax sugar such as the _ symbol. Key information includes the default use of structural equality for identifiers, handling of default parameters, and the restriction against using function calls directly as matchers. Intended for developers writing unit tests, this guide provides examples and rules for resolving type inference issues in stubs.

### 操作_API_2more.md 操作_API_2more.md
This API documentation outlines the operations and expectations available in a mock framework for the Cangjie language. It details specific actions for different stub types, including general operations like `throws` and `fails`, return value handling for functions, and delegation methods for spies. The document further explains how to define call cardinality using selectors such as `once` or `times` to enforce invocation limits. It provides a table of default expectations for each action type. This guide is intended for developers implementing unit tests who need to configure mock behavior and verify interaction counts.

### 桩链.md 桩链.md
This document serves as a technical reference explaining the implementation and usage of stub chaining within a testing framework. It covers the definition of "Continuation" instances returned by specifiers like returnsConsecutively and times(n), detailing how the then() function links subsequent actions. Key information includes the rule that calling then() requires a new operation and that the total expectation is the sum of all chain parts. The text provides code examples demonstrating how to split return sequences and simulate retry logic, such as throwing exceptions before returning a success response. This guide is intended for developers writing complex unit tests requiring sequential behavior simulation.

### 配置_API_3more.md 配置_API_3more.md
This document serves as a reference guide for the Configuration API within a Cangjie testing framework, detailing how to define mock and spy object behaviors using the `@On` macro. It covers stubbing concepts, supported declaration types (instance, static, top-level), the structure of stub declarations, and specific syntax rules for stub signatures including methods, properties, fields, and operators. Key takeaways include the distinction between stubbing instance members versus static/top-level declarations, the specific syntax patterns for matching calls, and the list of unsupported declarations like constructors and private members. The content is intended for developers writing unit tests in Cangjie who need to simulate component behavior or isolate dependencies.
