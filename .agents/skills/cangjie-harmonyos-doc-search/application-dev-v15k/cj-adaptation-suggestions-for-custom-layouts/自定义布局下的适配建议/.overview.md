# 自定义布局下的适配建议

This directory serves as a comprehensive technical guide for developers and UI/UX designers focusing on the integration of password vault autofill services within custom application layouts. It details the specific architectural and design constraints required to ensure that the SDK functions correctly across various authentication scenarios. The content covers the entire spectrum of user account management, including login, registration, and password modification processes. It highlights critical UI patterns that must be avoided—such as separating username and password fields across different screens—to prevent functional limitations. By following these adaptation suggestions, teams can ensure their applications support seamless and secure autofill experiences. This documentation is particularly suitable for software engineers and system architects responsible for implementing secure authentication flows and managing application state during user interactions.

## Detailed Description

### 将导致功能受限的布局.md 将导致功能受限的布局.md
This reference document outlines specific user interface layouts that restrict the functionality of a password vault autofill feature. It categorizes limitations across three main scenarios: Login, Registration, and Password Modification. Key takeaways include that autofill is unsupported when username and password fields are located on separate screens, during verification code logins, or when password change screens lack specific field combinations like the old password. This guide targets developers and designers integrating password vault services, ensuring they design authentication flows compatible with the SDK's capabilities. Keywords: password vault, autofill, UI layout, authentication, integration, functional limitations.

### 登录_4more.md 登录_4more.md
This guide outlines UI requirements and logic for implementing login, registration, and password modification pages to integrate with a password vault system. It covers specific interface configurations for these actions and details handling failed authentication attempts. Key takeaways include the necessity of placing username and password fields together and setting the enableAutofill attribute to false during failed navigation to prevent saving incorrect data. The document provides a Cangjie code example demonstrating state management for the autofill feature. Intended for developers, this technical reference requires understanding of application routing and input component properties.
