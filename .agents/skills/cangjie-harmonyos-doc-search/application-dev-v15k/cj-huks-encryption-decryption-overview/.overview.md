# cj-huks-encryption-decryption-overview

This directory serves as a specialized technical resource for developers working with the OpenHarmony HUKS (Harmony Universal KeyStore) framework. It provides a detailed overview of encryption and decryption capabilities, specifically focusing on the algorithm specifications supported across various device categories. The documentation distinguishes between standard and lightweight devices, offering tailored guidance for each environment to optimize performance and security. It covers critical cryptographic algorithms including AES, RSA, SM4, and SM2, outlining their specific block modes, padding schemes, and essential parameters such as IV, Nonce, and TAG. This reference is essential for developers ensuring secure data handling and compliance with API level 15+ requirements in their OpenHarmony applications, helping them navigate the complexities of cryptographic implementation. By utilizing this guide, developers can effectively select the correct algorithm combinations and parameters required for robust security solutions.

## Detailed Description

### cj-huks-encryption-decryption-overview.md cj-huks-encryption-decryption-overview.md

This document acts as a comprehensive technical reference guide detailing the encryption and decryption capabilities within the HUKS framework. Its primary focus is to define the precise specifications of supported algorithms, categorized by device type to accommodate different hardware capabilities. The content is logically divided into two main sections: specifications for standard devices and specifications for lightweight devices, ensuring that developers can find the relevant information for their specific target environment.

Within these sections, users will find detailed tables that enumerate valid algorithm combinations. These include widely used international standards such as AES and RSA, as well as national standards like SM4 and SM2. For each algorithm, the document provides granular details on permissible block modes, padding modes, and the mandatory parameters required for secure operations, such as Initialization Vectors (IV), Nonces, and Authentication Tags (TAG). It is important to note that all cryptographic features and specifications listed in this document are applicable only to systems running API level 15 or higher. This guide is intended for developers implementing cryptographic operations in OpenHarmony, providing the necessary constraints and parameter requirements for secure data handling. By strictly adhering to these specifications, developers can ensure the integrity, confidentiality, and security of their applications' data processing workflows. The document serves as a critical tool for avoiding common implementation errors and ensuring compatibility with the underlying HUKS subsystem.
