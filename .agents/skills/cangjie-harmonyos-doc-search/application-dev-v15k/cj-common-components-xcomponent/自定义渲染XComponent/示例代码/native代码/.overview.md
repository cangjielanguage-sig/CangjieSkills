# native代码

This directory contains C++ source code and headers for a native graphics application using OpenHarmony/HarmonyOS APIs. It focuses on EGL and OpenGL ES 3.0 rendering within a Native XComponent environment. Key components include the `EGLCore` class for context management, `PluginManager` for lifecycle and surface handling, and `PluginRender` for specific drawing operations. The code demonstrates shader compilation, geometric rendering (like stars), and window management. It is suitable for C++ developers working on low-level graphics programming, specifically those integrating native rendering surfaces into HarmonyOS applications.

## Detailed Description

### egl_coreh.md egl_coreh.md
This C++ header file defines the EGLCore class, which encapsulates the initialization, management, and rendering logic for an EGL and OpenGL ES 3.0 graphics context within a native application. The document outlines the class structure including public lifecycle methods for context creation, drawing, and resource release, alongside private helper functions for shader compilation, program linking, and specific geometric drawing operations like stars and 2D rotations. Key members include handles for the EGL display, surface, and context, as well as viewport dimensions, supporting dynamic color changes and background rendering. Intended for C++ developers working with native graphics APIs, specifically those implementing custom rendering surfaces using EGL and OpenGL ES 3 on platforms supporting Native XComponent.

### plugin_managercpp.md plugin_managercpp.md
This C++ source file implements the PluginManager class to manage the lifecycle and rendering operations of native plugin components within the NativeXComponentSample namespace. It covers surface management, window creation, and rendering commands. Key methods include SetSurfaceId, DestroySurface, ChangeSurface, DrawPattern, and ChangeColor. The class utilizes static unordered maps to track PluginRender and OHNativeWindow instances by their surface IDs. It delegates specific rendering tasks like drawing and resizing to the PluginRender objects while handling resource cleanup in the destructor. This implementation is intended for C++ developers working with OpenHarmony or HarmonyOS native APIs to handle graphical rendering and window management.
