# 鸿蒙应用经验沉淀 Skill

## 目的

维护项目根目录下的 Evolution.md，记录每次构建中遇到的难点与已验证解决方案，使后续相同问题能快速定位修复

## 核心原则

- 只记录已验证方案，BUILD SUCCESSFUL 之后才允许写入
- 每条记录必须完整，缺少必填字段不允许写入
- 查阅优先于新增，遇到构建失败先搜索 Evolution.md 匹配已有经验

## 记录格式

每条经验追加到 Evolution.md 末尾：

```markdown
## [简短问题标题]

- **日期**：YYYY-MM-DD
- **错误类型**：[编译错误 / 链接错误 / 运行时错误 / 打包错误 / 签名错误 / 配置错误]
- **错误信息**：
  ```
  [从 build.log 中摘录的关键报错]
  ```
- **原因分析**：[根因]
- **解决方案**：[具体修改]
- **正确代码示例**：
  ```cangjie
  // 修复后的关键代码片段
  ```
- **关键词**：[检索用关键词，逗号分隔]
```

## 使用场景

### 构建失败时查阅（读取）

harmonyos-build Skill 失败处理的第一优先级步骤

1. 读取项目根目录下的 Evolution.md（不存在则跳过）
2. 从 build.log 提取关键报错信息
3. 按优先级匹配：错误信息 → 关键词 → 错误类型
4. 命中则直接应用解决方案并重新构建，未命中则退出本 Skill

### 构建成功后沉淀（写入）

本次经历了失败→排查→修复→成功的完整周期时写入

1. 确认 BUILD SUCCESSFUL
2. 按记录格式组织内容，追加到 Evolution.md 末尾（不修改已有记录）
3. 向用户简要确认已沉淀的条目标题

### 首次即成功

构建一次通过无问题，无需写入

## 注意事项

- 不记录纯拼写错误等琐碎问题，重点记录有普遍参考价值的难点
- 代码示例精简到关键修改部分
- 关键词要覆盖类名、函数名、错误码、框架概念等可能的检索词
- 旧记录方案过时时在其下方追加更新说明，不删除原记录
