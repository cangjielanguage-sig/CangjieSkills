# Unittest_基础概念及用法

This directory covers the fundamental concepts and usage of the Cangjie unittest framework. It provides comprehensive resources for writing, organizing, and configuring unit tests, ranging from basic test functions to advanced lifecycle management. Key topics include the distinction between test functions and classes, assertion strategies for validation, and runtime configuration for execution control. Designed for Cangjie developers and QA engineers, this documentation guides users through the `cjpm` ecosystem to implement robust testing structures, manage test lifecycles, and optimize execution performance using macros and command-line tools.

## Detailed Description

### 测试及测试用例.md 测试及测试用例.md
This document serves as a guide for implementing tests within the Cangjie unittest framework, distinguishing between test functions and test classes. It explains that tests are marked with the `@Test` macro, while test classes utilize the `@TestCase` macro for individual methods to support structured testing and lifecycle behaviors. The content includes a code example demonstrating a test class with multiple cases and displays the resulting output from the `cjpm test` command. This resource is intended for Cangjie developers looking to organize their unit tests effectively, providing the necessary syntax and structural definitions for writing robust test cases.

### 测试生命周期.md 测试生命周期.md
This reference guide explains how to manage test lifecycle hooks for setup and teardown in the Cangjie testing framework. It details four specific macros (@BeforeAll, @BeforeEach, @AfterEach, @AfterAll), their execution order, parameter constraints, and usage within @Test classes. Key takeaways include that these hooks only apply to classes, not top-level functions, and that execution behavior varies for parameterized and parallel tests. BeforeEach/AfterEach can accept a test case name string. The target audience is developers using Cangjie to write structured unit tests.

### 测试配置.md 测试配置.md
This document serves as a reference guide for configuring advanced features within a unit testing framework. It covers three primary methods for setup: using the `@Configure` macro, applying command line arguments during runtime or via `cjpm test`, and utilizing the `cjpm` configuration file. The key takeaway is that advanced testing capabilities require explicit configuration through one of these channels. This guide is intended for developers and quality assurance professionals using the `cjpm` ecosystem who need to customize test execution parameters. Keywords: unit testing, configuration, cjpm, command line arguments, macro.

### 断言/
This directory provides comprehensive documentation for implementing assertions within the Cangjie testing framework. It covers essential testing mechanisms including standard behavior verification, explicit failure handling, and exception validation. Key topics include the distinction between fail-fast (`@Assert`, `@Fail`) and continuation-based (`@Expect`, `@FailExpect`) strategies, as well as approximate equality comparisons via the `NearEqutable` interface. This resource is designed for Cangjie developers seeking to write robust unit tests with precise control over execution flow, error reporting, and floating-point arithmetic validation.

### 运行配置/
This directory provides comprehensive documentation for configuring and executing unit tests within the CJC and cjpm development environment. It focuses on runtime flags and command-line options that allow users to control test execution flow, output visibility, and reporting mechanisms. Key topics covered include output capture settings to prevent log interleaving, parallel execution strategies for independent test classes, and advanced filtering using tags and patterns. Additionally, it details benchmarking capabilities and custom configuration options. This resource is essential for developers and QA engineers seeking to optimize test performance, manage reporting formats like XML and CSV, and ensure precise control over test execution behavior.
