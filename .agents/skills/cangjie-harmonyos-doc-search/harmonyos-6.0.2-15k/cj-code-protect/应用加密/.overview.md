# 应用加密

This directory provides comprehensive resources regarding application encryption, with a specific focus on the HarmonyOS ecosystem. It addresses the critical need for code protection against reverse engineering and unauthorized access. The content covers both theoretical aspects and practical implementation, including system-level security mechanisms using AES algorithms, performance implications, and alternative security strategies like obfuscation. Developers will find guidance on the end-to-end encryption process, from capability introduction to the release phase workflow. Additionally, it clarifies the trade-offs between security and performance, such as potential overhead and increased application volume. This directory is essential for HarmonyOS developers and security engineers aiming to balance robust security measures with application performance and package size constraints.

## Detailed Description

### 常见问题.md
This document serves as a FAQ guide addressing common concerns about application code protection, specifically focusing on official code encryption capabilities and alternative security measures. It covers three main topics: the sufficiency of official code encryption, alternative protection methods if encryption is not used, and the impact of encryption on application performance and package size. Key takeaways include that code encryption increases reverse engineering difficulty but should be combined with obfuscation and third-party hardening for maximum security. Users are warned that encryption may cause slight performance overhead and increased application volume. The target audience is application developers or security engineers seeking to safeguard code assets. Keywords: code encryption, application security, reverse engineering, obfuscation, performance impact, app hardening.

### 应用加密_5more.md
This document outlines the HarmonyOS application encryption feature, a system-level security mechanism designed to protect code against reverse engineering. It details the end-to-end encryption process using AES algorithms, covering the capability introduction, performance impacts, encryption effects on .abc files, and the step-by-step usage workflow. Key takeaways include that encryption is selected during the app market release phase, keeping code encrypted on disk and only decrypting in memory, thereby enhancing security with minimal performance overhead. This guide targets HarmonyOS developers seeking to secure their applications, noting current support for phones and tablets but limited compatibility with wearables.
