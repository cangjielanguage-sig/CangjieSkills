# 非首次渲染

本目录主要介绍在ArkUI框架中使用仓颉语言开发时，如何处理LazyForEach组件在数据源发生变化后的非首次渲染更新。内容涵盖了数据交换、单个及批量数据修改、子属性更新以及数据的增删操作。核心概念包括BasicDataSource、notifyData系列方法、@Observed深度观测及UI局部刷新机制。该文档适合需要优化列表渲染性能、处理动态数据状态管理的HarmonyOS开发者参考。

## 详细描述

### 交换数据.md 交换数据
本文档作为教程，演示了如何在Cangjie语言中使用LazyForEach组件和自定义数据源实现列表数据的交换功能。文档详细介绍了继承自BasicDataSource的MyDataSource类的实现，特别是包含数据更新和通知机制的moveData方法。文中解释了交互逻辑：通过点击两个列表项，调用notifyDataMove方法触发LazyForEach的UI更新，从而高效地交换子组件位置。核心概念涵盖数据源管理、事件处理及UI同步。该指南面向使用ArkUI和Cangjie的开发者，旨在帮助他们处理动态列表项重排和状态更新。

### 改变单个数据.md 改变单个数据
本文档旨在演示如何在LazyForEach渲染的列表中更新单个数据项并触发UI局部刷新。文档通过自定义MyDataSource类，重点展示了changeData方法的实现，即修改数据后调用notifyDataChange通知监听器。核心机制在于，当用户点击列表项时，数据源更新会触发LazyForEach的onDataChange回调，从而仅重建对应索引的子组件。本文属于代码教程，适用于使用仓颉语言开发ArkUI应用的开发者，需具备基础组件和数据源绑定知识。

### 改变多个数据_91ef24e7.md 改变多个数据_91ef24e7.md
本文档旨在演示如何在LazyForEach组件中实现多个数据项的批量修改与重新加载。文档通过Cangjie代码示例展示了自定义数据源MyDataSource的实现，重点讲解了modifyAllData方法修改数据后，调用reloadData触发notifyDataReload的流程。核心机制在于LazyForEach通过键值比对新旧数据项，若键值相同则复用缓存，不同则重建节点。这适用于需要高效处理列表数据批量更新的UI开发场景，面向具备基础组件开发能力的开发者。

### 改变数据子属性.md 改变数据子属性
本文档旨在介绍如何在LazyForEach中利用深度观测机制优化数据子属性更新时的渲染性能。文档涵盖了LazyForEach默认刷新机制的性能瓶颈，引入了@Observed和@Link装饰器进行深度观测，并提供了完整的Cangjie代码示例。核心要点在于，利用@Observed和@Link机制，当数据子属性变化时，框架仅刷新使用该属性的特定组件，而无需重建整个ListItem，从而显著提升性能。该文档面向使用ArkUI框架的开发者，特别是需要处理复杂列表组件状态管理及性能优化的技术人员。

### 非首次渲染_3more_b6cf4f7b.md 非首次渲染_3more_b6cf4f7b.md
本文档旨在指导开发者如何在LazyForEach数据源发生变化时进行非首次渲染更新。文档主要涵盖添加数据和删除数据两个核心场景，提供了基于Cangjie语言的代码示例。关键信息包括通过实现BasicDataSource并在数据变动时调用notifyDataAdd或notifyDataDelete方法，进而触发listener通知LazyForEach创建或删除子组件。这是一份面向HarmonyOS开发者的技术教程，要求读者具备基础组件开发知识。

### 精准批量修改数据/
本目录包含关于如何在Cangjie语言中通过LazyForEach实现数据源精准批量修改的技术文档。内容涵盖了继承BasicDataSource、利用notifyDatasetChange方法以及DataOperation（如移动、交换、增加、删除）的具体实现与逻辑。重点在于优化列表数据变更时的渲染性能，详细解析了索引计算规则及操作限制。适合具备基础UI开发能力、需要高效管理动态数据列表的开发者参考。
