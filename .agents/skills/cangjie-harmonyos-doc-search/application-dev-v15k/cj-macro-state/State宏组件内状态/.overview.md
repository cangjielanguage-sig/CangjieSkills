# State宏组件内状态

This directory provides comprehensive documentation on the `@State` macro within the Cangjie programming language and ArkUI framework, focusing on managing internal component state. It covers fundamental definitions, usage scenarios, constraints, and the mechanisms of reactive rendering. Key topics include state initialization, data type support, component isolation, and performance optimization. The content is designed for developers building HarmonyOS applications who need to implement reactive UI components, manage state synchronization, and troubleshoot common issues related to state observation and lifecycle management.

## Detailed Description

### State宏组件内状态_4more.md State宏组件内状态_4more.md
This reference document defines the @State macro, the fundamental mechanism for managing internal component state and triggering UI refreshes in a declarative framework. It covers an overview of @State characteristics, detailed usage rules regarding supported data types, and rules for variable initialization and passing between components. Key information includes that @State variables are private, require local initialization, and support one-way sync with @Prop and two-way sync with @Link. While supporting basic types, complex types like classes and arrays require specific decorators like @Observed or ObservedArray to detect internal changes. Intended for developers with basic knowledge of state management frameworks, this guide serves as a technical reference for implementing reactive UI components.

### 使用场景.md 使用场景.md
This document serves as a usage guide for the @State decorator in the Cangjie programming language within the ArkUI framework. It covers two primary scenarios: decorating simple type variables and class object type variables. Key takeaways include how @State variables trigger targeted component updates upon modification and the initialization mechanism, distinguishing between default values and externally passed parameters. The guide demonstrates component isolation, ensuring state changes in one instance do not affect others. Targeted at developers building HarmonyOS applications, this tutorial requires basic knowledge of Cangjie syntax and UI component lifecycle.

### 限制条件.md 限制条件.md
This document outlines specific usage constraints and limitations for the @State decorator in the Cangjie programming language. It covers mandatory variable initialization requirements and restrictions on supported data types. The key takeaways are that @State decorated variables must be initialized with a value to prevent compilation errors, and the decorator does not support Function type variables, which will also cause compile-time failures. This reference material targets Cangjie developers implementing state management who need to understand syntax rules to avoid common compilation errors. Keywords: Cangjie, @State, decorator, initialization, compile error, Function type.

### 常见问题/
This directory provides technical guides and best practices for Cangjie developers, focusing on resolving common issues related to state management and UI responsiveness. It covers critical topics such as avoiding infinite re-render loops caused by modifying state variables in the build method, preventing memory leaks through proper callback lifecycle management, and troubleshooting arrow functions that fail to update the UI. Key concepts include `@State`, `@Publish`, `@Observed`, and the `aboutToDisappear` lifecycle. This resource is suitable for application developers using the Cangjie language who want to optimize performance and ensure stable UI behavior.

It covers how state changes are detected across various data types, how these changes trigger component updates, and the framework's behavior in optimizing rendering performance. Key topics include reactive rendering, state management, the `@State` decorator, and the distinction between observable and standard variable changes.
