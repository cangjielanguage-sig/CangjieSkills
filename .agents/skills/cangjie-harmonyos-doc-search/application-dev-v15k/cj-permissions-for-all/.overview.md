# cj-permissions-for-all

This directory serves as a comprehensive resource for managing permissions within the HarmonyOS and OpenHarmony ecosystems. It details the procedures for evaluating and applying for various permissions, distinguishing between those requiring explicit user authorization (`user_grant`) and those automatically granted by the system (`system_grant`). The content covers critical areas such as hardware access, data access, and system-level capabilities. It is designed for developers and system architects seeking to understand permission levels, ACL enablement, and the correct workflow for declaring permissions in configuration files to ensure application compliance and security. By providing clear guidelines on permission types, this documentation helps streamline the development process while maintaining strict security standards.

## Detailed Description

### 对所有应用开放/

This directory provides comprehensive documentation for permissions available to all HarmonyOS applications. It covers the procedures for evaluating and applying for permissions, distinguishing between those requiring explicit user authorization (`user_grant`) and those granted automatically by the system (`system_grant`). Key topics include hardware access, data access, and system-level capabilities. This section is suitable for developers seeking to understand permission levels, ACL enablement, and the correct workflow for declaring permissions in configuration files to ensure application compliance and security.

### 开放权限系统授权/

This directory provides a comprehensive guide to open permissions in the OpenHarmony and HarmonyOS ecosystems that utilize system authorization. It focuses on permissions automatically granted by the system upon installation, specifically those classified as `system_grant` and `normal` level, which do not require user interaction. The content covers the definition of these permissions, declaration procedures, and a detailed list of capabilities ranging from hardware interactions like Bluetooth and sensors to system features like background running. This resource is primarily suitable for HarmonyOS application developers who need to identify automatically available permissions and correctly declare them in application manifests to ensure compliance and functionality. It is also valuable for system architects designing applications that rely on standard hardware and system features without requiring complex user consent flows, thereby streamlining the development process for standard capabilities.
