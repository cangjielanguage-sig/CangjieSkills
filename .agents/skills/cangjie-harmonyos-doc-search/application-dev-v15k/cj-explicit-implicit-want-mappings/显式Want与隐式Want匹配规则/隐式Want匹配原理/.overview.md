# 隐式Want匹配原理

This directory provides a comprehensive technical reference for the principles and logic behind implicit Want matching within the HarmonyOS/OpenHarmony ecosystem. It covers the detailed rules for matching application component skills based on parameters such as action, entities, URI, type, and linkFeature. The documentation explains how the system validates these parameters against component configurations to ensure correct routing and intent handling. Suitable for application developers and system engineers configuring module.json5 files and implementing cross-component invocation, this collection ensures precise control over application capabilities and system behaviors.

### 隐式Want匹配原理.md 隐式Want匹配原理.md
This technical reference document outlines the principles and rules for implicit Want matching in HarmonyOS application development. It details parameter definitions via a table, explains the relationship between caller want parameters and target skills configuration, and describes specific matching logic for standard attributes and the linkFeature parameter. Key information includes that implicit matching requires abilityName to be empty and compares action, entities, uri, and type against component skills. The linkFeature parameter takes priority; if set, it must match first, followed by URI and type checks. This guide targets HarmonyOS developers configuring module.json5 files and implementing cross-component invocation.
