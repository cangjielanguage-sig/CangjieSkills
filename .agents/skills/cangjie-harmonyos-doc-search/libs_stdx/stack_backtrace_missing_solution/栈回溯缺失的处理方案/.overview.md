# 栈回溯缺失的处理方案

This directory focuses on resolving issues related to missing stack backtraces within the cj-fuzz framework. It covers technical solutions for capturing native signals from C code crashes and provides detailed case studies on debugging uncaught exceptions in the Cangjie runtime. Key topics include LLVM ASan linking strategies, signal handling, and the interaction between Cangjie stack traces and native stack traces involving `libcangjie-runtime.so`. This resource is suitable for developers and debugging engineers working with fuzzing tools, native code integration, and runtime stability analysis who need to debug signal-based failures effectively. The documents provide both the theoretical linking strategy and practical execution flow analysis to aid in comprehensive debugging. By understanding these mechanisms, users can better diagnose the root causes of crashes in complex hybrid environments involving both high-level language runtimes and native C libraries.

## Detailed Description

The following documents provide specific technical details and case studies regarding stack trace issues in the Cangjie fuzzing environment.

### 栈回溯缺失的处理方案_1.md
This technical guide provides a solution for missing stack backtraces in the cj-fuzz framework. It explains that while exceptions are captured, native signals from C code crashes or timeouts result in missing traces due to unimplemented sanitizer functions. The document details a linking strategy involving the LLVM ASan static library, -lgcc_s, and --eh-frame-hdr to enable __sanitizer_print_stack_trace. This ensures stack traces are generated for native crashes. The content is intended for developers working with fuzzing tools and native code integration, specifically those needing to debug signal-based failures.

### 栈回溯缺失的处理方案_2.md
This document functions as a technical log or case study analyzing a crash scenario within a Cangjie fuzzing environment, specifically addressing the handling of stack traces during exceptions. The content details an uncaught "TRAP!" exception occurring in `ci_fuzzer0.cj`, displaying the specific input data that triggered the failure. It provides a comprehensive execution flow, contrasting the high-level Cangjie stack trace with the underlying native stack trace involving `libcangjie-runtime.so` and libFuzzer internals. Key takeaways include the identification of the crash origin and the interaction between the fuzzer callback and the runtime exit handlers. This material is intended for runtime developers or debugging engineers investigating signal handling and crash reporting mechanisms in the Cangjie ecosystem.
