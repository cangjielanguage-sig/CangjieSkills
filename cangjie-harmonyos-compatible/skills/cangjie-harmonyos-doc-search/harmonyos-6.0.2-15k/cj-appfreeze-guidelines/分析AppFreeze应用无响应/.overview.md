### 分析AppFreeze应用无响应.md 分析AppFreeze应用无响应.md
This technical guide explains the mechanism of Application Not Responding (AppFreeze) and how to analyze the associated system logs to diagnose unresponsive applications. Main topics include the definition of AppFreeze, the system's detection mechanisms, and the generation of logs for developer analysis. Key information highlights that AppFreeze is triggered when user interactions fail to receive a response within a specific time limit and that this analysis is strictly applicable to the Stage model. Intended for developers, the document requires prior knowledge of Cangjie runtime behavior, C++ stack traces, and relevant subsystems to effectively interpret the logs.

### 应用无响应检测能力点.md 应用无响应检测能力点.md
This technical reference document outlines the mechanisms for detecting application non-responsive (ANR) faults to assist developers in debugging. It details three specific fault types: main thread execution stalling (THREAD_BLOCK_6S), user input response timeouts (APP_INPUT_BLOCK), and Ability lifecycle switching timeouts (LIFECYCLE_TIMEOUT). The text explains detection principles involving watchdog threads and liveness checks, noting specific timeout thresholds (e.g., 3s warning, 6s error) and varying durations for lifecycle states like Load and Foreground. It targets application developers seeking to understand the root causes of app freezes for better analysis and troubleshooting.

### 应用退出.md 应用退出.md
This document outlines the system policy for forcibly terminating applications to maintain system stability and recoverability when specific critical faults occur. It focuses on a categorized list of fault types that trigger an application exit, structured around a table defining specific error codes and their meanings. The key takeaway is that the system kills the app under three conditions: main thread freezing for over 6 seconds, failure to respond to user input, or timeouts during Ability lifecycle transitions. This reference material is intended for developers or system engineers debugging application stability issues or understanding system watchdog behavior.
