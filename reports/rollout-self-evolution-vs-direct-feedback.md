# `cangjie-skill-evolution` 使用场景与优势

## 定位

`cangjie-skill-evolution` 是面向 `cangjie-rollout-collector` 收集的 `Rollout Record` 的 Skill 治理入口。

它把问题先转成候选，再判断候选应进入主流程、经验库、验证资产，还是保持 `pending` / `rejected`。它的核心价值不是写入更多内容，而是控制什么值得写、写到哪里、凭什么写。`cangjie-skill-evolution` 会做跨 rollout 对比、目标 Skill 本体扫描和增量去重。

## 适用场景

适合在目标 Skill 已有雏形、开始积累 rollout，或进入维护期后使用：

- 初期定型：Skill 能跑通，但失败样本较多，需要从 rollout 中抽取稳定规则和失败规避。
- 维护收敛：Skill 已可用，但出现步骤冗余、规则重复、经验堆叠或执行犹豫。
- 腐化体检：Skill 越改越长、越改越特例化时，用 rollout 证据重新清理增长边界。

错别字、措辞优化、明确的小 bug 可以直接修；会改变主流程、行为边界或长期知识结构的问题，优先走自进化治理。

## 主要优势

### 1. 防腐化：让增长受控

直接反馈修复容易把每次问题都追加进 `SKILL.md`。短期看修得快，长期会导致主流程膨胀、规则互相覆盖、经验噪声增多，最终让 agent 读得更多、判断更慢、行为更脆。

自进化治理用候选池和状态门禁控制写入：

- `accepted` 才进入 consolidated patch。
- `pending` 保留启发，但不污染主流程。
- `rejected` 过滤低价值、不可复现、会误导的内容。
- `stale` / `conflict` 暴露锚点失效和规则冲突。
- `delta K` / `delta e` 分流稳定知识和上下文经验。

它也会通过 `corruption_type` 主动识别重复规则、冲突规则、过宽触发条件、孤立引用和经验污染。

去腐化不只靠新增规则，也包括 `delete`、`merge`、`narrow`、`relocate`、`repair_link`。

这让 Skill 可以持续变强，但不会在反复修补中变厚、变乱、变脆。

### 2. 防过拟合：不让单次案例变成通用规则

直接反馈常常只看到一个症状，容易把“一次任务有效的做法”误写成“所有任务都该这么做”。

自进化治理会先检查证据质量：是否有 ground truth，trace outcome 与 adjudicated outcome 是否冲突，问题是否跨 rollout 复现。

它还会判断候选是否只是一次性路径、样例数据、用户偏好或临时产物，以及是否能被 eval、validator 或最小复现验证。

证据不足时，候选默认保持 `pending`。这能避免 Skill 为了修一次案例牺牲通用能力。

### 3. 防经验污染：区分规则、经验和不沉淀内容

不是所有有用发现都应该进入主 Skill：

- `delta K` 是稳定知识，适合写成流程、规则、工具约束或验证要求。
- `delta e` 是上下文敏感经验，只能在通过 experience gate 后进入经验库。
- 证据不足、边界不清或一次性的内容，应保留在治理摘要中，而不是写入长期上下文。
- 已有经验如果无触发条件、无边界、无来源证据或低复用价值，也应被收窄、迁移或拒绝继续沉淀。

这种分流可以减少“经验越积越多、执行越来越犹豫”的慢性腐化。

### 4. 防止同类问题复发：把修复变成验证资产

自进化治理不会只停留在文字修补。对于反复出现的问题，它会推动补充 validator、schema 检查、eval case、lint gate、最小复现和写入后的验证流程。

因此它更适合处理“这类问题以后不能再出现”的场景。

## 与直接反馈修复的边界

直接反馈修复适合明确、局部、低风险的问题；Rollout 自进化治理适合重复、结构性、会影响长期行为的问题。

前者解决当前症状，后者维护长期能力。`cangjie-skill-evolution` 的优势在于用证据门禁防腐化，用候选治理防过拟合，用验证资产防止同类问题复发，让 Skill 在持续迭代中保持清晰、稳健和可维护。
