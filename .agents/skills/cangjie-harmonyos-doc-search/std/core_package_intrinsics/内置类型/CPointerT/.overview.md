# CPointerT

This directory serves as a comprehensive resource for the `CPointer` type within the Cangjie programming language, specifically designed to facilitate seamless interoperability with the C language. It covers the fundamental definition of C-style T* pointers, detailing platform-dependent size and alignment characteristics. The documentation highlights critical operational requirements, such as the mandatory use of unsafe contexts for pointer arithmetic, memory reading, writing, and type casting. Furthermore, it specifies that the generic type `T` must satisfy the `CType` constraint. This content is essential for developers engaged in low-level programming, Foreign Function Interface (FFI) tasks, or any development scenario requiring precise, direct memory manipulation capabilities and manual resource management.

## Detailed Description

### CPointerT.md CPointerT.md
This document provides API reference documentation for the CPointer type, which facilitates interoperability with the C language. It defines CPointer as a representation of a C-style T* pointer, specifying that the generic type T must satisfy the CType constraint. The text outlines critical behavioral requirements, noting that the type's size and alignment are platform-dependent. Key information includes the necessity of operating within an unsafe context for pointer arithmetic, memory reading and writing, and type casting between different CPointer types. This guide targets developers engaged in low-level programming or Foreign Function Interface (FFI) tasks who require direct memory manipulation capabilities.

### extendT_CPointerT/
This directory contains API documentation for extending the `CPointer` type within the Cangjie programming language. It focuses on low-level memory manipulation, providing essential interfaces for pointer arithmetic, resource management, and data access. Key topics include automatic memory release using `asResource`, null checks, reading and writing data, and pointer offsetting operations. These extensions are designed for developers working on C interoperability who need to manage raw pointers manually. Users must operate within unsafe contexts to ensure safety and prevent undefined behavior, and the generic type `T` must satisfy the `CType` constraint.
