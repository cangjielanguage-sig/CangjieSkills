# 隐式Want匹配原理

This directory provides a comprehensive technical reference for the principles and rules governing implicit Want matching in the system. It covers the logic used to match a caller's request parameters—specifically action, entities, URI, and type—against the skills configuration defined in a target application's module.json5. Key topics include URI component parsing, wildcard usage, linkFeature scenarios, and the specific behaviors for empty versus non-empty inputs. This documentation is suitable for developers configuring component capabilities, implementing application routing, or handling implicit intent invocations to ensure correct system behavior and application launching.

### uri匹配规则_3more.md uri匹配规则_3more.md

Intended for developers configuring component routing, this guide ensures correct application launching behavior.

### want参数的action匹配规则_2more.md want参数的action匹配规则_2more.md
This technical reference document defines the logic for matching the want parameter's action and entities against an application component's skills configuration. The content is divided into two main sections detailing the specific matching rules for action and entities respectively. Key takeaways include the distinct behaviors for empty versus non-empty inputs: an empty action generally results in a match failure unless the target has defined actions, whereas an empty entities input typically results in a match success. Successful matching for non-empty inputs requires the component's skills to strictly contain the provided values. This guide is intended for developers configuring component capabilities and handling implicit intent invocations, ensuring correct system routing behavior.

This technical reference document defines the matching logic for `want` parameters (uri and type) against installed application components' skills configuration. It details four scenarios based on input presence, explains "leftmost uri matching" for partial scheme/host/port alignment, and includes fallback logic for deriving MIME types from file extensions. Key takeaways include that a match succeeds if any element in the component's uris array satisfies the specific conditions for the provided uri and type combination. Intended for developers configuring component skills or implementing application launch requests, this guide ensures correct intent resolution within the system.

### 隐式Want匹配原理.md 隐式Want匹配原理.md
This technical reference document outlines the principles of implicit Want matching, defining how the system matches a caller's request with target application components. It details matching rules for parameters such as action, entities, uri, and type, explaining the comparison between the caller's want object and the target's skills configuration in module.json5. Key takeaways include the requirement that abilityName must be empty and the priority logic for the linkFeature parameter. If linkFeature is absent, all four main attributes must match for the component to appear in the application selector. This guide is intended for developers implementing implicit invocation capabilities.
