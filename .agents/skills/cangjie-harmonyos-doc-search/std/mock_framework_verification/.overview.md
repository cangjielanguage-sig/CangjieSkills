# mock_framework_verification

This directory serves as a comprehensive resource hub for the verification module of a Cangjie language mocking framework. It focuses specifically on the post-interaction validation phase of unit testing, providing the necessary tools and documentation to assert that mock or spy objects were called correctly. The content covers the `Verify` API, including cardinality checks, argument matching, and call ordering. It is designed for software developers and QA engineers who utilize the Cangjie language and require granular control over their test assertions. By mastering the resources in this directory, users can ensure robust interaction testing, moving beyond simple state checking to validate the complex behavioral logic and communication patterns within their applications.

## Detailed Description

### mock_框架验证_API/

This directory contains comprehensive documentation for the Verification API within a Cangjie language mocking framework. It acts as the definitive guide for the `Verify` class, offering technical references and utility method descriptions that are essential for advanced unit testing strategies. The primary focus is on validating interactions—ensuring that the system under test communicates correctly with its dependencies.

The documentation covers a wide array of features necessary for precise assertion control. This includes detailed explanations of cardinality functions, which allow developers to assert the exact number of invocations (such as `times(1)` or `atLeastOnce()`), and parameter matching mechanisms that support both exact values and wildcard matchers to verify complex argument structures. Furthermore, it addresses the complexities of ordered versus unordered verification, enabling tests to enforce strict sequences of events or simply check that calls occurred regardless of order.

A significant portion of the content is dedicated to error handling and debugging. When a verification fails, the framework provides specific feedback, and this documentation explains how to interpret those errors to quickly isolate issues. It also delineates the clear distinction between "expectations" (stubbing behavior) and "verification" (asserting behavior), a concept often confused by new users. By providing practical usage patterns, this resource helps developers write cleaner, more effective tests, ensuring that mock or spy objects behave exactly as required and that the logic flow within the application is rigorously validated.
