# Agent Skill 生成与进化

## 概述

把轨迹、rollout、工具调用、视觉观察、反馈和测试转化为可执行、可验证的单个 Skill 或技能库。每次先选择一个主路线，再按证据叠加增强模块：

- Trace2Skill：逐轨迹生成局部知识单元，再集中合并和裁决。
- SkillX：分层组织技能，治理拆分、合并、依赖、能力缺口和工具调用。
- XSkill：区分稳定任务流程与上下文经验，形成技能流和经验流。

需要选择路线或核对论文方法时，读取 [paper-synthesis.md](references/paper-synthesis.md)。

## 执行模式与边界

- 分析评审模式：读取目标 Skill、技能库和证据，输出路线决策、知识决策和具体修改建议，不修改文件。
- 实际修改模式：读取目标文件和证据，实际修改受影响 Skill、references、evals 或脚本，并完成验证。
- 只修复 lint 诊断时，使用 `cangjie-skill-lint-fix`。
- 具体领域 API 查询、普通代码修复、文档格式检查或鸿蒙构建排障，使用对应领域 Skill。

## 路线决策契约

开始提取知识前，必须输出并遵循以下决策：

```markdown
- 主路线：Trace2Skill / SkillX / XSkill。
- 增强模块：无，或列出附加使用的路线。
- 选择理由：证据形态、目标问题和预期收益。
- 目标形态：单 Skill / 技能库。
- 必需产物：本次必须写入或交付的技能流、经验流、拓扑变更和验证。
```

选择规则：

- 以成功/失败轨迹提炼稳定流程或防错规则为核心时，选择 Trace2Skill。
- 以多工具编排、技能分层、拆分合并、能力扩展或技能库治理为核心时，选择 SkillX。
- 以多路径 rollout、多模态观察或上下文敏感动作经验为核心时，选择 XSkill。
- 同时命中多个条件时，只选择一个主路线，其余作为增强模块；不得无差别运行全部机制。

## 候选知识单元契约

每个候选知识单元必须包含公共字段：

```markdown
- 知识单元：一句话说明要改变的 agent 行为或可复用能力。
- 单元类型：规则 / 技能 / 工具 / 经验。
- 触发条件：何时应用。
- 做法：可执行步骤、工具选择、参数约束或验证动作。
- 证据来源：轨迹、rollout、视觉观察、日志、反馈、测试或论文方法。
- 例外/边界：何时不应用或需要人工复核。
- 放置位置：SKILL.md / references / references/experiences.md / evals / 待验证清单。
- 验证方式：使用哪个 eval、命令、schema 检查或最小复现实验。
- 验证状态：accepted / pending / rejected。
- 预期行为变化：应用后可观察的行为变化。
```

按单元类型补充字段：

- 技能单元：`层级` 为规划层、功能层或原子层，并记录输入、输出、依赖和停止条件。
- 工具单元：记录工具 schema 或命令、参数约束、失败模式和实际验证结果。
- 经验单元：记录观察状态、动作、结果、适用上下文、适配规则、失效条件和提升条件。

只有 `accepted` 知识单元可以进入目标产物。`pending` 和 `rejected` 保留在决策清单或交付摘要中，不得表述为最终硬性规则。`accepted` 经验仍然保留在经验流中，只有满足提升条件并在多个场景重复验证后才能进入稳定主流程。

## 路线强制行为

### Trace2Skill

- 分别读取每条成功轨迹和失败轨迹，为每条轨迹独立生成局部知识单元。
- 从成功轨迹提取可迁移流程，从失败轨迹提取防错补丁。
- 局部知识单元生成完毕后再集中进行适用性检查、冲突裁决和合并，不能用后读证据覆盖前序有效结论。

### SkillX

- 对候选能力做语义聚类，并组织为规划层、功能层和原子层。
- 单 Skill 内可以保留三层结构；只有层级具备独立触发语句、维护边界或复用价值时才拆为独立 Skill。
- 对过宽 Skill 做拆分，对语义重复 Skill 做合并，对能力缺口做探索和扩展，并记录跨 Skill 输入输出及依赖。
- 工具知识必须通过 schema、`--help`、实际命令或等价可执行检查验证。

### XSkill

- 对多路径 rollout 做跨路径 critique，区分稳定任务流程和上下文敏感动作经验。
- 多模态任务必须保留截图、控件树、视觉状态或操作结果等观察来源。
- 稳定任务流程进入技能流；已验证但上下文敏感的动作建议进入 `references/experiences.md`，不得存入 `evals/`。
- 目标 `SKILL.md` 必须说明何时读取经验，以及如何依据当前上下文重写后应用；不得原样或无条件套用经验。

## 放置规则

- `SKILL.md`：高频、稳定、已接受的规则和技能流，以及 references 的加载条件。
- `references/`：按需加载的长案例、工具矩阵、技能依赖和上下文知识。
- `references/experiences.md`：已验证但上下文敏感的经验单元；每条经验使用完整经验字段。
- `evals/`：只验证发现性和行为，不保存规则或经验。
- 待验证清单：保存未通过验证的知识单元；通过后再决定进入技能流或经验流。

## 六阶段统一编排

### 1. 定义目标与选择路线

- 输入：用户请求、目标 Skill 或技能库路径、仓库上下文。
- 必须动作：确认执行模式；读取目标；写出能力边界、典型触发、非目标场景和可检查成功标准；使用路线决策契约选择主路线、增强模块和目标形态。
- 输出产物：任务画像、验收清单和路线决策。
- 完成条件：每项成功标准可由文件检查、命令、eval 或人工复核确认，且路线决策字段完整。
- 停止条件：目标无法发现或边界歧义会导致错误修改时，停止写入并请求必要信息。

### 2. 收集与标注证据

- 输入：成功/失败轨迹、多路径 rollout、工具 schema、视觉状态、用户反馈、测试、benchmark 或论文方法。
- 必须动作：读取可用证据；区分事实、分析和猜测；记录来源标识、适用场景和观察模态；Trace2Skill 主路线必须保持逐轨迹边界，XSkill 主路线必须保持逐 rollout 边界。
- 输出产物：可追溯证据清单。
- 完成条件：每条进入知识提取的事实可追溯到具体来源。
- 停止条件：没有可复核证据时，不生成最终知识单元；将建议标为 `pending` 并设计验证。

### 3. 按路线生成候选知识单元

- 输入：路线决策、证据清单和任务画像。
- 必须动作：使用完整知识单元契约；执行主路线强制行为；按需叠加增强模块；拆分包含多个触发条件或多个产物的知识单元。
- 输出产物：带类型、放置位置、验证方式和初始状态的候选知识单元。
- 完成条件：每个候选项字段完整，并说明预期行为变化。
- 停止条件：无法关联证据、缺少类型专属字段或无法设计验证的候选项不得进入 `accepted`。

### 4. 合并、拓扑决策与经验分流

- 输入：候选知识单元、当前 Skill 拓扑和目标形态。
- 必须动作：先检查场景适用性，再比较证据强度；语义合并重复项；记录冲突裁决；决定保留单 Skill 或拆分/合并技能库；将稳定知识分入技能流，将上下文敏感知识分入经验流。
- 输出产物：`accepted`、`pending`、`rejected` 决策清单，技能拓扑决策和经验分流决策。
- 完成条件：每个知识单元有唯一决策、理由、放置位置和验证方式；每个拓扑变更有独立触发或复用依据。
- 停止条件：无法裁决的冲突保持 `pending`；没有 `accepted` 知识单元时停止写入目标产物。

证据都适用于当前场景时，真实测试或运行轨迹优先于失败分析，失败分析优先于成功经验，成功经验优先于用户口头反馈，用户反馈优先于未验证论文迁移。

### 5. 写入技能流、经验流与验证资产

- 输入：知识决策、拓扑决策、经验分流决策和执行模式。
- 必须动作：分析评审模式输出具体建议；实际修改模式编辑所有受影响 Skill；为经验流创建或更新 `references/experiences.md`；为拆分后的 Skill 增加独立发现性和行为 eval；保持无关内容不变。
- 输出产物：修改建议，或已修改的 `SKILL.md`、`references/`、`evals/` 和必要脚本。
- 完成条件：主文件只包含稳定 `accepted` 知识；经验有加载和适配指引；evals 不保存经验；拆分 Skill 可独立发现。
- 停止条件：文件不可写、会破坏用户未提交更改或缺少实施工具时，停止相关写入并报告阻塞。

### 6. 验证所有受影响 Skill 并交付

- 输入：修改后的目标、验收清单、路线决策和验证方式。
- 必须动作：对所有受影响 Skill 运行 `skill-lint`；运行真实 agent eval；验证工具 schema/命令、跨 Skill 依赖、经验放置和原始证据未被修改；读取报告并检查失败原因。
- 输出产物：验证报告、通过结果、失败项、路线决策和知识决策摘要。
- 完成条件：要求的验证全部通过；摘要列出主路线、增强模块、目标形态、accepted、pending、拓扑变更、经验流、修改文件和报告路径。
- 停止条件：验证失败时不得声称交付完成；真实 agent 不可用时必须明确报告阻塞，不能用非真实 agent 验证代替。

## 验证命令

在仓库根目录执行，并为每个受影响 Skill 保存报告：

```powershell
$target = ".agents\skills\<skill-name>"
$skillName = Split-Path -Leaf (Resolve-Path -LiteralPath $target)
New-Item -ItemType Directory -Force -Path "reports\lint","reports\eval" | Out-Null

skill-lint --path $target --format json --out "reports\lint\$skillName.json"
skill-eval --path $target --mode all --runner agent-command --agent-command "python -m skill_cli.eval_tools.codex_exec_agent_adapter" --emit-trace --timeout 600 --progress --out "reports\eval\$skillName.json"
```

若 Codex 不可用，真实 agent eval 可以改用 `python -m skill_cli.eval_tools.claude_code_agent_adapter`。新增或修改 `evals/` 后，真实 agent eval 是最终验收要求。

## 最小检查清单

- 路线决策完整，且只选择一个主路线。
- 每个候选项使用完整知识单元契约，只有 `accepted` 项进入目标产物。
- Trace2Skill 已逐轨迹提取后集中合并；SkillX 已做分层和必要拓扑治理；XSkill 已分离技能流和经验流。
- `references/experiences.md` 只保存已验证的上下文经验，且主文件包含加载与适配指引。
- `evals/` 只验证行为，不保存经验。
- 所有受影响 Skill 的 lint 和真实 agent eval 已通过。
- 最终摘要列出路线、知识决策、拓扑变更、经验流、修改文件、验证结果和阻塞。
