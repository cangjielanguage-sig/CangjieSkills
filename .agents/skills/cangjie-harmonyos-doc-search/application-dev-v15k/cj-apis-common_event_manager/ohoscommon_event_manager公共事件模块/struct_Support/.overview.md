# struct_Support

This directory contains API reference documentation for the `Support` struct and related system event constants within the Cangjie programming language environment. It primarily focuses on defining static constant string identifiers for various system-level common events, including Bluetooth states, Wi-Fi operations, storage volume changes, user lifecycle management, and device power states. The documentation provides specific event values, required subscriber permissions, and API version compatibility. It is suitable for application and system developers who need to subscribe to, handle, or broadcast system-level notifications and hardware state changes within the OpenHarmony ecosystem.

### static_const_COMMON_EVENT_10more.md static_const_COMMON_EVENT_10more.md
This API reference document defines static constant strings for various system common events in the Cangjie programming language. The content primarily categorizes constants into Wi-Fi P2P operations (device state, group state, peer discovery), general Wi-Fi status updates (power state, RSSI, scan completion), and device power management (entering and exiting force sleep). Key information includes the specific event string values, required subscriber permissions like `ohos.permission.GET_WIFI_INFO` or `LOCATION`, and the starting API version for each constant. This documentation targets application developers who need to subscribe to and handle system-level broadcast events within their software.

### static_const_COMMON_EVENT_11more.md static_const_COMMON_EVENT_11more.md

This documentation targets application developers who need to subscribe to and handle system-level hardware state changes within the OpenHarmony ecosystem.

### static_const_COMMON_EVENT_12more.md static_const_COMMON_EVENT_12more.md
This API reference document defines static constant strings for user-related common events in the Cangjie programming language. It covers events regarding user lifecycle management, such as adding, removing, switching, and unlocking users, as well as account visibility updates. Key information includes specific event string values, required system-level permissions like `MANAGE_LOCAL_ACCOUNTS`, and system capabilities, with several events marked as reserved and currently unsupported. Targeted at system application developers using API version 12 or higher, this documentation facilitates the implementation of features that react to system-wide user state changes.

### static_const_COMMON_EVENT__5more.md static_const_COMMON_EVENT__5more.md
This API reference document defines static constant strings for specific system common events in the Cangjie programming language. It covers events related to device power states, specifically entering and exiting hibernation, user mode changes regarding minors mode activation and deactivation, and updates to managed browser policies. Key information includes the specific string values for each event, their classification under the `SystemCapability.Notification.CommonEvent` capability, and a critical requirement that subscribers must process the hibernate entry event within one second. The target audience is system developers building applications that need to react to these specific hardware or policy changes, requiring knowledge of event subscription mechanisms.

### static_const_COMMON_EVENT__9more.md static_const_COMMON_EVENT__9more.md
This API reference document defines static constant strings for Bluetooth-related common events in the Cangjie language. It categorizes events into host operations, such as state updates and scan mode changes, and remote device interactions, including ACL connections, battery level updates, and connection replies. A key takeaway is that most constants are marked as reserved events not yet supported, with only the host state update currently active. Subscribers generally require the `ohos.permission.USE_BLUETOOTH` permission. This documentation targets developers implementing Bluetooth features in system version 12, providing necessary event identifiers for subscribing to system-level Bluetooth status changes.
