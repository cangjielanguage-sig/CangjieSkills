It covers the mechanisms for application recovery, state management during freezes, and specific API references for the `appRecovery` module. Key topics include `APP_RECOVERY`, `onSaveState`, `errorManager`, and fault handling workflows for various crash types. It is suitable for application developers seeking to implement robust error handling, state restoration, and automatic recovery features to ensure application stability and data integrity.

## Detailed Description

### 应用恢复状态管理示意_3more.md
This technical guide details the mechanisms for application recovery, state management, and fault handling within the application framework. It covers application recovery state triggers, specific state saving procedures during AppFreeze scenarios, and the comprehensive framework fault management workflow. Key concepts include the APP_RECOVERY startup reason, non-main thread callbacks for onSaveState during freezes, and the roles of errorManager, appRecovery, and faultLogger. Developers are advised to avoid native libraries in freeze callbacks. This is intended for application developers seeking to implement robust error handling and recovery features.

Keywords: Application Recovery, State Management, AppFreeze, Fault Management, errorManager, onSaveState, UIAbility, faultLogger

### 应用故障管理接口支持场景.md
This document outlines the support scenarios for application fault management interfaces, detailing how different fault types are handled by the underlying recovery framework. It covers definitions of common faults including Cangjie program crashes, application freezes, and C++ crashes. A key section provides a comparison table of supported capabilities such as fault listening, state saving, automatic restart, and log query for each fault type. Key takeaways indicate that Cangjie crashes support all features, app freezes support most except listening, and C++ crashes only support log queries. The document advises developers to implement timed or background state saving for app freeze scenarios to maximize data protection. This reference guide targets application developers utilizing the fault management framework.

### 接口说明_2more.md
This document serves as an API reference for the appRecovery module, detailing interfaces for application fault recovery and state management. It covers four primary functions: enabling recovery, saving application state, restarting the process, and setting the target Ability for recovery. Key information includes the requirement to call enableAppRecovery during initialization, such as in AbilityStage OnCreate, and the behavior of restartApp which kills the process and relaunches the app with restored state via want parameters. Notably, restartApp enforces a one-minute interval between calls. This guide targets developers seeking to implement robust error handling and recovery mechanisms in their applications.
