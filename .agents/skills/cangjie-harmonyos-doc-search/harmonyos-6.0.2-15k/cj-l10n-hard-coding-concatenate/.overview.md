# cj-l10n-hard-coding-concatenate

This directory focuses on essential software localization (l10n) guidelines, specifically targeting the elimination of hard-coded strings and string concatenation within the codebase. It addresses the complexities of adapting software for global markets by explaining the risks associated with embedding text directly into logic. The content covers the semantic problems caused by splicing text fragments, which often leads to broken grammar in translated languages. By enforcing the use of resource files and placeholders, this guide ensures that applications remain flexible and grammatically correct across different locales. It is an indispensable resource for developers and localization engineers looking to optimize their internationalization (i18n) strategies, reduce technical debt, and minimize the burden on translation teams while ensuring semantic integrity.

## Detailed Description

### cj-l10n-hard-coding-concatenate.md cj-l10n-hard-coding-concatenate.md

This comprehensive guide instructs developers on the critical importance of avoiding hard-coding and string concatenation to facilitate effective software localization. It begins by detailing various usage scenarios that highlight the significant risks of embedding data directly in code. By doing so, it exposes how such practices create rigid codebases that are difficult to adapt for different languages. The text also delves into the semantic issues caused by splicing text fragments, explaining how this method often results in nonsensical or grammatically incorrect sentences when translated.

To mitigate these issues, the document outlines specific architectural constraints that must be followed during development. It mandates that all translatable strings be extracted from the source code and moved into external resource files, which are then loaded via well-defined interfaces. This separation of concerns is vital for maintainability. Furthermore, the guide advises using placeholders for variable parts of sentences. This technique allows translators to rearrange sentence components according to the grammatical rules of their target language without altering the underlying code logic. This resource is primarily intended for developers and localization engineers aiming to reduce translation errors and streamline their workflow.
