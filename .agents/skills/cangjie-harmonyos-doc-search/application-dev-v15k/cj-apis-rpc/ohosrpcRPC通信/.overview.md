## Detailed Description

### class_DeathRecipient.md
This document provides API reference documentation for the Cangjie `DeathRecipient` class, which enables subscription to death notifications of remote objects in Inter-Process Communication (IPC). The content covers the abstract class definition and the `onRemoteDied` callback method, detailing system capabilities and version requirements. Key takeaways include understanding that remote object death encompasses process termination, device shutdown, or network disconnection, and that users must override `onRemoteDied` to handle these events. Targeted at Cangjie developers implementing IPC mechanisms, this guide requires knowledge of object-oriented programming and distributed systems.

### class_IPCSkeleton.md
This document serves as API reference documentation for the Cangjie language's `IPCSkeleton` class, designed to manage Inter-Process Communication (IPC) context and system capabilities. The content details static methods for retrieving critical process information, such as calling UID, PID, TokenId, and local or remote device IDs. It also includes functionality to flush command buffers and verify if calls originate from the same device. Key takeaways involve understanding that methods like `getCallingPid` return local process data when outside an IPC context. This reference targets system developers implementing secure IPC mechanisms.

### enum_TypeCode.md
This API reference document defines the `TypeCode` enum in the Cangjie language, designed to distinguish specific `TypedArray` types during Inter-Process Communication (IPC) data transmission. The documentation lists enum members representing various numeric array types, such as `INT8_ARRAY`, `UINT32_ARRAY`, and `FLOAT64_ARRAY`, alongside inherited methods for equality comparison and string conversion. Key information includes the system capability requirement (`SystemCapability.Communication.IPC.Core`) and the starting version (19). This guide is intended for developers working on IPC functionality who need to handle typed data serialization and identification.

### interface_Parcelable.md
This document serves as API reference for the Cangjie `Parcelable` interface, enabling object serialization for Inter-Process Communication (IPC). It covers the interface definition, system capabilities, and two primary methods: `marshalling` to write objects into a `MessageSequence` and `unmarshalling` to reconstruct them. Key details include parameter descriptions, return values indicating success or failure, and a code example demonstrating custom implementation. The content is intended for developers building IPC features who need to transfer complex data types across processes.

### ohosrpcRPC通信_4more.md

### struct_RequestResult.md
This API reference document defines the Cangjie struct `RequestResult`, which encapsulates the response results for Inter-Process Communication (IPC) requests. The documentation details the struct's constructor and four read-only properties: `errCode`, `code`, `data`, and `reply`. Key information includes that the struct stores an error code, a message code, and two `MessageSequence` objects representing data sent to the peer process and data returned from it. This resource is intended for developers implementing IPC functionality requiring system capability `SystemCapability.Communication.IPC.Core` starting from version 19.
