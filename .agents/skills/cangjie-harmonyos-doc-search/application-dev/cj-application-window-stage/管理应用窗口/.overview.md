# 管理应用窗口

This directory provides comprehensive technical guides for managing application windows in HarmonyOS using the Stage model and Cangjie language. It covers essential window management tasks, including configuring main windows, creating immersive experiences by hiding system bars, and implementing floating or sub-windows. Key topics include window lifecycle, property configuration, and UI integration. Suitable for HarmonyOS developers and UI engineers looking to build dynamic, multi-window interfaces and optimize user experiences through advanced window behaviors.

## Detailed Description

### 体验窗口沉浸式能力.md 体验窗口沉浸式能力.md
This guide explains how to implement immersive window capabilities to hide or customize system bars like the status and navigation bars, enhancing user experience for scenarios like video playback. The document outlines a three-step development process: obtaining the main window, applying immersive effects via two methods (hiding bars or setting full-screen layout with transparent properties), and loading content. It provides a Cangjie code example demonstrating key APIs such as setWindowSystemBarEnabled, setWindowLayoutFullScreen, and setWindowSystemBarProperties. Targeting HarmonyOS developers using API version 10, it notes that configurations are window-level and offers workarounds for page-level requirements.

### 管理应用窗口_4more.md 管理应用窗口_4more.md
This document serves as a technical guide for managing application windows in the Stage model. It covers core concepts like immersive window capabilities and global floating windows, alongside typical development scenarios. The content details key APIs for creating, showing, and configuring main and sub-windows, including methods for setting full-screen layouts, system bar visibility, and window properties. It is intended for developers seeking to implement advanced window behaviors, such as background floating windows and immersive user experiences, providing the necessary interface definitions and usage context.

### 设置应用主窗口.md 设置应用主窗口.md
This tutorial guides developers on configuring the application main window within the Stage model using the Cangjie language. It covers obtaining the main window via WindowStage, setting window properties like background color or touchability, and loading target pages. The process occurs in the onWindowStageCreate callback of UIAbility. Key APIs include getMainWindow, setWindowTouchable, and loadContent. It also notes that some properties can be pre-configured in module.json5. This is intended for application developers working with HarmonyOS ArkUI and Cangjie who need to manage window lifecycle and UI behavior.

### 设置悬浮窗.md 设置悬浮窗.md
This tutorial guides developers on creating and managing floating windows that remain visible in the foreground. It covers the prerequisites, specifically the `ohos.permission.SYSTEM_FLOAT_WINDOW` permission, and outlines a four-step development process: creating the window, configuring properties like size and position, displaying content, and destroying the window. The document includes a Cangjie code example demonstrating key APIs such as `createWindow`, `showWindow`, and `destroyWindow`. Intended for application developers, this guide provides the necessary steps to implement persistent overlay windows within their applications.

### 设置应用子窗口/
This directory serves as a comprehensive technical resource for HarmonyOS developers focusing on the implementation and configuration of application sub-windows using the Cangjie language. It provides a structured approach to window management, covering the full lifecycle from creation and property adjustment to display and destruction. The content highlights specific technical procedures, such as setting dimensions before displaying windows and integrating sub-windows with UI components like AppStorage. Furthermore, it offers critical guidance on the limitations of sub-windows in various display modes, such as split-screen or freeform windows, and suggests alternative solutions like the overlay attribute for better performance. This resource is ideal for developers and UI engineers who need to create dynamic, multi-window interfaces while adhering to platform constraints and optimizing user experience in HarmonyOS applications.
