# 应用扩展布局全屏显示不隐藏避让区

This directory provides comprehensive resources for implementing immersive full-screen layouts in HarmonyOS applications. The core objective is to enable UI elements to extend into system areas—such as the status bar and navigation bar—without hiding these critical system components. By retrieving avoidance area dimensions and dynamically adjusting padding, developers can prevent content overlap. The documentation covers key APIs like `setWindowLayoutFullScreen`, `getWindowAvoidArea`, and `@StorageProp`. This collection is suitable for HarmonyOS developers using either Cangjie or ArkTS who need to build adaptive interfaces that handle complex screen states, including rotation and multi-window scenarios, ensuring a seamless user experience.

## Detailed Description

The files in this section offer language-specific implementation strategies for achieving full-screen layouts that respect system avoidance areas.

### 应用扩展布局全屏显示不隐藏避让区_1.md 应用扩展布局全屏显示不隐藏避让区_1.md
This guide explains how to implement an immersive full-screen layout in Cangjie applications where UI elements extend into system bars without hiding them. It covers enabling full-screen mode via setWindowLayoutFullScreen, retrieving avoidance area dimensions using getWindowAvoidArea, and registering dynamic listeners for layout changes. Key takeaways include the necessity of adjusting UI padding based on status bar and navigation indicator heights to prevent overlap, and handling scenarios where avoidance areas might be zero. This tutorial targets HarmonyOS developers using the Cangjie language who need to adapt their UI for various screen states like rotation or multi-window modes.

This technical tutorial demonstrates how to implement a fullscreen layout in ArkUI that respects system avoidance areas without hiding the status bar and navigation bar. The document provides an ArkTS code example illustrating the use of `@StorageProp` to dynamically retrieve top and bottom system bar heights. It explains how to apply these values as padding to the root container, ensuring UI elements do not overlap with system controls. Additionally, it discusses optional configurations for status bar text and background colors. The content includes visual comparisons showing correct layout avoidance versus overlapping issues, targeting HarmonyOS developers seeking to create immersive yet accessible user interfaces.
