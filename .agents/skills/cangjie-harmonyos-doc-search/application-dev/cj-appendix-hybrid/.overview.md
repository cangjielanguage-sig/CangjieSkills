# cj-appendix-hybrid

This directory serves as a comprehensive technical resource for implementing hybrid development strategies within the OpenHarmony ecosystem. It specifically addresses the integration of Cangjie UI components into existing ArkTS applications, enabling developers to combine the strengths of both languages in a single project. The content covers the essential background of hybrid scenarios, provides a comparative analysis between hybrid and pure Cangjie approaches, and outlines critical project configuration steps required to set up the environment. It highlights specific implementation details such as the use of `@HybridComponentEntry` and `CJHybridComponent`, while also clarifying constraints regarding lifecycle management, routing, and the lack of support for cross-language state synchronization. This guide is best suited for OpenHarmony developers who are already proficient in ArkTS and are looking to extend their applications by incorporating Cangjie for specialized logic or UI rendering, ensuring a smooth interoperability experience. By following this guide, developers can effectively bridge the gap between ArkTS and Cangjie, optimizing their development workflow.

## Detailed Description

### cj-appendix-hybrid.md cj-appendix-hybrid.md
This document acts as an essential guide for developers looking to perform hybrid development by embedding Cangjie UI components directly into ArkTS applications. It begins by establishing the background and use cases for hybrid scenarios, providing a clear rationale for mixing languages within the OpenHarmony framework. The guide offers a detailed comparison between hybrid development and pure Cangjie development, explicitly pointing out limitations related to component lifecycles and routing systems that developers must navigate to ensure stability. Furthermore, it provides step-by-step instructions for project configuration to enable interoperability. Technical implementation is demonstrated through the use of the `@HybridComponentEntry` decorator in Cangjie and the `CJHybridComponent` in ArkTS, facilitating the embedding process. Crucially, the document notes that cross-language state synchronization is not supported, setting clear expectations for data flow and state management. The target audience includes OpenHarmony developers with a strong grasp of ArkTS who wish to leverage Cangjie for specific application logic or UI components.
