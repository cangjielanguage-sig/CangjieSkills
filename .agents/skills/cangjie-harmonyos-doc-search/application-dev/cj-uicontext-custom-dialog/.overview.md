# cj-uicontext-custom-dialog

This directory serves as a specialized technical resource for implementing global custom dialogs within Cangjie HarmonyOS applications, specifically leveraging the `openCustomDialog` API. It is designed to address and resolve the architectural limitations associated with the traditional `CustomDialogController`, particularly its inability to support dynamic content creation and refreshing without heavy dependencies on specific UI components. The documentation covers a range of advanced topics, including parameter input strategies using `CustomDialogOptions` and Lambda expressions, comprehensive dialog lifecycle management, and ID-based control for precise instance handling. This resource is primarily intended for ArkUI developers and system architects who aim to construct flexible, decoupled, and highly maintainable popup interfaces by utilizing `getUIContext().getPromptAction()`.

## Detailed Description

### 不依赖UI组件的全局自定义弹出框openCustomDialog/

This subdirectory offers a deep dive into the mechanics of implementing global custom dialogs in Cangjie HarmonyOS applications via the `openCustomDialog` API. It is structured to help developers overcome the rigidity of `CustomDialogController` by introducing methods for dynamic content generation and real-time updates.

The content focuses on three main pillars:
1.  **Parameter Input Methods:** It provides comparative analysis and examples for passing data using `CustomDialogOptions` versus Lambda expressions, helping developers choose the right approach for their specific use case.
2.  **Lifecycle Management:** It outlines best practices for managing the existence of dialogs, ensuring that they are created, displayed, and destroyed in a manner that preserves application performance and stability.
3.  **ID-based Control:** It explains how to use unique identifiers to manage specific dialog instances, allowing for granular control over the UI layer.

This collection is an invaluable tool for ArkUI developers seeking to master the creation of decoupled popup interfaces using `getUIContext().getPromptAction()`.
