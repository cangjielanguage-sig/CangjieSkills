# cj-huks-key-import-overview

This directory serves as a comprehensive technical resource dedicated to the processes and specifications for importing keys into the HarmonyOS Universal KeyStore (HUKS). As a critical component of the HarmonyOS security architecture, HUKS ensures that sensitive cryptographic material is managed securely throughout its lifecycle. This documentation specifically addresses the key import phase, detailing the mechanisms required for both plaintext and encrypted key ingestion. It provides an in-depth analysis of the supported cryptographic algorithms, including AES, RSA, ECC, ECDH, and X25519, as well as the necessary data formats such as X.509 and Length-Data. Crucially, the content differentiates between the requirements for standard devices and lightweight devices, outlining specific security constraints and API level dependencies. This distinction ensures that developers can optimize security implementations regardless of hardware capabilities. This directory is an essential guide for security developers, system integrators, and OEMs aiming to build secure applications or facilitate secure key transfer and storage solutions on HarmonyOS devices.

## Detailed Description

### 密钥导入介绍及算法规格/

This subdirectory contains the definitive technical documentation for importing keys into the HarmonyOS Universal KeyStore (HUKS). It is structured to assist developers in navigating the complex requirements of secure key management. The documentation covers the fundamental mechanisms for key import, supporting both plaintext import for less sensitive scenarios and encrypted import for high-security requirements. This dual approach ensures flexibility while maintaining a high baseline of security.

A major focus of the content is the specification of cryptographic algorithms. It provides detailed parameters for AES, RSA, ECC, ECDH, and X25519, ensuring that developers implement keys that are compliant with industry standards and HarmonyOS security policies. Furthermore, it specifies the data formats required for successful import, such as X.509 for certificate-based keys and Length-Data for raw key material, which are essential for ensuring data integrity during the transfer process.

Recognizing the diverse ecosystem of HarmonyOS devices, the documentation draws a clear line between standard and lightweight device specifications. For standard devices, it outlines full-featured security constraints, while for lightweight devices—often used in IoT scenarios—it provides tailored specifications that account for limited resources. It also details API level dependencies, helping developers ensure backward compatibility and forward readiness. This makes the resource invaluable for OEMs and security developers who need to implement precise, hardware-aware key storage solutions. By following these specifications, users can guarantee that their key import processes are robust, secure, and fully aligned with the HarmonyOS security framework.
