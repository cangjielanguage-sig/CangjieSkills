# unittest_mock_package_enums

This directory contains the essential API reference documentation for the enumeration types utilized within the Cangjie unit testing mock framework. It is specifically designed to assist developers in understanding and implementing the core configuration options available for mock objects. The content focuses on three primary enumerations: `Exhaustiveness`, `MockSessionKind`, and `StubMode`. These elements are crucial for defining how verification processes are handled, how stubbing sessions are managed, and how mock objects return values or handle properties. By mastering these enumerations, developers can ensure their unit tests are both flexible and rigorous, adapting to various testing scenarios. This documentation is highly suitable for software developers and testers working in the Cangjie language environment who require granular control over their testing infrastructure to validate complex logic and interactions within their applications. It provides the necessary definitions to leverage the full power of the mocking framework effectively.

## Detailed Description

### unittest_mock_package_enums.md unittest_mock_package_enums.md
This API reference document serves as the definitive guide for the three enumeration types used within the Cangjie unit testing mock framework to configure verification and stubbing behaviors. It provides an in-depth look at `Exhaustiveness`, `MockSessionKind`, and `StubMode`, carefully explaining their specific variants and distinct functional roles.

Key information detailed in this document includes how the `Exhaustiveness` enum controls the strictness of `Verify.unordered` checks. It allows developers to choose between requiring that all calls be explicitly defined or allowing for more lenient, partial verification. Additionally, the document covers `MockSessionKind`, which dictates the permissible stub types within a session, and `StubMode`, which determines if mock objects return default values or treat properties as synthetic fields. This guide is targeted at developers implementing unit tests who need precise control over mock object interactions and verification logic. By utilizing these enums, developers can fine-tune the framework's behavior to match specific testing requirements, ensuring that mocks behave exactly as expected during the verification of complex software components.
