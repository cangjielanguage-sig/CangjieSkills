# unittest_mock_package_enums

This directory serves as a comprehensive API reference for enumeration types utilized within a unit testing mock framework specifically developed for the Cangjie programming language. It focuses on the critical configuration aspects of verification and stubbing behaviors required for robust testing. The documentation covers three primary enumeration types: `Exhaustiveness`, which dictates the strictness of call verification; `MockSessionKind`, which manages session-level constraints; and `StubMode`, which controls how mocks return values and handle field mutability. This resource is essential for software developers and QA engineers who are writing unit tests in Cangjie and need granular control over mock object interactions to ensure their test logic is both precise and reliable.

### unittest_mock_package_enums.md unittest_mock_package_enums.md

This API reference document is a crucial resource for understanding the three core enumeration types used within the unit testing mock framework for the Cangjie language. Its primary purpose is to guide developers in configuring verification and stubbing behaviors effectively.

The documentation provides an in-depth look at the `Exhaustiveness` enum, which is essential for defining verification modes. It clarifies the distinction between `Exhaustive` mode, which enforces strict checking of function calls, and `Partial` mode, which allows for more lenient verification. Additionally, the text covers the `MockSessionKind` enum, which is used to apply session constraints. This enum restricts stub usage to three specific levels: `Forbidden`, `Stateless`, and `Verifiable`, giving developers control over the scope of stubbing.

Lastly, the `StubMode` enum is explained in detail, outlining how it determines the behavior of mocks. It specifies whether mocks should return default values or if they should treat fields as synthetic mutable fields. This document is specifically designed for developers writing unit tests who need to maintain precise control over mock object behavior and verification logic to ensure high-quality software testing.
