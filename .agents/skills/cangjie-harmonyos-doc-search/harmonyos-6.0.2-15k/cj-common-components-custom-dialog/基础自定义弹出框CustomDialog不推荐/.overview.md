# 基础自定义弹出框CustomDialog不推荐

This directory serves as a technical resource for implementing custom pop-up dialogs using the `CustomDialog` component within the ArkUI framework, specifically targeting the Cangjie language. Although the usage of `CustomDialog` is marked as "not recommended" in favor of the Navigation component, this collection provides detailed instructions for developers who need to build or maintain custom interactive overlays. The content covers fundamental concepts such as the `@CustomDialog` decorator, `CustomDialogController` management, and user interaction handling. It also explores advanced topics including modal properties, complex styling with borders and shadows, and the intricacies of nested dialog lifecycles. This guide is suitable for HarmonyOS developers looking to master overlay mechanics and state management in Cangjie applications.

### 基础自定义弹出框CustomDialog不推荐_3more.md 基础自定义弹出框CustomDialog不推荐_3more.md
This guide provides instructions for implementing custom pop-up dialogs using the CustomDialog component in ArkUI, although it is marked as not recommended. It covers creating dialogs with the @CustomDialog decorator, managing display via CustomDialogController, and implementing user interactions like button clicks. The document highlights that dialogs are non-page-level by default and require manual closing during route jumps, suggesting the Navigation component as an alternative. It also explains the isModal property for modal and non-modal behaviors. This tutorial targets ArkUI developers using the Cangjie language who need to build custom interactive overlays.

### 弹出框的样式_2more.md 弹出框的样式_2more.md
This tutorial guide explains how to style custom dialogs and manage nested dialog interactions in the Cangjie UI framework. The document covers two main topics: configuring dialog appearance using parameters like width, borders, and shadows within CustomDialogControllerOptions, and implementing nested custom dialogs. Key takeaways include the recommendation to define the second dialog in the parent component rather than inside the first dialog. This approach prevents lifecycle issues where closing the parent dialog destroys the child's ability to create new components due to state management dependencies. Intended for Cangjie developers, this guide provides practical code examples for building complex UI interactions in HarmonyOS applications.
