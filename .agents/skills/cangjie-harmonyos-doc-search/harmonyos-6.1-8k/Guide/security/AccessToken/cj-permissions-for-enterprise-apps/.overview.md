# cj-permissions-for-enterprise-apps

This directory serves as a specialized technical resource dedicated to the complex landscape of sensitive permissions within the HarmonyOS and OpenHarmony operating systems, specifically focusing on enterprise-class applications. It provides a detailed examination of the permissions required for advanced features such as security auditing, process management, eSIM configuration, file control, and Wi-Fi network management. The documentation meticulously outlines permission levels (e.g., `system_basic`), authorization modes (e.g., `system_grant`), and the specific changes in permission availability across API versions 12 through 18. This resource is indispensable for developers building applications for customized enterprise devices, offering the necessary guidance to correctly declare and utilize system-level permissions while adhering to security and functional requirements.

## Detailed Description

### 企业类应用可用权限/

This subdirectory functions as a comprehensive reference guide for the sensitive permissions that enterprise applications—including both Mobile Device Management (MDM) solutions and standard enterprise software—can request within the HarmonyOS and OpenHarmony environments. The documentation is designed to address the unique needs of enterprise deployments, where access to core system functions is often required for device management and security enforcement.

The content covers a wide range of critical functional areas. Developers will find information regarding permissions for security auditing, which is essential for monitoring compliance; process management for maintaining system stability; and eSIM settings for connectivity management. Additionally, it includes permissions for file control, Wi-Fi configuration, and broader enterprise network management tasks.

Beyond listing permissions, the documents provide granular technical specifications. They explain the hierarchy of permission levels, such as `system_basic`, and the appropriate authorization methods, notably `system_grant`. Crucially, the documentation tracks the evolution of these permissions across different API versions, specifically from API 12 to API 18, highlighting any changes in scope or availability. This information is vital for developers working on customized enterprise devices, as it ensures they can correctly declare and use the permissions necessary to interact with the system's core functionalities without violating security protocols.
