# 接口说明

This directory provides comprehensive technical documentation for application fault management and recovery interfaces. It focuses on the `appRecovery` module, detailing how to handle application crashes, freezes, and state restoration. Key topics include fault listening mechanisms, state saving logic (onSaveState), auto-restart capabilities, and specific API usage for enabling recovery and restarting applications. The documentation also distinguishes support capabilities between different fault types, such as Cangjie and C++ crashes. It is designed for application developers and system engineers seeking to implement robust error handling and state persistence to ensure system stability.

## Detailed Description

### 应用恢复状态管理示意_3more.md
This technical guide details the application recovery state management and fault handling mechanisms. It covers the logic for triggering APP_RECOVERY, specific procedures for saving state during AppFreeze scenarios, and the overall framework fault management workflow. Key information includes the non-main thread execution of onSaveState during AppFreeze, restrictions on using native libraries or thread-local objects in that context, and the integration of errorManager, appRecovery, and faultLogger. The document targets application developers aiming to implement robust error recovery and state persistence. Keywords: application recovery, state management, AppFreeze, fault handling, onSaveState, errorManager, appRecovery, faultLogger.

### 应用故障管理接口支持场景.md
This document outlines the support scenarios for application fault management interfaces, detailing how the underlying recovery framework handles specific fault types without requiring upper-layer intervention. The main content defines common faults like Cangjie program crashes, app freezes, and C++ crashes, providing a comparative table of supported capabilities including fault listening, state saving, auto-restart, and log querying. Key takeaways indicate that Cangjie crashes support full management features, whereas C++ crashes are limited to log querying. The document advises developers to implement timed or background state saving strategies for app freeze scenarios to maximize data protection. This technical reference targets application developers utilizing the Performance Analysis Kit for system stability.

### 接口说明_2more.md
This document serves as an API reference guide for the appRecovery module, detailing interfaces for application fault recovery and state restoration. It covers a function table and detailed explanations for four key interfaces: enableAppRecovery, saveAppState, restartApp, and setRestartWant. Key information includes that enableAppRecovery must be called during initialization, while restartApp kills the process and relaunches the specified Ability with saved state data passed via wantParam. Notably, restartApp has a one-minute interval limit and does not throw exceptions. This technical guide targets developers building resilient applications who need to implement crash recovery mechanisms.
