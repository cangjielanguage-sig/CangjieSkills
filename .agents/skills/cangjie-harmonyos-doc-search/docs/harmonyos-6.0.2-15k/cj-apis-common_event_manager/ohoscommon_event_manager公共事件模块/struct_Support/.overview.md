# struct_Support

This directory contains API reference documentation for the `Support` struct within the Cangjie programming language. It primarily defines static constant strings used for subscribing to and handling system-wide common events. The content covers a broad range of hardware and system state changes, including Wi-Fi connectivity, Bluetooth states, power management (sleep/hibernate), user account lifecycle, and storage volume events. These resources are essential for developers building system-level applications that require real-time monitoring of device status and inter-process communication capabilities.

## Detailed Description

### static_const_COMMON_EVENT_10more.md static_const_COMMON_EVENT_10more.md
This API reference document defines static constant strings for various system common events, primarily focusing on Wi-Fi connectivity and device power states. The content covers Wi-Fi P2P events (device, group, and peer discovery states), general Wi-Fi status (power, RSSI, scanning), and system sleep mode transitions (entering/exiting force sleep). Key information includes the specific string values, functional descriptions, required subscriber permissions like GET_WIFI_INFO or LOCATION, and the minimum API version, mostly version 12. This documentation is intended for developers using the Cangjie language who need to subscribe to and handle system-level broadcast events within their applications.

### static_const_COMMON_EVENT_11more.md static_const_COMMON_EVENT_11more.md
This API reference document defines static constants for common system events in the Cangjie language, specifically targeting API version 12. The content covers storage volume events, such as mounting, unmounting, and bad removal, alongside Wi-Fi events including hotspot state, P2P connections, and client join or leave actions. Key details include the specific string values for each event, required subscriber permissions like ohos.permission.STORAGE_MANAGER or ohos.permission.GET_WIFI_INFO, and associated system capabilities. This documentation is intended for developers building system-level applications that need to monitor and react to hardware state changes in external storage and wireless networks.

### static_const_COMMON_EVENT_12more.md static_const_COMMON_EVENT_12more.md
This API reference document defines static constant strings for user and account-related common events in the Cangjie programming language. It details specific event actions such as user addition, removal, switching, unlocking, and information updates, while also noting several reserved lifecycle events that are currently unsupported. Key information includes the required system-level permissions for subscribers, such as MANAGE_LOCAL_ACCOUNTS, and the version 12 availability. This documentation targets system application developers who need to monitor and respond to changes in user states and account visibility.

### static_const_COMMON_EVENT__5more.md static_const_COMMON_EVENT__5more.md
This API reference document defines specific string constants for system common events related to device power states, user modes, and policy changes in a Cangjie development environment. It details five static constants: COMMON_EVENT_ENTER_HIBERNATE, COMMON_EVENT_EXIT_HIBERNATE, COMMON_EVENT_MINORSMODE_ON, COMMON_EVENT_MINORSMODE_OFF, and COMMON_EVENT_MANAGED_BROWSER_POLICY_CHANGED. Key information includes that these events are published by the notification service, with the hibernation entry event requiring subscriber processing within one second. All constants utilize the SystemCapability.Notification.CommonEvent capability and are available from version 20. This documentation targets application developers who need to subscribe to and handle system-level state changes like sleep mode, parental controls, or browser policy updates.

### static_const_COMMON_EVENT__9more.md static_const_COMMON_EVENT__9more.md
This document serves as an API reference defining static constant strings for Bluetooth-related common events in the Cangjie language. It covers host events such as enabling requests and state updates, alongside remote device events including ACL connections, battery levels, and connection replies. Key information indicates that most events are currently reserved and unsupported, with the exception of the host state update event. All constants are of type String and generally require the ohos.permission.USE_BLUETOOTH permission. This reference is intended for system developers or application engineers working on Bluetooth functionality, specifically targeting API version 12.
