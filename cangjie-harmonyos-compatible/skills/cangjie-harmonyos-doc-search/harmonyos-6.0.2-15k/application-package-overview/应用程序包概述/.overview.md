# 应用程序包概述

This directory provides a comprehensive technical overview of HarmonyOS application packages, focusing on the Stage model's design mechanisms and structural organization. It covers the fundamental definitions of applications and packages, the multi-module design mechanism for enhanced modularity, and strategies for device adaptation. Key concepts include the classification of Module types, distinguishing between Ability modules that generate HAP files for installation and Library modules that create HAR packages for resource sharing. The content also addresses hardware abstraction for cross-platform compatibility. This documentation is specifically designed for HarmonyOS developers who need a deep understanding of package architecture, module classification, and dependency management to effectively design and structure their applications prior to coding. By mastering these concepts, developers can optimize their application structure for performance and maintainability.

## Detailed Description

### 应用程序包概述_4more.md
This document provides a foundational overview of application packages for developers using the Stage model, explaining design mechanisms and package structures. It covers the definition of applications and packages, the multi-module design mechanism for modularity and device adaptation, and the classification of Module types. Key concepts include Ability modules, which generate entry or feature HAP files as basic installation units, and Library modules, which create Static HAR packages for code and resource sharing. The system abstracts hardware differences to ensure cross-platform compatibility. This guide is intended for HarmonyOS developers needing to understand package architecture before development.

### 选择合适的包类型.md
This guide assists HarmonyOS developers in selecting the appropriate package type, HAP or HAR, by comparing their functionalities and constraints. The document covers definitions and usage scenarios for HAPs as installable Ability modules and HARs as static shared libraries for compile-time reuse. A detailed specification comparison highlights that HAPs support independent installation and ExtensionAbility components, whereas HARs lack independent execution capabilities and do not support transitive dependencies. Key takeaways include warnings about potential package size increases when multiple HAPs reference the same HAR and recommendations for code obfuscation. This reference is intended for developers designing application architecture and managing SDK dependencies.
