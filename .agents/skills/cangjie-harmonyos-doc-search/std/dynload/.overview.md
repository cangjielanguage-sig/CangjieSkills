# dynload

The `dynload` directory contains a specialized tutorial focused on the implementation of dynamic loading within the Cangjie programming language. This documentation addresses the technical requirements for creating modular systems where code is loaded at runtime rather than being statically linked. It provides a deep dive into the `std.reflect` package and the `cjpm` build system, illustrating how to define public global variables and access them via `PackageInfo.load`. The guide emphasizes the importance of file naming conventions for library stability. This resource is highly suitable for Cangjie developers, system architects, and software engineers who are looking to build extensible applications, plugin architectures, or require the flexibility of runtime code integration and modification. By following this guide, users will learn to decouple components effectively, allowing for easier updates and feature additions without recompiling the entire application base.

## Detailed Description

### dynload.md dynload.md

This file serves as a comprehensive tutorial for developers working with the Cangjie programming language, specifically guiding them through the complex process of implementing dynamic loading. The document is structured to assist in creating both a dynamic library module and an executable capable of loading this module during runtime execution. This separation allows for greater modularity in software design.

Key sections of the tutorial include:

*   **Project Structure Setup:** Detailed instructions on using `cjpm` to establish the correct environment for dynamic loading projects, ensuring that build artifacts are generated correctly.
*   **Variable Management:** Best practices for defining public global variables that need to be exposed to the loading executable, serving as the communication bridge between the host and the library.
*   **Reflection Implementation:** A technical walkthrough of utilizing the `std.reflect` package to gain access to and modify the library's variables through the `PackageInfo.load` method, enabling powerful runtime introspection.

Additionally, the document underscores a critical operational constraint: the dynamic library filename must remain unchanged to ensure the loader can locate and function with the library correctly. This guide is designed for Cangjie developers who are actively seeking to implement modular architectures or integrate code dynamically at runtime.
