# application-models

This directory contains comprehensive documentation for HarmonyOS application development, specifically focusing on the Stage model and the Cangjie programming language. It covers core concepts such as the Ability Kit framework, UIAbility components, lifecycle management, configuration files (app.json5, module.json5), and inter-component communication via Want objects. The content is designed for developers building applications for HarmonyOS/OpenHarmony, providing guidance on architecture, component interaction, and cross-device capabilities.

## Detailed Description

### [1] README_zh
This directory provides Chinese navigation documentation for the Ability Kit (Program Framework Service), focusing on the HarmonyOS Stage model application development framework and key concepts. It covers application model overviews, Stage model development guides, UIAbility component lifecycle management, startup mode settings, and Want information passing mechanisms. It also details inter-application jump logic and configuration file writing standards. Suitable for HarmonyOS developers to build a clear understanding of the program framework and master component interactions. Note: Most features are in Beta.

### [2] cj-abilitykit-overview
This directory provides a comprehensive overview of the Ability Kit, explaining the core architecture and runtime mechanisms of the HarmonyOS application model framework. It explores the Stage model, component lifecycle management, context environment, and access control. It analyzes multi-module development, cross-device flow, and component-UI decoupling. By introducing the relationship between Ability Kit and ArkUI, it helps developers build efficient, standardized applications supporting multi-device collaboration. Suitable for application developers to optimize development processes and user experience.

### [3] cj-actions-entities
This directory contains documentation on `actions` and `entities` definitions in application configuration files. It covers common operations performed by the caller (e.g., startup entry, viewing data) and target component category information (e.g., default, browser). These attributes are usually declared in the `skills` field of the callee's configuration file. Suitable for developers configuring application modules, especially in `startAbility` scenarios. Note: Content is in Beta and not recommended for use. Keywords: skills, configuration file, component category, common operations.

### [4] cj-application-component-configuration-stage
This directory is dedicated to the application component configuration stage, a critical phase in the HarmonyOS development lifecycle. It provides a structured approach to defining the fundamental attributes of an application, ensuring it meets platform requirements and standards.

### [5] cj-application-models
This directory focuses on the architectural design of the system application model, specifically the core concepts and implementation details of the Stage model. It covers the five constituent elements: application components, process model, thread model, task management model, and configuration files.
