# mock_框架验证_API

This directory contains comprehensive documentation for the Verification API within a Cangjie language mocking framework. It covers technical references for the `Verify` class, utility methods, error handling, and practical usage patterns for asserting method calls. Key topics include cardinality functions, parameter matching, ordered vs. unordered verification, and the distinction between expectations and verification. The documentation is designed for developers writing unit tests who need to validate interactions between test code and mock or spy objects, ensuring precise control over test assertions and debugging capabilities.

## Detailed Description

### mock_框架验证_API_3more.md
This document provides technical reference documentation for the Verification API within a mock framework, explaining how to assert that specific method calls occurred during testing. It covers the Verify class as the entry point and the @Called macro used to construct verification statements. Key sections detail cardinality functions such as once(), atLeastOnce(), and times() to specify expected invocation counts, alongside rules for parameter matching. The guide clarifies that verification operates on call logs generated by mock and spy objects. Intended for developers writing unit tests in Cangjie, it assumes familiarity with stub signatures and parameter matchers.

### 其他_API_3more.md
This document provides API reference documentation for the Verify class in a Cangjie mocking framework, focusing on utility methods and error handling. It details specific tools such as that for single statement checks, noInteractions for verifying no calls, and clearInvocationLog for resetting logs. The text lists the full class signature, including ordered and unordered verification methods, and explains the VerificationFailedException with various failure types like call mismatches, unexpected calls, and disjoint statements. Intended for developers writing unit tests, this guide requires an understanding of mock objects and verification logic to effectively debug test failures.

### 示例和模式.md
This document serves as a practical tutorial for the Cangjie language's Mock API, demonstrating common patterns for verifying interactions between test code and external objects. It covers three main verification scenarios: verifying the number of method calls, verifying calls with specific arguments using matchers, and verifying the strict order of execution. Key takeaways include the usage of spy and mock objects, the `Verify` class methods like `unordered` and `ordered`, and argument matching techniques such as `ofType` and `argThat`. The target audience is developers writing unit tests who need to validate object interactions, requiring knowledge of the Cangjie language and testing frameworks.

### 预期与验证_API.md
This document serves as a usage guide for configuring mock objects using Expectation and Verification APIs within the Cangjie testing framework. It compares two distinct strategies for asserting test behavior: using explicit Verify blocks to check call counts and arguments, versus defining expectations directly on stubs using modifiers like .once(). Key takeaways include the recommendation to avoid repeating configuration steps in verification blocks and to choose the method that best reflects the specific intent of the test. The content provides code examples illustrating both Verify.unordered and direct @On syntax. This guide targets developers writing unit tests who require precise control over mock interactions and assertions.

### 验证块.md
This document serves as a technical guide for using verification blocks to assert mock and spy object interactions within a testing framework. It covers two primary verification modes: Ordered, which validates the exact sequence of calls, and Unordered, which checks call frequencies regardless of order. Key information includes that ordered verification defaults to once() and requires listing all relevant calls, while unordered verification defaults to atLeastOnce() and supports a Partial mode to ignore unspecified calls. The guide also explains dynamic block construction using lambda expressions. This reference is intended for developers writing unit tests who need to verify complex mock object behaviors and call sequences.
