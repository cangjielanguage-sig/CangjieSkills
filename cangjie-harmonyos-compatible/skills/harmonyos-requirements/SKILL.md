# 仓颉鸿蒙需求分析与设计 Skill

## 目的

把模糊需求转化为可执行的功能清单、设计方案和验收标准，作为后续实现输入。

## 适用场景

- 用户提出新功能开发需求（如"帮我做一个XX页面"、"实现XX功能"）
- 用户要求对现有功能进行较大改动
- 涉及多个组件/模块协作的开发任务
- **不适用**：改文字、调颜色、加按钮等轻量修改 — 直接确认改动内容后动手即可

## 需求分析流程

### 步骤 1：理解与拆解需求

把用户的模糊需求转化为明确的功能点清单：

1. 提取核心诉求，拆解为具体功能点，每点一句话描述
2. 识别不确定项（交互细节、异常处理、数据来源等）
3. 输出功能点列表、边界条件、待确认项

### 步骤 2：技术设计

基于确认后的功能点输出设计方案：

- **页面/组件拆分** — 需要哪些页面、自定义组件、弹窗
- **状态管理** — 状态装饰器选型及数据流转
- **布局方案** — 主要布局结构（Column/Row/Stack/List/Grid 等）
- **系统能力依赖** — 需要调用的系统 API（网络、文件、权限、路由等）

输出设计方案与数据流说明。

### 步骤 3：验收定义与确认

把需求和方案落成可验证结果，并完成确认：

- 给出验收标准（功能正确性、交互预期、异常处理）
- 标注未决事项和决策依赖
- 用户确认后再移交实现类 Skill

## 注意事项

1. **不确定的地方先确认** — 需求歧义、交互细节、边界条件宁可多问一轮，不要猜
2. **只做分析不做实现** — 本 Skill 不进入检索脚本执行、代码修改和构建流程
3. **结果可交接** — 产出需能被实现 Skill 直接消费（功能点、设计、验收、待确认项）

## 与其他 Skill 的关系

此 Skill 只负责分析与设计。确认完成后再移交：

- `cangjie-harmonyos-doc-search` — 文档检索
- `harmonyos-build` — 构建与编译验证
- `harmonyos-app-diagnose` — UI 验证与运行时诊断
- `harmonyos-evolution` — 经验沉淀
