# cj-restricted-permissions

This directory serves as a specialized repository for technical documentation concerning restricted open permissions within the HarmonyOS and OpenHarmony ecosystems. It focuses on the protocols for applications to obtain elevated privileges during the Beta phase, detailing Access Control Lists (ACL), Application Privilege Levels (APL), and specific configurations in the `HarmonyAppProvision` file. Additionally, it acts as a comprehensive reference guide for API 12 system-level permissions, covering hardware interfaces, network settings, and sensitive data access. This resource is primarily designed for HarmonyOS developers, system integrators, and security engineers who need to navigate complex permission configurations and understand the security boundaries for high-privilege system applications. It ensures that users can correctly implement temporary debugging measures without compromising the security standards required for official commercial releases.

## Detailed Description

### 受限开放权限/
This directory provides comprehensive technical documentation regarding restricted open permissions for the HarmonyOS and OpenHarmony ecosystems. It details the specific procedures for applications to access elevated privileges during the Beta phase, including the manipulation of Access Control Lists (ACL) and Application Privilege Levels (APL). The content covers critical configuration changes required in the `HarmonyAppProvision` file, specifically for debugging purposes, while clearly distinguishing these temporary measures from the official commercial release requirements.

Furthermore, it acts as a detailed reference repository for API 12 system-level permissions, covering hardware interfaces, network settings, and sensitive data access. This documentation is primarily designed for HarmonyOS developers, system integrators, and security engineers involved in building high-privilege system applications or managing complex permission configurations. It serves as a vital resource for understanding the security boundaries and capabilities available within the operating system environment, ensuring that development teams can effectively manage privilege escalation and system access during the software development lifecycle.
