## Detailed Description

### 栈回溯缺失的处理方案/

This subdirectory is dedicated to providing a robust solution for the "stack backtrace missing" problem that frequently arises during the fuzzing process within the cj-fuzz framework. When fuzzing complex applications, particularly those involving the Cangjie runtime, crashes may occur without providing a readable stack trace, making debugging extremely difficult. The content within this directory addresses this challenge by offering a complete technical roadmap.

It covers the entire lifecycle of the fix, starting with the necessary link configurations required to support symbol resolution and moving on to the integration of AddressSanitizer (ASan) to detect memory errors that might lead to silent crashes. Furthermore, it provides detailed analysis of specific crash cases to illustrate how native signal handling interacts with the runtime. By following these guidelines, users can effectively diagnose faults occurring at the native layer. This documentation is specifically curated for developers using cj-fuzz for security testing, security engineers investigating vulnerabilities, and QA engineers responsible for the Cangjie runtime, with the ultimate goal of significantly improving debugging efficiency and system reliability.

The solution delves deep into the mechanics of the Cangjie runtime, explaining how native signals are captured and translated into meaningful stack information. It highlights the importance of correct AddressSanitizer integration, which not only helps in detecting memory corruption but also ensures that when a crash occurs, the execution context is preserved for backtrace generation. By addressing these low-level interactions, the document empowers engineers to maintain a higher standard of code quality and security assurance.
