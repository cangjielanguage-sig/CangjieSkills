# 声明权限

This directory provides comprehensive guidelines for declaring and managing application permissions in HarmonyOS. It details the technical configuration required within the `module.json5` file, including tag structures and attributes like `name`, `reason`, and `usedScene`. Additionally, it offers style standards for drafting user-facing permission request reasons to ensure compliance and clarity. Key concepts include `user_grant` permissions, multilingual support, and app store validation prerequisites. This resource is designed for HarmonyOS developers seeking to implement robust permission management and ensure their applications meet platform authorization requirements.

## Detailed Description

### 声明权限_3more.md 声明权限_3more.md
This configuration guide instructs developers on declaring application permissions within the module.json5 file to ensure proper authorization. It covers the requestPermissions tag structure, detailing attributes such as name, reason, and usedScene through a descriptive table and JSON code examples. Key takeaways include the mandatory nature of the name field, the requirement for multilingual reason text for user_grant permissions, and the specification of usage scenarios like inuse or always. Targeted at HarmonyOS developers, this document serves as a prerequisite for app store validation and permission management.

### 权限使用理由的文案内容规范.md 权限使用理由的文案内容规范.md
This document serves as a style guide for developers on how to write the "reason" field when requesting user-granted permissions. It details writing standards, requiring direct, specific sentences under 256 characters that cover all usage scenarios across different app modules. The guide also explains display logic, noting that specific sensitive permission groups list sub-permissions, while other groups use the reason of the first applied sub-permission. Key takeaways include maintaining consistency across HAPs and adhering to length limits for UI display. This reference material targets application developers configuring permissions to ensure compliance and user understanding.
