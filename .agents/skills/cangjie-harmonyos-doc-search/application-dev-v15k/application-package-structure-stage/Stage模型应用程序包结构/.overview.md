# Stage模型应用程序包结构

This directory provides comprehensive technical documentation on the Stage model application package structure for HarmonyOS development. It covers the project hierarchy within DevEco Studio, detailing the organization of global AppScope and individual Module directories, configuration files like `app.json5`, and Cangjie source code management. Additionally, it explains the structural transformation from development to release, including the generation of HAP and HAR files, resource merging rules, and the relationship between App Packs and HAPs. This guide is essential for HarmonyOS developers, particularly those using the Cangjie language, who need to understand project architecture, file dependencies, and build deployment processes to effectively manage their applications from coding to market distribution. It serves as a critical reference for mastering the lifecycle of a HarmonyOS application package, ensuring proper configuration and successful deployment.

## Detailed Description

### Stage模型应用程序包结构_2more.md Stage模型应用程序包结构_2more.md
This technical guide details the Stage model application package structure during the development phase within DevEco Studio. It covers the project hierarchy, specifically distinguishing between the global AppScope directory and individual Module directories. Key sections explain the purpose of configuration files like app.json5 and module.json5, Cangjie source code storage, resource management, and build scripts such as hvigorfile.ts. The document emphasizes the importance of directory naming conventions and file organization. It is intended for HarmonyOS developers using the Cangjie language to understand their project's architecture and file dependencies.

### 编译态包结构_2more.md 编译态包结构_2more.md
This technical guide details the structural transformation of HarmonyOS applications from development through compilation to release. It covers the compile-time package structure, explaining how Modules generate HAP and HAR files, how Cangjie source compiles to .so files, and the merging rules for resources and configuration files. It further describes the release-time structure, defining the relationship between HAPs, Bundles, and App Packs, and the role of the pack.info file. Key takeaways include the precedence of AppScope resources and the fact that while App Packs are for market distribution, HAPs are the fundamental units for signing and installation. This reference is intended for developers managing application builds and deployment.
