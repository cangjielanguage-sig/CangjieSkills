# 观察变化

This directory provides a comprehensive technical overview of change observation mechanisms within the Cangjie state management system, specifically designed for ArkUI developers. It delves into the intricacies of the `@Prop` decorator, explaining how data synchronization works between parent and child components. The content covers a wide range of data types, including primitives, structs, classes, and arrays, highlighting specific behaviors such as deep observation requirements and the limitations of standard versus observed arrays. Furthermore, it addresses critical constraints regarding collection reactivity, particularly focusing on `HashSet` mutations. This resource is vital for developers aiming to master reactive programming in Cangjie, ensuring efficient state management and accurate UI updates in their applications. By understanding these rules, developers can avoid common pitfalls related to data binding and ensure their interfaces respond correctly to state changes.

## Detailed Description

### 观察变化_1.md
This technical guide details the change observation mechanisms of the @Prop decorator in Cangjie state management. It covers observation rules for primitive types, structs, classes, and various array or collection types, alongside synchronization logic with @State variables. Key takeaways include that primitives and struct reassignments are observable, while struct internals are not. Classes require @Observed and @Publish decorators for deep observation. Standard arrays only detect whole assignment, whereas ObservedArray supports item-level changes and modifications. The document also explains that @Prop syncs one-way from parent @State without modifying the source. This reference is intended for ArkUI developers managing component state and data reactivity.

### 观察变化_2.md
This document serves as a technical note or tutorial snippet explaining the limitations of observing internal changes within collections in the Cangjie programming language. It specifically addresses how the observation system handles HashSet mutations. The content demonstrates that while a HashSet can be assigned to an observable property, subsequent internal modifications, such as adding elements, are not detected by the observation mechanism. Key takeaways include the distinction between variable reassignment and internal collection mutation. This information is crucial for developers implementing reactive state management in Cangjie applications who need to understand data binding constraints. Keywords: Cangjie, HashSet, observation, reactivity, state management, collection mutation.
