# ohosdatadistributed_kv_store分布式键值数据库

本目录包含基于仓颉语言的HarmonyOS分布式键值数据库（KVStore）API参考文档。内容涵盖数据库管理、数据存储、查询及跨设备协同等核心功能，包括KVManager、SingleKVStore、DeviceKVStore、Schema定义及安全配置等关键组件。该文档旨在帮助开发者实现高效的数据管理与多设备数据同步，适用于使用仓颉语言进行分布式应用开发的开发人员。

### class_Constants.md class_Constants.md
本文档是分布式键值数据库常量类的API参考，旨在定义系统操作的各种数值约束。主要内容包括最大批处理数量、键值长度、存储ID长度及查询长度等六个静态常量。关键信息指出最大批处理操作数为128，Key长度限制为1024字节，Value长度限制为4194303字节，且区分了设备协同场景下的Key长度限制。该文档面向使用仓颉语言的开发者，用于确保数据操作符合系统规范。关键词：分布式数据库、KVStore、常量、长度限制、仓颉。

### class_Distributed_2more_60ee4eb2.md class_Distributed_2more_60ee4eb2.md
这是一份Cangjie语言的API参考文档，定义了分布式键值存储相关的类及其方法。文档涵盖`DistributedKVStore`和`Entry`两个核心类。`DistributedKVStore`类提供静态方法`createKVManager`，用于根据配置创建管理数据库的`KVManager`实例；`Entry`类则定义了数据库中的键值对结构，包含`key`和`value`属性及初始化构造函数。文档详细列出了参数、返回值、系统能力及起始版本，并附带代码示例。文档面向使用Cangjie进行分布式数据管理的开发者，提供了初始化管理器和定义数据条目的具体规范。

### class_FieldNode.md class_FieldNode.md
本文档是Cangjie语言中FieldNode类的API参考文档，用于表示Schema实例节点并定义分布式KV存储中的数据库字段值。文档涵盖了类的属性定义（包括默认值、可空性、节点类型）以及构造函数的详细说明。关键信息包括nodeType对应KVValueType枚举值，但当前版本不支持BYTE_ARRAY类型；构造函数中name参数不可为空且长度不超过64字符。面向使用分布式数据管理KVStore系统能力的开发者，提供Schema定义的参考。

### class_KVManagerCo_2more_2c1332b1.md class_KVManagerCo_2more_2c1332b1.md
本文档是Cangjie语言的API参考文档，旨在定义分布式数据管理中KVManagerConfig和KVStoreResultSet类的接口与用法。主要内容包括KVManagerConfig的配置属性（如bundleName和context）及其构造函数，以及KVStoreResultSet用于查询和遍历数据库结果集的方法。关键信息指出结果集不实时刷新，游标起始位置为-1，且最大打开数量为8个。文档面向使用HarmonyOS分布式KV存储的开发者，需具备Cangjie编程及上下文处理的基础知识。

### class_KVOptions.md class_KVOptions.md
本文档是KVOptions类的API参考文档，用于提供创建数据库时的配置信息。文档涵盖了类定义、属性（如自动同步、备份、创建缺失、加密、Schema及安全级别）以及构造函数的详细说明。关键信息包括各属性的默认值（如默认创建、不加密）、securityLevel为必填参数，以及autoSync在跨设备协同中的特定生效条件。面向使用分布式数据管理KVStore的开发者，需具备仓颉语言开发基础，适用于系统版本22及以上。

### class_Query_9e6dddb2.md class_Query_9e6dddb2.md
本文档是Cangjie语言中Query类的API参考文档，旨在定义用于表示数据库查询的类。主要内容包括类的功能概述、系统能力声明以及构造函数init()的详细说明。关键信息指出Query对象通过谓词查询数据，且谓词数量上限为256个，起始版本为22。该文档面向需要操作分布式数据KVStore的开发者，提供了创建查询实例的基础接口说明。

### class_Schema.md class_Schema.md
本文档是Cangjie语言中Schema类的API参考文档，旨在定义分布式键值数据库的模式结构。文档涵盖了类的构造函数及四个关键属性：root（字段定义）、indexes（索引路径）、mode（校验模式）和skip（校验跳过字节数）。核心要点在于mode属性，它区分了STRICT（严格匹配）和COMPATIBLE（允许额外字段）两种数据校验策略。该类用于KVOptions配置，适用于需要结构化存储和索引优化的分布式数据库开发人员。关键词：Schema、KVStore、STRICT、COMPATIBLE、FieldNode。
