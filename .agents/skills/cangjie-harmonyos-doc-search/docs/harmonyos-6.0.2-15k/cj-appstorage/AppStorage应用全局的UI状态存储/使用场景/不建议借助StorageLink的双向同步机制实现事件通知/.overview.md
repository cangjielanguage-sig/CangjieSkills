# 不建议借助StorageLink的双向同步机制实现事件通知

This directory provides critical technical guidance and best practices for implementing event notifications in application development, specifically within the HarmonyOS and Cangjie ecosystems. It strongly advises against utilizing `@StorageLink` and `AppStorage` for event-driven tasks due to the significant performance overhead caused by their two-way synchronization mechanisms. Instead, it promotes the use of the `Emitter` pattern for decoupled communication. The content covers the inefficiencies of global state refreshes, the benefits of callback-based event dispatching, and practical implementation strategies. This resource is essential for developers using the UIKit framework or ArkTS who aim to optimize UI rendering performance and maintain clean, readable code architecture while avoiding common pitfalls in state management. By following these guidelines, developers can ensure their applications remain responsive and efficient.

The following documents provide a comprehensive look at why standard storage links should be avoided for events and how to correctly implement the alternative solution.

### 不建议借助StorageLink的双向同步机制实现事件通知_1.md 不建议借助StorageLink的双向同步机制实现事件通知_1.md
This guide advises developers against using @StorageLink and AppStorage for event notifications due to performance overhead. It covers the drawbacks of the two-way synchronization mechanism, provides a code example using @Watch, and recommends the `emit` interface as an alternative. Key takeaways include that modifying AppStorage variables triggers UI refreshes in all bound components, which is inefficient for specific event notifications. Using `emit` for callbacks reduces overhead and improves code readability, though it is unsupported in the Previewer. This is intended for application developers using the Cangjie language and UIKit framework who need to manage state and events efficiently.

### 不建议借助StorageLink的双向同步机制实现事件通知_2.md 不建议借助StorageLink的双向同步机制实现事件通知_2.md
This document serves as a technical code example demonstrating how to implement event notifications between components using the Emitter mechanism, likely as an alternative to the discouraged StorageLink method. The content features an ArkTS implementation where a parent EntryView emits events based on user interactions in a Grid, and child TapImage components listen to these events to update their border color dynamically. Key takeaways include the usage of Emitter.emit for dispatching events and Emitter.on for subscribing to state changes, highlighting a decoupled communication pattern. This tutorial is designed for HarmonyOS developers with prior knowledge of ArkTS and component lifecycle management, specifically those seeking efficient ways to handle UI state updates and event-driven architecture.
