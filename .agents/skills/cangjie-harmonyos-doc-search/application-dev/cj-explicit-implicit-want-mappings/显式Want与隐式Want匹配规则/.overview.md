# 显式Want与隐式Want匹配规则

This directory serves as a comprehensive technical resource for understanding the matching rules governing Explicit and Implicit Wants within the application framework. It is designed to assist developers in mastering the mechanisms required to launch application components effectively. The content covers the alignment of caller parameters with target component configurations, focusing on critical fields such as bundleName, abilityName, action, entities, and URI. By detailing the nuances of priority handling, wildcard usage, and `module.json5` configuration requirements, this guide ensures robust implementation of cross-component invocation. It is highly suitable for application developers and system engineers utilizing the AbilityKit API to facilitate seamless component startup, data transmission, and intent filtering in a complex system environment. Mastering these rules is essential for ensuring application stability and correct inter-component communication.

## Detailed Description

The following sections provide in-depth technical details regarding the specific matching rules and principles for both Explicit and Implicit Wants.

### 显式Want与隐式Want匹配规则_2more.md 显式Want与隐式Want匹配规则_2more.md

This technical reference guide outlines the matching rules for Explicit and Implicit Wants used to launch application components. It details how parameters in the caller's Want object align with the target component's configuration file. The primary section covers Explicit Want matching principles, specifying that bundleName and abilityName are mandatory fields for successful matching. The document clarifies that while fields like action and entities are ignored during the matching process, they are still passed as parameters to the target component. This guide is intended for developers working with the AbilityKit API to manage component startup and data transmission.

### 隐式Want匹配原理/

This directory provides a comprehensive technical overview of the implicit Want matching mechanism used in system application component routing. It covers the core logic for resolving intents based on parameters such as action, entities, URI, type, and linkFeature. The documents detail specific matching rules, priority handling, and configuration requirements within `module.json5`. Key topics include URI expression types, wildcard handling, and the interaction between caller parameters and target skills. This resource is suitable for system developers and application engineers looking to implement or debug cross-component invocation and intent filtering.
