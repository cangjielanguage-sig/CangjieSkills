This directory serves as a comprehensive collection of API reference documents for enumerations used within the Cangjie testing and performance framework. It specifically covers definitions for garbage collection types (ExplicitGcType), precise time measurement units (TimeUnit), and CPU performance counters (PerfCounter). These enumerations are essential for developers who need granular control over memory management, accurate time tracking, and low-level hardware or software event monitoring during performance analysis and benchmarking. The documentation is primarily suitable for systems programmers and performance engineers working in the Cangjie language who are building robust testing tools or analyzing system metrics. It includes details on interface inheritance, such as ToString, and mappings to system calls like Linux's perf_event_open.

## Detailed Description

### enum_ExplicitGcType_2more.md enum_ExplicitGcType_2more.md

This API reference document defines two enumerations for the Cangjie testing framework: ExplicitGcType and TimeUnit. The ExplicitGcType enum configures garbage collection behavior within the @Configure macro, offering options to disable GC or trigger heavy or light collection during benchmarks. The TimeUnit enum specifies time measurement units, including Nanos, Micros, Millis, and Seconds, for use with the TimeNow constructor. Both enums inherit from the ToString interface to provide string representations. This documentation serves developers implementing performance tests who require precise control over memory management and time measurement.

### enum_PerfCounter.md enum_PerfCounter.md

This API reference document defines the PerfCounter enum, which specifies CPU performance counters supported by the Perf constructor in the Cangjie language. The content categorizes members into hardware counters, such as CPU cycles and cache misses, and software counters, including context switches and page faults. It also details the toString() method for string representation. Key information includes that these counters map directly to the Linux perf_event_open system call for low-level performance monitoring. This documentation targets developers implementing performance analysis tools who need to select specific metrics for hardware or software event tracking.
