# cj-apis-device_info

This directory serves as a specialized technical repository for the `ohos.device_info` module, specifically adapted for the Cangjie programming language within the HarmonyOS environment. It functions as a vital reference for developers seeking to retrieve detailed terminal device information, encompassing both hardware identifiers and software metadata. The documentation outlines key implementation requirements, including module import protocols, necessary security permissions such as `ohos.permission.sec.ACCESS_UDID`, and practical usage instructions for template projects. Given the module's Beta status, the resource emphasizes its read-only characteristics and current lack of configuration options. This documentation is primarily intended for Cangjie application developers and system integrators who need accurate device data to create system-aware applications, conduct diagnostics, or verify compatibility across various OpenHarmony devices, supporting development from API version 22 onwards.

## Detailed Description

### ohosdevice_info设备信息/

This directory serves as a comprehensive technical resource for the `ohos.device_info` module, specifically tailored for the Cangjie programming language within the HarmonyOS ecosystem. It provides essential documentation for developers aiming to query terminal device information, ranging from basic hardware identifiers to detailed software metadata. The content covers critical implementation aspects such as module import procedures, necessary security permissions (e.g., `ohos.permission.sec.ACCESS_UDID`), and practical usage guidelines for template projects. As the module is currently in Beta, the documentation highlights its read-only nature and the absence of configuration options. This resource is primarily suitable for Cangjie application developers and system integrators who require precise device data to build system-aware applications, perform diagnostics, or ensure compatibility across different OpenHarmony devices. By utilizing these references, developers can effectively access system capabilities starting from API version 22.
