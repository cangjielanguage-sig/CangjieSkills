These resources are essential for developers implementing custom benchmarks, managing test data, or configuring unit test parameters like coverage guidance, timeouts, and reporting formats. The documentation provides structural definitions and usage guidance for optimizing performance testing accuracy and framework configuration.

## Detailed Description

### struct_BatchInputProviderT_2more.md struct_BatchInputProviderT_2more.md
This API documentation details two Cangjie structs, `BatchInputProvider` and `BatchSizeOneInputProvider`, used for managing input generation during performance benchmarking. Both inherit from `BenchInputProvider` and feature constructors accepting a builder closure, alongside get and reset methods. The key distinction lies in their execution strategy: `BatchInputProvider` pre-generates the entire batch in a buffer, whereas `BatchSizeOneInputProvider` generates input per execution to exclude generation time from measurements. The latter is specifically recommended when input generation is slow or unstable compared to the benchmark logic.

### struct_CpuCycles_2more.md struct_CpuCycles_2more.md
This API documentation defines two structs for the Cangjie unittest package: `CpuCycles` for performance measurement and `GenerateEachInputProvider` for benchmark data generation. The file details the `CpuCycles` struct, which implements the `Measurement` interface to count CPU cycles via the rdtscp instruction on x86 platforms. It also covers `GenerateEachInputProvider`, a provider that generates fresh input for every benchmark iteration. Key information includes `CpuCycles` properties like conversionTable and a measure function returning Float64, alongside `GenerateEachInputProvider` methods that ensure input generation time is calculated as framework overhead.
