It explains that Cangjie interfaces called from the ArkTS main thread must not block while waiting for results from tasks spawned via spawn(UIThread). The key takeaway is that blocking operations like future.get() or Mutex.lock() on the main thread cause deadlocks because the spawned task requires the main thread to run. The document provides a code example illustrating this error. It is intended for developers needing to manage asynchronous execution and thread safety across these languages.
