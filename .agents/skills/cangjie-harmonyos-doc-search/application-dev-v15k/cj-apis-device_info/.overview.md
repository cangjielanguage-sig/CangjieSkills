# cj-apis-device_info

This directory serves as a specialized technical resource dedicated to the `ohos.device_info` module, explicitly designed for HarmonyOS developers utilizing the Cangjie programming language. It provides comprehensive documentation and API references for querying read-only terminal device information, covering critical aspects such as hardware specifications, build metadata, and operating system distribution details. The content thoroughly explains essential implementation requirements, including module imports, necessary system capabilities like `SystemCapability.Startup.SystemInfo`, and specific permissions such as `ohos.permission.sec.ACCESS_UDID` for accessing sensitive data like serial numbers. This resource is highly suitable for developers who need to programmatically access device configuration for system analysis, compatibility checks, or application diagnostics. It ensures users understand how to execute code within template projects to read extensive device data, while clarifying that configuration changes are not supported through this interface.

### ohosdevice_info设备信息/
This directory functions as a comprehensive technical resource dedicated to the `ohos.device_info` module. It is specifically tailored for HarmonyOS developers who are utilizing the Cangjie programming language. The content provides detailed API references and implementation guides focused on querying read-only terminal device information. This encompasses a wide range of data points, including hardware specifications, build metadata, and operating system distribution details.

Furthermore, the documentation thoroughly covers essential implementation aspects. This includes instructions on module imports, required system capabilities such as `SystemCapability.Startup.SystemInfo`, and specific permissions like `ohos.permission.sec.ACCESS_UDID` which are necessary for accessing sensitive data like serial numbers. The resource is designed for developers who need to programmatically access device configuration for purposes such as system analysis, compatibility checks, or application diagnostics. It ensures that users understand how to execute code within template projects without modifying device settings. Finally, the content clarifies that while developers can read extensive device data, configuration changes are not supported through this interface.
