# collection_package_exception

This directory serves as a comprehensive resource for the `ConcurrentModificationException` class found within the Cangjie programming language's collection package. It provides essential API reference material, detailing the class definition, its inheritance hierarchy from the base Exception type, and the specific constructors available for creating instances with default or custom error messages. The documentation highlights critical concurrency constraints, explaining that collection containers do not support unsynchronized concurrent modifications. It is particularly valuable for Cangjie developers who need to diagnose and handle runtime errors that occur when collections are modified during iteration or when views like MapEntryView are used after underlying data changes.

This API reference document details the ConcurrentModificationException class within the Cangjie collection package. The main sections cover the class definition, its inheritance from the Exception parent type, and two constructors for initializing instances with or without a custom message. Key information explains that this exception is thrown when unsynchronized concurrent modification is detected, specifically noting that collection containers do not support concurrent modification. Typical scenarios include modifying a container during for-in iteration or using MapEntryView after the underlying container changes. This documentation targets Cangjie developers who need to understand error handling and concurrency constraints when working with collection data structures.
