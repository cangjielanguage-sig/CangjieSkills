# cj-common-components-custom-dialog

This directory serves as a specialized technical repository for HarmonyOS developers working with the ArkUI framework and the Cangjie language. It focuses specifically on the creation, configuration, and management of custom pop-up dialogs using the `@CustomDialog` decorator and `CustomDialogController`. The content highlights a Beta feature that is currently not recommended for production environments, making it a resource for experimental development, testing, and future-proofing applications. It covers essential topics such as distinguishing between modal and non-modal behaviors, managing dialog persistence across different page routes, and handling component lifecycles effectively. This directory is ideal for developers aiming to build complex user interactions, such as system warnings or update prompts, who need to understand the specific architectural constraints and capabilities of custom dialogs in this ecosystem.

## Detailed Description

### 基础自定义弹出框CustomDialog不推荐/

This subdirectory functions as a comprehensive educational resource for HarmonyOS developers interested in the ArkUI framework's capabilities for custom pop-up dialogs using the Cangjie language. It provides detailed tutorials that cover the entire spectrum of implementation, starting with the fundamental usage of the `@CustomDialog` decorator and `CustomDialogController`. The content is structured to help developers master not only the basic setup but also more sophisticated requirements such as advanced styling and the management of nested dialog structures.

Key technical concepts are thoroughly explored to ensure a deep understanding of the component's behavior. The tutorials explicitly distinguish between modal and non-modal behaviors, explaining how each affects user interaction and application flow. Additionally, the directory addresses the critical aspect of dialog persistence across page routes, ensuring that dialogs maintain their state correctly during navigation. Component lifecycle management is another core topic, equipping developers with the skills to handle initialization and destruction events properly. Given that this feature is currently in Beta and not recommended for production, this directory serves as a forward-looking guide for developers preparing to implement complex user interactions like warnings or updates within the specific architectural constraints of the HarmonyOS environment.
