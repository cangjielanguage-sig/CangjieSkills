# 桩使用指南

This directory serves as a comprehensive technical guide for developers using the Cangjie unit testing framework, focusing on the effective use of stubs and mock objects. It covers advanced topics such as sharing mocks across tests, capturing arguments for verification, configuring default behaviors via Stub Modes, and creating custom parameter matchers. The documentation aims to reduce code redundancy and improve test maintainability. It is intended for developers seeking to master mocking patterns, manage mock object states, and implement robust testing strategies within the Cangjie ecosystem.

## Detailed Description

### 共享_mock_对象和桩.md 共享_mock_对象和桩.md
This technical guide explains best practices for sharing mock objects and stubs across multiple test cases to reduce redundancy while avoiding test instability. It covers declaring mocks as instance variables and differentiates between placing stubs in test bodies versus `@BeforeAll` functions. Key takeaways include that shared stubs in `BeforeAll` must be stateless operations like `returns` or `throws` without expectations or cardinality, whereas stubs in test bodies allow full expectation checking. The document explicitly warns against declaring stubs in constructors to prevent framework errors. Intended for developers using the Cangjie unit testing framework, it provides code examples demonstrating how to implement shared default behaviors safely.

### 捕获参数.md 捕获参数.md
This technical guide explains how to use the `captor` parameter matcher and `ValueListener` within a mock framework to intercept and verify arguments passed to stubbed methods. It covers immediate validation using `ValueListener.onEach`, post-execution inspection via `allValues()` and `lastValue()`, and conditional capturing using the `argThat` matcher with filters. The document provides Cangjie code examples demonstrating how to bind listeners to specific method calls. It highlights that while captors work with mocks and spies, they are prohibited within the `@Called` macro. This guide targets developers using unit testing frameworks who need to validate specific input parameters during test execution.

### 桩使用指南_4more.md 桩使用指南_4more.md
This guide provides instructions on using stubs within a mock framework to create maintainable test cases. It details the working mechanism of the `@On` macro, including parameter matching, scope, and default behaviors for mock and spy objects. The document explains how to redefine stubs and configure multiple stubs for a single declaration, highlighting the bottom-to-top priority rule. Key takeaways include the necessity of satisfying all stub expectations unless the `anyTimes()` modifier is used. Intended for developers writing tests in the Cangjie language, this tutorial covers essential patterns for managing mock object behaviors and verifying interactions.

### 桩的模式.md 桩的模式.md
This technical reference guide explains how to configure default behaviors for mock objects using Stub Modes in a Cangjie testing framework. It details two specific modes: ReturnsDefaults, which provides default values like zero or empty strings for common types without explicit stubbing, and SyntheticFields, which simplifies setting values for mutable properties. Key information includes enabling these modes via the mock function and the StubMode enum, with explicit stubs and assigned values taking precedence over defaults. The document warns that these modes do not impose expectations and do not support static members. This guide is intended for developers writing unit tests who need to reduce boilerplate code when configuring mock objects.

### 自定义和使用参数匹配器_2more.md 自定义和使用参数匹配器_2more.md
This technical guide explains how to extend the Cangjie mock framework by creating custom argument matchers and configuring stubs for properties and fields. The document covers defining reusable matchers via the `Matchers` class extension, including parameterized matchers using `TypedMatcher<T>`. It details stubbing properties and setters, distinguishing between standard stubbing and stateful behavior using `SyntheticField.create`. Key takeaways include using `getsField` and `setsField` to bind properties to synthetic storage, ensuring state resets between tests. Intended for developers familiar with Cangjie unit testing, this guide provides advanced techniques for reducing code duplication and managing mock object state.
