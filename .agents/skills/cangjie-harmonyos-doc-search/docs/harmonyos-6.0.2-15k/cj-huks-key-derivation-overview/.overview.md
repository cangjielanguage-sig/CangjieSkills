# cj-huks-key-derivation-overview

This directory provides a comprehensive technical overview of Key Derivation Functions (KDF) as implemented in the Harmony Universal KeyStore (HUKS) framework for OpenHarmony. It is designed to assist developers in understanding how to securely generate cryptographic keys from base secrets using standardized algorithms. The content focuses heavily on the specifications and constraints of supported derivation methods, specifically detailing the usage of HKDF and PBKDF2 in conjunction with various SHA hashing algorithms. It addresses critical compatibility factors, such as the requirement for API level 15 or higher and the specific input/output key sizes supported for major encryption standards like AES, HMAC, and SM4. Additionally, the documentation highlights important security restrictions, including the inability to derive keys directly from user passwords and the exclusion of this functionality on lightweight devices. This resource is vital for software engineers and security architects working within the OpenHarmony ecosystem who need to implement secure key management strategies that rely on the hardware-backed security of a Trusted Execution Environment (TEE). By adhering to these guidelines, developers ensure their applications maintain high security standards while leveraging the native capabilities of the OpenHarmony platform.

The following summary outlines the key points covered in this document:

This document provides an overview and algorithm specifications for key derivation functions within the HUKS framework. It covers the introduction to KDF concepts and a detailed table of supported algorithms including HKDF and PBKDF2 variants with SHA digests. Key takeaways include the restriction that derivation is only possible using HUKS-managed keys, not direct user passwords, and is unavailable on lightweight devices. The table details supported input/output key sizes like AES, HMAC, and SM4, requiring API level 15 or higher. This reference guide targets developers implementing cryptographic security in OpenHarmony applications who need to derive keys securely within a TEE environment.
