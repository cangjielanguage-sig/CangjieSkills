# 使用Deep_Linking实现应用间跳转

This directory provides a comprehensive guide on implementing inter-application navigation using Deep Linking technology within the HarmonyOS ecosystem. It covers the underlying principles of URI-based app launching, implicit Want matching, and the specific configuration required for both calling and target applications. Key topics include the `openLink` API, `module.json5` configuration, and lifecycle callbacks like `onNewWant`. This resource is suitable for HarmonyOS developers using the Cangjie programming language and ArkUI framework who need to enable seamless cross-app jumps and web-to-native transitions.

## Detailed Description

### 使用Deep_Linking实现应用间跳转_2more.md 使用Deep_Linking实现应用间跳转_2more.md
This document explains how to implement inter-application navigation using Deep Linking technology. It covers the general behavior of URI-based app launching and details the "Implementation Principle" behind the functionality. Key information includes how the system locates installed apps based on provided URIs and displays a selection dialog if multiple matches are found. The mechanism relies on the implicit Want matching framework, specifically URI matching rules. This guide targets developers seeking to integrate cross-app navigation capabilities into their applications, providing a conceptual overview of the underlying matching logic.

### 目标应用操作指导.md 目标应用操作指导.md
This technical guide instructs developers on configuring a target HarmonyOS application to support deep linking and parse incoming application links. The document details two primary steps: configuring the module.json5 file with specific skills and uris tags, and implementing link retrieval logic within the UIAbility lifecycle callbacks. Key takeaways include the necessity of creating separate skill objects for different jump scenarios, defining custom schemes, and using onCreate() or onNewWant() to extract URI parameters for business logic processing. This guide is intended for developers using Cangjie to enable cross-application access.
