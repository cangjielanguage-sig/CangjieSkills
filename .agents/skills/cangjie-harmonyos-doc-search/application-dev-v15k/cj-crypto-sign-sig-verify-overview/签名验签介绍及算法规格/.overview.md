## Detailed Description

### DSA_3more.md
This document serves as a technical reference for configuring digital signature algorithms, specifically DSA, SM2, and Ed25519, within a cryptographic API. It details the string parameter format required to instantiate signature and verification instances, typically combining asymmetric key types and digest algorithms using a pipe delimiter. Key sections cover supported key lengths, compatible hash functions like SHA variants for DSA and SM3 for SM2, and API version requirements. Important takeaways include the specific syntax for parameter construction, compatibility notes for keys without specified lengths, and the restriction that DSA with NoHash does not support segmented operations. This guide is intended for software developers implementing cryptographic security features, providing the necessary specifications for algorithm selection and parameter formatting.

### ECDSA.md
This document serves as a technical reference for implementing ECDSA (Elliptic Curve Digital Signature Algorithm) within a specific algorithm library framework, detailing supported curves and digest combinations. It covers the definition of ECDSA, the string parameter format for specifying algorithm specifications, and a comprehensive table mapping supported asymmetric key types (like ECC224, BrainPool, Secp256k1) to compatible digest algorithms (SHA1-SHA512). Users must construct a string parameter using the format "KeyType|Digest" (e.g., "ECC224|SHA256") to initialize signature instances. The framework supports various curves including standard NIST curves and BrainPool variants, with a generic "ECC" option available for key compatibility. All features require API version 12 or higher. This reference guide targets developers integrating cryptographic signing and verification into applications, requiring knowledge of public key cryptography and API versioning.
