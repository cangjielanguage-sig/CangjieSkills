# LocalStorage页面级UI状态存储

This directory covers the LocalStorage mechanism for page-level UI state management within the ArkUI and Cangjie frameworks. It details how to use decorators like `@LocalStorageProp` and `@LocalStorageLink` to synchronize data between components and storage, supporting both one-way and two-way data binding. The content includes API definitions, usage constraints, lifecycle management, and practical scenarios for sharing state across pages and components. It is suitable for HarmonyOS developers looking to implement efficient, persistent, or shared application states.

## Detailed Description

### LocalStorageLink.md LocalStorageLink.md
This API documentation defines the `@LocalStorageLink` decorator, which enables two-way data synchronization between custom component state variables and LocalStorage. The document covers macro usage rules, variable transfer and access constraints, and detailed observation behaviors for various data types including classes, arrays, and collections like Map and Set. Key information includes the requirement for a string key, support for bidirectional syncing where local changes update LocalStorage and vice versa, and the prohibition of parent node initialization. This guide targets developers using the ArkUI framework who need to manage persistent or shared application state across components.

### LocalStorageProp.md LocalStorageProp.md
This API documentation explains the `@LocalStorageProp` decorator used for one-way data synchronization between LocalStorage and custom component variables in ArkUI. It details macro usage rules, including required string keys, supported data types (class, String, number, collections), and initialization requirements. The document outlines variable passing restrictions, prohibiting parent initialization while supporting child initialization. It further describes observation behaviors for various data types and framework behavior regarding component refreshes. This guide is intended for developers managing application state, emphasizing that LocalStorage changes overwrite local values.

### LocalStorage页面级UI状态存储_2more.md LocalStorage页面级UI状态存储_2more.md
This technical guide introduces LocalStorage, a page-level UI state storage mechanism in the Cangjie framework designed for managing state within and across pages in a UIAbility instance. The document details the core concepts of LocalStorage as an in-memory database and explains the usage of key macros: `@LocalStorageProp` for one-way synchronization and `@LocalStorageLink` for two-way synchronization. It also references API interfaces for manual data manipulation. Developers should have a basic understanding of state management frameworks before reading. Key takeaways include the lifecycle of LocalStorage instances and how they are propagated through the component tree via the `@Entry` decorator.

### 限制条件.md 限制条件.md
This reference document outlines the specific constraints and usage rules for LocalStorage and its associated decorators in the Cangjie framework. It covers parameter type requirements for decorators, unsupported variable types, immutability of attribute types after creation, and the scope of LocalStorage as page-level storage. Key takeaways include that decorator parameters must be strings, function types are not supported, attribute types are immutable once defined, and it operates at the page level. This guide targets developers using Cangjie for UI development who need to manage state storage correctly to avoid compile-time or runtime errors.

This directory contains tutorials and guides on using LocalStorage for state management in ArkUI applications developed with the Cangjie language. It covers various scenarios ranging from basic data binding and component communication to sharing state across UIAbility and views. Key topics include one-way and two-way data binding using decorators like `@LocalStorageProp` and `@LocalStorageLink`, handling complex data types, and modifying state from external logic. These resources are suitable for HarmonyOS developers looking to implement efficient state synchronization and data flow within their applications.
