# 基于shell命令测试

This directory provides comprehensive documentation for executing automated UI testing on HarmonyOS/OpenHarmony systems using shell commands via the hdc tool. It covers a wide range of testing functionalities, including screen capturing, layout hierarchy dumping, UI interaction recording, and the simulation of complex user inputs such as touch gestures and hardware key events. Additionally, it includes guides for environment setup, version verification, and daemon management. These resources are specifically designed for developers and QA engineers who require efficient, script-free testing workflows and remote control capabilities for their applications.

## Detailed Description

### 基于shell命令测试_4more.md 基于shell命令测试_4more.md
This reference guide documents the uitest shell command tool for performing quick automated testing tasks like screen capturing, layout dumping, and UI simulation. The content covers a command list table, usage examples for screenshots and layout retrieval, and a detailed explanation of the UI recording feature and its data structure. Key information includes commands such as screenCap, dumpLayout, uiRecord, and uiInput, along with specific parameters for file paths and attribute saving. It also details the JSON schema for recorded user interactions. Intended for developers with configured hdc environments, this guide facilitates efficient testing workflows without full script deployment.

### 注入UI模拟操作.md 注入UI模拟操作.md
This document serves as a technical reference for the uiInput command suite, enabling automated simulation of user interface interactions via the hdc shell. It details specific commands for touch gestures (click, doubleClick, longClick, fling, swipe, drag, dircFling), text input, and hardware key events. Key information includes parameter definitions such as coordinates, velocity, and key IDs, along with usage examples for each action. The guide targets developers and QA engineers performing automated testing or remote control on HarmonyOS/OpenHarmony systems, providing the necessary syntax to programmatically manipulate the device UI.

### 获取版本信息_2more.md 获取版本信息_2more.md
This technical guide provides instructions for checking the UITest version and initiating the testing daemon process. The document covers two main operations: retrieving version information using a shell command and starting the uitest daemon. Key information includes critical prerequisites such as enabling developer mode on the device. It specifies that only processes launched via the aa test command possess the capability to invoke UITest interfaces, whereas aa start will cause errors. Additionally, the test HAP requires an APL level of system_basic or normal. This guide is intended for developers or QA engineers setting up automated UI testing environments.
