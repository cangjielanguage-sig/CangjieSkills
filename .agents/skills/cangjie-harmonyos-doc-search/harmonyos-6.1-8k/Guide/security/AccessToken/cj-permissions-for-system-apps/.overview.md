# cj-permissions-for-system-apps

This repository serves as a comprehensive guide for managing permissions in system-level applications built for the OpenHarmony and HarmonyOS operating systems. It specifically targets permissions that are not available to standard applications and require an Access Control List (ACL) application process. The documentation covers a wide range of sensitive capabilities defined across API versions 12 through 20, including critical domains like device management, network security, privacy protection, media control, and direct hardware access. All permissions listed here are of the `system_grant` type, meaning they are authorized by the system rather than the user, and strictly require ACL enablement. This resource is essential for developers working on `system_basic` or higher-level system applications who need to understand the rigorous compliance standards and authorization protocols necessary to securely access and utilize the underlying system capabilities.

## Detailed Description

### 可ACL申请的系统应用可用权限系统授权/

This subdirectory acts as a centralized repository for documentation regarding system application permissions that are eligible for ACL (Access Control List) applications within the OpenHarmony and HarmonyOS ecosystems. Unlike standard permissions, the permissions detailed here are highly sensitive and are defined across API versions 12 through 20. The scope of this documentation is extensive, covering critical functional areas including device management, network security, privacy protection, media control, and hardware access.

Specifically, all permissions cataloged in this section are classified as `system_grant`. This classification indicates that these permissions are granted by the system during installation or runtime based on specific policies, rather than being explicitly authorized by the end-user. Consequently, accessing these capabilities requires ACL enablement, a process that validates the application's privilege level. This documentation is primarily designed for developers building system applications at the `system_basic` level or above. Its primary objective is to provide clear permission application specifications and compliance guidance, ensuring that developers can securely and legally integrate deep system functionalities into their applications while adhering to the platform's security standards.
