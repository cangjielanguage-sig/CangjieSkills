# 示例代码

This directory provides a comprehensive collection of example code demonstrating the integration of the Cangjie language with high-performance Native C++ graphics rendering on the HarmonyOS platform. It focuses on the practical implementation of the XComponent component, Foreign Function Interface (FFI) declarations, and the management of EGL and OpenGL ES 3.0 environments. The examples illustrate how to bridge Cangjie UI logic with C++ backend processing to manage rendering surfaces, handle lifecycle callbacks, and execute complex geometric drawing operations. This resource is specifically suitable for HarmonyOS developers and C++ programmers aiming to combine Cangjie application interfaces with native graphics capabilities for advanced visual applications.

## Detailed Description

### 示例代码_2more.md 示例代码_2more.md
This document serves as a tutorial for developers on how to use the XComponent component in the Cangjie language to render graphics via Native C++ integration. It details the Cangjie code structure, focusing on Foreign Function Interface (FFI) declarations that bridge to native methods for creating EGL/GLES environments and managing NativeWindow instances. Key sections include a custom XComponentController handling surface lifecycle callbacks and a user interface with buttons to trigger drawing and color changes. The example demonstrates passing SurfaceId to the native side to manipulate graphics. This guide is intended for HarmonyOS developers seeking to combine Cangjie UI with high-performance native rendering.

### native代码/
This directory contains C++ source code and headers for a native graphics application using OpenHarmony/HarmonyOS APIs. It focuses on EGL and OpenGL ES 3.0 rendering within a Native XComponent environment. Key components include the `EGLCore` class for context management, `PluginManager` for lifecycle and surface handling, and `PluginRender` for specific drawing operations. The code demonstrates shader compilation, geometric rendering (like stars), and window management. It is suitable for C++ developers working on low-level graphics programming, specifically those integrating native rendering surfaces into HarmonyOS applications.
