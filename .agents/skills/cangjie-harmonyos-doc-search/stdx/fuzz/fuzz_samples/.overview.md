# fuzz_samples

This directory contains a comprehensive collection of documentation and sample resources designed to support fuzzing activities within the Cangjie programming language ecosystem. It covers essential topics ranging from basic fuzzing test structures and API usage with `FuzzDataProvider` to advanced troubleshooting for coverage initialization and stack backtrace issues. The content is tailored for developers and QA engineers who utilize the `cj-fuzz` framework and libfuzzer to identify software defects, optimize test coverage, and resolve common technical obstacles during the fuzzing process.

## Detailed Description

### [1] basic_fuzzing_test/
This directory serves as a comprehensive resource for conducting basic fuzzing tests, with a specific focus on the Cangjie programming language. It provides a structured approach to identifying software defects through automated input generation.

### [2] dataprovider_usage/
This directory contains guide documentation on using FuzzDataProvider for API testing in the Cangjie language. The content covers the basic usage of the FuzzDataProvider class, code examples for generating standard data types from mutation data sources via consume methods, and how to configure debugging features to print logs tracking data consumption. This document is primarily for developers needing fuzzing and API debugging, aiming to provide a more testing-friendly way than directly manipulating byte streams, including specific compilation flag usage and debug output formats.

### [3] fake_coverage_usage/
This directory contains usage guide documentation for the FakeCoverage feature, aimed at resolving Fuzz abnormal termination issues caused by libfuzzer initialization detection failure in DataProvider mode. The document deeply analyzes the root cause of initialization input being consumed early in libfuzzer version 14 and below, and provides a solution to circumvent this problem by creating fake coverage information. Core keywords include: FakeCoverage, libfuzzer, DataProvider, coverage initialization, fuzzing. This guide is suitable for developers using fuzzing tools, especially technical personnel encountering coverage initialization obstacles.

### [4] print_cj-fuzz_usage/
This directory contains usage documentation for the `cj-fuzz` fuzzing tool, focusing on how to display help information and configure random number seeds. The documentation covers key command-line parameters such as `-help=1` and `-seed`, and elaborates on two running modes: passing a directory for fuzzing versus passing a file for single execution. This guide is suitable for developers and testers who need to quickly check command-line parameter formats and running modes to efficiently configure and execute test tasks.

### [5] print_coverage/
This directory mainly contains documentation on the coverage printing feature in the Cangjie fuzzing tool. The directory aims to guide developers on how to count and analyze function test coverage through specific startup parameters. Content covers a basic overview of the feature, detailed compilation configuration requirements (e.g., must link Cangjie's built-in libfuzzer library and enable specific sanitizer coverage options), and provides C language vs. Cangjie language output example comparisons. As an experimental feature, this will not interfere with the normal fuzz process and is very suitable for Cangjie language developers who need to deeply analyze test coverage. Core keywords include: Cangjie, fuzzer, coverage, libfuzzer, sanitizer.
