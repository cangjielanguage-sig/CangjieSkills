# AESGCMNoPadding

This directory serves as a technical resource for developers implementing AES-GCM (Galois/Counter Mode) encryption with NoPadding using the HarmonyOS Universal Keystore Kit (HUKS). It provides detailed code examples in Cangjie, demonstrating how to utilize hardware-backed key storage to secure sensitive data. The documentation covers the complete cryptographic workflow, starting from key generation and configuration of AES-128 properties, through to data encryption and decryption. It also emphasizes the correct handling of essential security parameters like Nonce, Additional Authenticated Data (AAD), and AE tags. Furthermore, it addresses key lifecycle management, specifically the secure deletion of keys. This guide is suitable for software engineers and security-focused developers working within the HarmonyOS ecosystem who need to ensure data confidentiality, integrity, and authenticity in their applications.

## Detailed Description

The following files provide specific code examples and technical explanations for implementing AES-GCM operations and managing key lifecycles in HarmonyOS.

### AESGCMNoPadding_1.md
This document provides a Cangjie code example demonstrating how to implement AES/GCM/NoPadding encryption and decryption using the Universal Keystore Kit (HUKS). It covers the complete workflow including key generation, data encryption, and data decryption. The code details configuration properties for AES-128, GCM mode, and NoPadding, highlighting the handling of Nonce, Additional Authenticated Data (AAD), and the Authentication Encryption (AE) tag during the cryptographic processes. This tutorial targets developers working with cryptographic operations in Cangjie who need to secure data using hardware-backed key storage.

### AESGCMNoPadding_2.md
This document provides a code example demonstrating how to delete a cryptographic key within a HarmonyOS HUKS context, specifically following an AES-GCM encryption workflow. The content focuses on the DeleteKey function, illustrating the use of the deleteKeyItem API and the necessary parameters like the key alias and empty options. The key takeaway is the syntax for securely removing a key from the keystore using its alias, which must match the one specified during key generation. This technical snippet is intended for developers working on HarmonyOS security features who need to manage key lifecycles, specifically the deletion phase of cryptographic operations.
