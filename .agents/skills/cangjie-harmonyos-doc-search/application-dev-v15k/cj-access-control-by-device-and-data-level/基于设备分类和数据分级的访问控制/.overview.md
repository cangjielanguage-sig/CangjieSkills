# 基于设备分类和数据分级的访问控制

This directory provides a comprehensive guide to implementing access control mechanisms based on device classification and data grading within distributed data management systems. It covers the fundamental concepts of security labels (S1-S4) and device levels (SL1-SL5), alongside practical tutorials for applying these classifications using relational and key-value databases in the Cangjie language. Key topics include cross-device synchronization rules, security level configuration, and the ArkData framework. This resource is suitable for application developers and system architects looking to secure sensitive data and manage access permissions across different device environments, ensuring that data only flows to compliant hardware based on established security policies. By understanding these mechanisms, developers can prevent data leakage and ensure compliance with hardware security constraints.

## Detailed Description

### 使用关系型数据库实现数据分级.md 使用关系型数据库实现数据分级.md
This tutorial guides developers on implementing data classification by setting security levels for relational databases using the Cangjie language. The document covers two main steps: retrieving the UIAbility context and creating a relational database store configured with a specific security level (S1). Key information includes the use of the StoreConfig class, the RelationalStoreSecurityLevel.S1 parameter, and the getRdbStore function to initialize the database securely. Intended for application developers using the ArkData kit, this guide requires basic knowledge of Cangjie syntax and database operations.

### 使用键值型数据库实现数据分级.md 使用键值型数据库实现数据分级.md
This technical tutorial explains how to implement data classification in key-value databases using the securityLevel parameter. It details the process of obtaining the UIAbility context and creating a KV store configured with security level S1, providing Cangjie code examples. Key takeaways include specific constraints for upgrading database security levels: the operation is upgrade-only, requires closing and reopening the database, and prohibits cross-device synchronization. The document targets developers working with the ArkData framework who need to manage data security levels in single-device scenarios.

### 基本概念_3more.md 基本概念_3more.md
This document outlines the security mechanisms for distributed data management, focusing on classification, grading, and access control. It covers data security labels (S1-S4) based on risk severity, device security levels (SL1-SL5) based on hardware capabilities, and the rules governing cross-device synchronization. Key information includes the access control matrix where data can only sync to a device if its security label is lower than or equal to the device's level. This reference guide targets developers implementing secure distributed databases, emphasizing the importance of correctly setting database labels to match data sensitivity.
