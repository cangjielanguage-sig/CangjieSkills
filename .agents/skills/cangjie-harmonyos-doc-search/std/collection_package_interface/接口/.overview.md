# 接口

This directory contains API reference documentation for core collection interfaces in the Cangjie programming language. It covers a wide range of data structures including lists, sets, maps, queues, stacks, and deques, distinguishing between mutable and read-only variants. The documentation details method signatures, inheritance hierarchies, and functional behaviors such as element access, iteration, and manipulation. It is suitable for Cangjie developers seeking to implement or utilize generic collections, requiring knowledge of type safety and functional programming patterns.

## Detailed Description

### interface_DequeT.md interface_DequeT.md
API reference for the Deque interface, a double-ended queue in Cangjie. It details properties (first, last) and functions for insertion and deletion at both ends (addFirst, addLast, removeFirst, removeLast). It inherits from Collection and uses Option types for safe retrieval, targeting developers familiar with generics.

### interface_EquatableCollectionT.md interface_EquatableCollectionT.md
Defines the EquatableCollection interface, extending Collection to support element containment comparisons. It specifies `contains(element: T)` and `contains(all!: Collection)` methods for checking element presence or subset relationships, returning Bool results. This assists developers in implementing equality checks for collections.

### interface_ListT.md interface_ListT.md
API reference for the mutable, index-friendly List interface extending ReadOnlyList. It covers methods for modifying content: add (elements/collections at indices), remove (indices, ranges, predicates), clear, and subscript assignment. It is intended for developers working with generic mutable collections.

### interface_MapEntryViewK_V.md interface_MapEntryViewK_V.md
Documents the MapEntryView<K, V> interface for viewing specific map keys. It details the read-only `key` property and the mutable `value` property, which allows reading, modifying, adding, or deleting entries. The view remains usable even after deletion, aiding direct map manipulation.

### interface_OrderedMapK_V.md interface_OrderedMapK_V.md
Reference for the OrderedMap interface, maintaining key-value pairs in a specific order. It includes properties for first/last elements, removal functions, and bidirectional iteration methods. Inheriting from Map, it uses optional return types for safe empty state handling.

### interface_OrderedSetT.md interface_OrderedSetT.md
API reference for the OrderedSet interface, defining operations for ordered, readable, and writable collections. Extending Set, it ensures element order and provides methods to access/remove endpoints and create forward/backward iterators from a specific mark.

### interface_QueueT_2more.md interface_QueueT_2more.md
Documents the Queue (FIFO) and ReadOnlyList interfaces. Queue details adding to the tail, peeking, and removing the head. ReadOnlyList supports read-only sequential access with properties for first/last elements and index-based retrieval (get, subscript). Both extend Collection.

### interface_ReadOnlyMapK_V.md interface_ReadOnlyMapK_V.md
Defines the read-only ReadOnlyMap interface for mapping unique keys to values. It specifies methods like get (optional return), contains, keys, values, and the subscript operator (throws on missing key). It targets developers implementing read-only map structures.

### interface_ReadOnlySetT.md interface_ReadOnlySetT.md
Reference for the ReadOnlySet interface, defining read-only set operations. Inheriting from Collection, it specifies `contains` (single/collection) and `subsetOf` functions for Boolean checks on membership and subset relationships, suitable for developers using set data structures.

### interface_SetT.md interface_SetT.md
API reference for the mutable Set interface extending ReadOnlySet. It details methods for adding, removing, clearing, retaining, and conditionally removing elements. It supports collection operations and intersection, emphasizing that sets are unordered.

### interface_StackT.md interface_StackT.md
Documents the generic Stack interface (LIFO) inheriting from Collection. It specifies `add` (push), `peek`, and `remove` functions, handling stack top elements with nullable return types for empty states. It targets developers utilizing stack data structures.

### interface_MapK_V/
Contains API reference for the mutable `Map<K, V>` interface. It covers inheritance from `ReadOnlyMap<K, V>` and methods for adding, removing, and replacing entries. It is designed for developers needing to implement mutable key-value mappings with generic types.
