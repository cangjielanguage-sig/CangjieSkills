# Builder宏自定义构建函数

This directory provides a comprehensive technical overview of the @Builder macro within the Cangjie UI framework, serving as a lightweight yet powerful mechanism for reusing UI elements. It abstracts UI components into custom build functions to streamline development. The content covers fundamental definitions, distinguishing between private and global functions, and delves into complex parameter passing rules, specifically the nuances between pass-by-value and pass-by-reference. It also addresses critical state management topics, such as using @Observed classes to ensure dynamic UI updates. Designed for developers proficient in Cangjie syntax and ArkUI, this guide offers practical code examples and advanced scenarios to help users optimize their declarative UI architecture, manage state synchronization effectively, and master intricate component interactions.

### Builder宏自定义构建函数_2more.md Builder宏自定义构建函数_2more.md
This guide explains the @Builder macro in Cangjie UI, a lightweight mechanism for reusing UI elements by abstracting them into custom build functions. It covers two primary usage methods: Private Custom Build Functions defined within components and Global Custom Build Functions defined at the module level. Key takeaways include that private functions can access component state variables via this, whereas global functions are recommended for stateless UI reuse. The document targets developers familiar with Cangjie syntax and declarative UI, providing code examples to facilitate efficient UI component construction.

### 参数传递规则_2more.md 参数传递规则_2more.md
This technical guide outlines parameter passing rules for @Builder decorated functions in ArkUI using the Cangjie language. It distinguishes between pass-by-value and pass-by-reference mechanisms, emphasizing their impact on UI refresh behavior. Key sections include general constraints, default pass-by-value limitations regarding state variables, and the implementation of pass-by-reference using @Observed classes to enable dynamic UI updates. The document clarifies that only pass-by-reference triggers UI re-rendering upon state changes. Intended for ArkUI developers, it provides code examples to illustrate how to maintain type consistency and manage state synchronization effectively within custom build components.
