## 详细描述

### AppStorage应用全局的UI_2more_89d18e12.md AppStorage应用全局的UI_2more_89d18e12.md
本文档介绍了AppStorage，一种应用全局的UI状态存储机制，旨在为仓颉应用提供中心化的状态管理。文档涵盖了AppStorage的概述、与LocalStorage的区别、作为持久化数据和环境变量中转的作用，以及@StorageProp和@StorageLink宏的使用场景。AppStorage是应用启动时创建的单例，通过唯一键访问，支持与UI和业务逻辑的双向同步。它仅支持纯仓颉场景，并提供API接口供外部手动操作数据。面向需要跨页面或全局状态共享的仓颉开发者，建议阅读状态管理概述作为前置知识。

### StorageLink.md StorageLink.md
本文档详细说明了@StorageLink装饰器的功能、规则及行为，用于实现自定义组件变量与AppStorage之间的双向数据同步。主要涵盖宏使用规则（参数、类型、初始值）、变量传递与访问规则、以及观察变化和框架行为表现。关键信息包括：@StorageLink通过key实现双向同步，必须指定初始值，支持class、Map、Set等多种类型，且数据变化会同步回AppStorage并触发组件重新渲染。属于API参考文档，面向使用ArkUI框架进行应用开发的开发者，需具备基础的状态管理知识。

### StorageProp.md StorageProp.md
本文档是关于@StorageProp宏的API参考文档，旨在说明如何在AppStorage与自定义组件变量之间建立单向数据同步。文档涵盖了宏的使用规则（参数、支持类型、同步机制）、变量传递与访问规则、初始化逻辑以及针对类、数组和集合等数据类型的观察变化行为。关键信息指出，@StorageProp实现单向同步，AppStorage的变化会覆盖本地修改，且必须指定初始值，支持Map和Set等复杂类型但不支持Any。该文档面向使用该UI框架的开发者，帮助他们理解应用状态管理机制，需具备AppStorage和组件生命周期的基础知识。

### 限制条件_d78fa6d6.md 限制条件_d78fa6d6.md
本文档详细阐述了ArkUI框架中状态管理装饰器（如@StorageProp和@StorageLink）的使用限制及注意事项。主要涵盖参数类型要求、不支持Func类型、与PersistentStorage及Environment的交互顺序、UI更新机制以及进程内共享范围。关键点包括装饰器参数必须为字符串，调用顺序会影响数据持久化结果，状态变更会触发UI渲染，非UI消息传递建议使用emitter方式。该文档属于参考指南，面向使用ArkUI进行应用开发的开发者，旨在帮助其避免编译错误和运行时异常。
