This directory provides comprehensive API reference documentation for managing distributed accounts using the Cangjie programming language within the OpenHarmony ecosystem. It covers the essential module interfaces, data structures, and enumerations required to handle distributed account synchronization, state management, and lifecycle events. This documentation is suitable for system application developers and HarmonyOS developers aiming to implement robust distributed account features and ensure seamless account synchronization across devices.

### class_DistributedInfo.md class_DistributedInfo.md
This document serves as API reference documentation for the DistributedInfo class in the Cangjie language, designed to encapsulate distributed account information for an operating system. It covers the class definition, read-only properties including name, ID, event, nickname, avatar, status, and scalable data, alongside the constructor parameters. Key information includes that all properties are immutable, with optional fields having default values. The class handles account states like login, logout, and token invalidity via specific enums. Intended for developers building OpenHarmony applications using system account capabilities, specifically those managing distributed user accounts starting from API version 19.

### enum_DistributedAccountSta_2more.md enum_DistributedAccountSta_2more.md
This API reference document defines Cangjie enums for managing distributed account states and events within the HarmonyOS system. It details the DistributedAccountStatus enum, which tracks login states like LOGGED_IN and NOT_LOGGED_IN, and the OhosAccountEvent enum, which handles events such as LOGIN, LOGOUT, TOKEN_INVALID, and LOGOFF. Both enums rely on the SystemCapability.Account.OsAccount capability and are available starting from version 19. This documentation serves developers implementing account management features, providing the necessary enumerations to monitor and handle distributed account lifecycle changes effectively.
