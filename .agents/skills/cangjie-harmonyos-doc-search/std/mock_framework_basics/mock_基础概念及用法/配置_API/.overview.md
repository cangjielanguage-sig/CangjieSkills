# 配置_API

This directory provides comprehensive technical documentation for the Configuration API within a Cangjie mocking framework. It covers the fundamental aspects of creating and managing mock objects, including defining stub signatures, using parameter matchers, and configuring specific behaviors like return values and exceptions. The guides explain advanced features such as operation chaining and cardinality settings to ensure precise test control. This resource is intended for Cangjie developers and testers who need to isolate dependencies and simulate complex component interactions during unit testing.

## Detailed Description

### 参数匹配器.md 参数匹配器.md
This reference guide explains how to define and use parameter matchers within a Cangjie mocking framework to specify conditions for stub function arguments. It details predefined matchers like any, eq, same, ofType, argThat, and none, alongside syntax sugar such as the underscore symbol for any(). Key takeaways include the default use of structural equality for single identifiers and the rule that function calls inside matchers are treated as matcher invocations rather than evaluated values. The document also addresses function overload resolution and default parameter behavior. This guide targets developers using the Cangjie mocking framework who need to configure precise stubbing behavior.

### 操作_API_2more.md 操作_API_2more.md
This document serves as a technical reference for a Mock framework's API, detailing how to define stub operations and invocation expectations. It categorizes operations into general actions like throws and fails, return behaviors for functions and getters such as returns and returnsConsecutively, setter actions like doesNothing, and spy delegations including callsOriginal. Key information includes the use of cardinality selectors like once and times to enforce specific call counts, alongside a table of default expectations for each operation type. Targeted at developers writing unit tests in Cangjie, this guide ensures precise control over mock behavior and verification logic.

### 桩链.md 桩链.md
This technical reference document explains the mechanism of chaining stub operations using the "Continuation" concept within a testing framework. It covers the definition of the Continuation instance returned by `returnsConsecutively`, `once`, and `times(n)`, and the usage of the `then()` function for sequential execution. Key information includes the requirement to specify new operations after `then()` and that total invocation expectations are the sum of all chain segments. The document provides Cangjie code examples demonstrating sequential return values and retry logic involving exceptions followed by success. This guide targets developers using the Cangjie language for unit testing who need to define complex mock behaviors.

### 配置_API_3more.md 配置_API_3more.md
This document serves as a technical reference for the Configuration API within a Cangjie mocking framework, detailing how to define behaviors for mock and spy objects using the `@On` macro. Main sections cover the concept of stubbing, supported declaration types (instance, static, and top-level), the anatomy of a stub declaration, and syntax for stub signatures including methods, properties, and operators. Key information includes the structure of a complete stub—comprising a signature, action, and optional cardinality—and a list of unsupported declarations like constructors and private members. The guide targets Cangjie developers seeking to isolate dependencies during unit testing by simulating component behavior.
