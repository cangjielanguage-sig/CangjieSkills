# class_UnifiedRecord

This directory contains essential API reference documentation for the UnifiedRecord class and its associated functions within the Unified Data Management Framework (UDMF). It serves as a technical guide for understanding the abstract definition of data content, covering initialization methods, type identification, and value retrieval mechanisms. Key topics include the structural overview of the UnifiedRecord class, specific constraints for creating records with complex types like PixelMap or Want, and the implementation of the getValue function for accessing record data. This documentation is specifically suitable for Cangjie and HarmonyOS developers utilizing the ArkData kit to implement distributed data management capabilities in their applications. By mastering these components, developers can effectively manage and manipulate unified data objects across distributed environments.

## Detailed Description

### class_UnifiedRecord_4more.md
This API reference document details the UnifiedRecord class, which serves as an abstract definition for data content within the Unified Data Management Framework (UDMF). It covers the class overview, two initialization methods (default and parameterized), and the getType function. Key information includes the requirement that a UnifiedData object contains multiple records like text or images, specific constraints for creating records with PixelMap or Want types, and the necessity of using getType to identify records before casting to subclasses. This documentation is intended for Cangjie developers utilizing the ArkData kit to implement distributed data management capabilities.

### func_getValue.md
This document serves as API reference documentation for the getValue function in the Cangjie language, designed to retrieve values from data records within the Unified Data Management Framework (UDMF). The content details the function signature, system capabilities, and the return type UnifiedDataChannelValueType, alongside a practical code example demonstrating usage and pattern matching. Key takeaways include the function's availability starting from version 19 and the necessity to handle multiple potential return types such as strings, integers, or pixel maps. The target audience is HarmonyOS developers working with distributed data management who need to programmatically access and process unified record values.
