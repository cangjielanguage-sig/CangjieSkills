# CString

This directory provides API documentation for the `CString` type in the Cangjie programming language, focusing on C-style strings used for interoperability with C libraries. It covers core definitions, instantiation via constructors or `LibC`, and essential memory management procedures where developers must manually release memory. The content also includes extensions for string manipulation, such as lexicographical comparison and type conversion. Key topics include FFI, `mallocCString`, and resource management. This documentation is intended for developers requiring Foreign Function Interface capabilities to integrate C libraries into Cangjie applications and those handling low-level string operations.

### CString.md CString.md
This document serves as API reference material for the CString type within the Cangjie programming language. It primarily defines the functionality of C-style strings used for interoperability with C language libraries. The content covers the core definition of CString, instantiation methods using either the CString constructor or the LibC mallocCString function, and memory management procedures. Key information highlights that developers must manually release memory on the Cangjie side by calling the LibC free method. This guide targets developers requiring Foreign Function Interface (FFI) capabilities to integrate C libraries into Cangjie applications. Keywords: CString, C-style string, Cangjie, C interop, LibC, memory management, FFI, mallocCString.

### extend_CString_ToString/
This directory contains API documentation for extending the `CString` type in the Cangjie programming language. It focuses on implementing the `ToString` interface and adding utility methods for C-style string manipulation. Key topics include resource management (`asResource`), lexicographical comparison (`compare`), substring extraction (`subCString`), and type conversion (`toString`). The documentation covers essential functions for checking prefixes/suffixes, calculating size, and handling null pointers within `unsafe` blocks. It is suitable for Cangjie developers working on low-level string operations, C interoperability, and manual memory management.
