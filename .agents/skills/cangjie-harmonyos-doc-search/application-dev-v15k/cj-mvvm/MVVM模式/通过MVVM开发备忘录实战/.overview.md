# 通过MVVM开发备忘录实战

This comprehensive resource focuses on the practical implementation of a memo application using the MVVM (Model-View-ViewModel) architecture. It addresses common development issues like code bloat and maintenance difficulties by demonstrating how to effectively decouple business logic from the user interface. Key topics include detailed layer design (Model, ViewModel, View), component classification (Business vs. Shared), and advanced state management using decorators like @Observed and @Publish. The content is specifically tailored for developers working with the Cangjie programming language or HarmonyOS who seek to build modular, maintainable, and responsive applications through reactive programming techniques. It serves as an essential guide for those transitioning from basic coding to architectural best practices in modern app development, ensuring scalable project structures.

This tutorial guides developers on refactoring a memo application using the MVVM architecture to address code bloat and maintenance difficulties associated with non-MVVM patterns. The document covers the design techniques for the three core layers: Model, ViewModel, and View. Key takeaways include defining the Model layer for core data, the ViewModel layer for data services and lazy loading organized by page, and the View layer's distinction between Page, Business, and Shared components. It specifically highlights the difference between Business components, which rely on ViewModels, and Shared components, which use external parameters. This guide targets developers looking to implement clear project structures and component decoupling.
