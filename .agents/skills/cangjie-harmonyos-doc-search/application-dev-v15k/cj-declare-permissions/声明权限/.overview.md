# 声明权限

This directory focuses on the essential processes for declaring and configuring application permissions within HarmonyOS or OpenHarmony development environments. It provides comprehensive technical guidance on modifying the `module.json5` configuration file to define authorization requirements accurately. Key topics include the structure of the `requestPermissions` tag, the mandatory attributes for different permission types, and the specific standards for writing user-facing permission reasons. By adhering to these guidelines, developers ensure their applications comply with system security policies and maintain transparency with users regarding data access. This resource is primarily designed for application developers and system integrators responsible for setting up project configurations and managing sensitive access rights.

## Detailed Description

### 声明权限_3more.md 声明权限_3more.md
This technical guide instructs developers on how to declare application permissions within the project configuration file to ensure proper authorization. It details the `requestPermissions` tag in `module.json5`, explaining attributes such as name, reason, and `usedScene` including abilities and when. Key takeaways include that name is mandatory, reason is required for user_grant permissions with multi-language support, and `usedScene` defines usage context. The document also notes that permissions declared in sub-modules apply globally. Intended for application developers configuring HarmonyOS or OpenHarmony projects, it provides JSON configuration examples for implementation.

### 权限使用理由的文案内容规范.md 权限使用理由的文案内容规范.md
This document provides guidelines for developers on how to write and configure the "reason" field for user-grant permissions in application configuration files. It covers writing standards for the reason string, including syntax, length limits, and consistency requirements across multiple HAP packages. Additionally, it explains display rules for permission groups in authorization pop-ups and settings interfaces. Key takeaways include the requirement for complete, specific sentences under 256 characters, and the logic that specific sensitive groups list sub-permissions while others use the reason of the first applied sub-permission. This reference guide targets app developers configuring permissions to ensure compliance and user transparency.
