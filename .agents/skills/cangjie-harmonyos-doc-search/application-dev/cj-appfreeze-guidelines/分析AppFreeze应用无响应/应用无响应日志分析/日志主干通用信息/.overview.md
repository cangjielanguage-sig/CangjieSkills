# 日志主干通用信息

This directory serves as a comprehensive resource for analyzing system logs, specifically targeting the diagnosis of application freezes and performance bottlenecks. It covers the interpretation of common log fields, main thread task queues, and Inter-Process Communication (IPC) mechanisms. Additionally, it provides insights into resource monitoring, including CPU usage and memory allocation. Key concepts include BinderCatcher logs, stack traces, and process metrics. This documentation is intended for developers and system engineers who need to troubleshoot application responsiveness and identify system-level issues in OpenHarmony environments.

## Detailed Description

### 日志主干通用信息_1.md
This document serves as a reference guide for analyzing common log fields and structures used in diagnosing application freeze issues. It details key fields such as EVENTNAME, TIMESTAMP, and MSG, explains how to interpret main thread task queue information to identify bottlenecks, and provides examples of process stack traces and BinderCatcher logs to pinpoint IPC communication delays. Key takeaways include methods for correlating events using PIDs and timestamps, understanding the impact of task accumulation, and recognizing potential data loss under high system load. Intended for developers or system engineers troubleshooting application responsiveness, this guide assumes familiarity with log analysis tools and debugging concepts.

### 日志主干通用信息_2.md
This reference document illustrates the structure and interpretation of system log data, specifically focusing on Inter-Process Communication (IPC) and resource monitoring. It details four key log sections: BinderCatcher for transaction statistics, PeerBinder Stacktrace for debugging peer process freezes, cpuusage for system load analysis, and memory for process memory allocation breakdown. The content provides examples of parsing PIDs, wait times, thread backtraces, CPU load averages, and memory metrics like PSS and Private Dirty. Targeted at system developers or debuggers analyzing application performance or freezes within the OpenHarmony environment.
