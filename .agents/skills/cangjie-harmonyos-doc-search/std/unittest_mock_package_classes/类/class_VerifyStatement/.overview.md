# class_VerifyStatement

This directory contains API reference documentation for the `VerifyStatement` class within the Cangjie unit testing mocking framework. It serves as a guide for defining verification rules regarding mock object execution counts, ensuring that methods are invoked the expected number of times during testing. The content covers the class definition and key member functions, including `atLeastOnce`, `atLeastTimes`, `once`, `times`, and `never`. It also details exception handling for invalid arguments or duplicate definitions. This documentation is intended for Cangjie developers and software testers who need to implement robust mock verification logic to validate the behavior of dependencies in unit tests.

## Detailed Description

### class_VerifyStatement_5more.md
This API reference document details the VerifyStatement class, used in unit testing to define verification rules for mock object execution counts. The content covers the class definition and four key member functions: atLeastOnce, atLeastTimes, once, and times. Key information includes that objects are created via the @Called macro and allow specifying exact or minimum execution frequencies. Crucially, execution counts can only be defined once per object; subsequent calls trigger MockFrameworkException, while negative arguments result in IllegalArgumentException. This guide targets Cangjie developers implementing mock verification logic in unit tests.

### func_timesInt64_Int64_3more.md
This document provides API reference documentation for verification methods within a Cangjie unit testing mocking framework. It details the times function for setting execution count ranges, the never function for asserting non-execution, and an internal static fromStub constructor. Key information includes that times validates stub signature execution between minimum and maximum counts, throwing exceptions for invalid states or negative arguments, while never asserts zero executions. Both methods return a VerifyStatement object to facilitate method chaining. This reference is intended for developers using the mocking framework to write unit tests, requiring prior knowledge of Cangjie syntax and testing concepts.
