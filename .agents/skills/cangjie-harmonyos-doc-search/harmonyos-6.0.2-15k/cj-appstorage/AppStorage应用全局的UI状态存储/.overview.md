# AppStorage应用全局的UI状态存储

This directory provides comprehensive documentation for AppStorage, a global UI state storage mechanism in the Cangjie and ArkUI frameworks. It covers the core concepts of application-level state management, distinguishing it from page-level storage, and details the usage of decorators like @StorageLink and @StorageProp for data synchronization. The content includes API references, constraint guidelines, and practical usage scenarios for complex data types. It is suitable for HarmonyOS developers and architects seeking to implement reactive state management, optimize UI performance, and understand the boundaries of data persistence and process isolation in their applications.

## Detailed Description

### AppStorage应用全局的UI状态存储_2more.md AppStorage应用全局的UI状态存储_2more.md
This document serves as a technical guide explaining AppStorage, a global UI state storage mechanism bound to the application process. It covers the overview of AppStorage as a singleton for central data storage, distinguishing it from page-level LocalStorage. Key sections discuss its role as a hub for PersistentStorage and Environment, and the usage of @StorageProp and @StorageLink macros for UI synchronization. Important takeaways include its support for state sharing across multiple UIAbility instances and its restriction to pure Cangjie development scenarios. The document targets developers needing application-level state management, recommending prior knowledge of the state management framework.

### StorageLink.md StorageLink.md
This API documentation defines the @StorageLink decorator, which enables two-way data synchronization between component variables and the central AppStorage in ArkUI applications. The document details macro usage rules, including required parameters, supported data types, and initialization requirements. It further outlines variable transfer restrictions and observation behaviors for complex types like classes, arrays, and collections. Key takeaways include that local modifications update AppStorage and trigger component re-renders, while AppStorage changes propagate to all bound variables. This reference guide is intended for HarmonyOS developers implementing state management in custom components.

### StorageProp.md StorageProp.md
This API documentation explains the @StorageProp decorator, which establishes one-way data synchronization between AppStorage and custom component variables. The document covers macro usage rules, variable transfer and access constraints, and observation behaviors for various data types. Key information includes that @StorageProp requires a string key and a mandatory local initial value to handle cases where the AppStorage key is missing. It supports types like class, string, number, and collections. Changes in AppStorage automatically overwrite local modifications and trigger component re-rendering, while parent nodes cannot initialize these variables. This reference guide targets UI developers managing application state within the ArkTS framework.

### 限制条件.md 限制条件.md
This reference document outlines critical constraints and usage limitations for state management decorators and storage mechanisms in the Cangjie framework. It covers parameter requirements for @StorageProp and @StorageLink, type restrictions, interaction rules with PersistentStorage and Environment, UI update performance considerations, and process isolation boundaries. Key takeaways include that decorator parameters must be strings, Func types are unsupported, initialization order affects data persistence, and AppStorage is not shared between different processes like UIAbility and UIExtensionAbility. This guide targets Cangjie developers implementing state management to avoid runtime errors and ensure correct data synchronization.

### 使用场景/ [Subdirectory]
This directory explores practical usage scenarios for state management in Cangjie and HarmonyOS application development. It focuses on the implementation of AppStorage and LocalStorage for managing application-wide and component-scoped states, including handling complex data types like DateTime, Map, and Set. Additionally, it addresses performance best practices, specifically advising against using state synchronization mechanisms for event notifications. This content is suitable for Cangjie developers and HarmonyOS architects looking to optimize reactive UI updates and application architecture.
